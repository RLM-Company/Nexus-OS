# @cosmora/tool-runtime

Единственная разрешённая точка вызова внешних инструментов Kosmora AI.

Перед вызовом обработчика runtime:

1. самостоятельно выводит capability ID из зарегистрированного инструмента;
2. загружает профиль проекта и активные Permission Contract из SQLite;
3. вызывает детерминированный Policy Engine;
4. требует от инструмента явно проверить ограничения для `ALLOW_WITH_LIMITS`;
5. привязывает reservation к версии профиля и выбранным point overrides;
6. создаёт запрос подтверждения либо атомарно резервирует операцию и расходует конечные разрешения;
7. передаёт инструменту исходный idempotency key и полный verdict;
8. сохраняет результат или состояние неопределённого сбоя.

Прямой обход `GuardedToolRuntime` для внешнего действия запрещён архитектурным контрактом.

`RESERVED` после аварийного завершения не исполняется повторно автоматически: сначала требуется
сверка с внешним провайдером по idempotency key. Это исключает дублирование публикаций, платежей и
сообщений.

Исключение обработчика после reservation также считается неопределённым внешним исходом. Runtime
оставляет операцию в `RESERVED`, возвращает `RECOVERY_REQUIRED` и не вызывает обработчик повторно.
Это относится и к ситуации, когда внешний вызов завершился, но его результат не удалось надёжно
сериализовать или сохранить.

Finite-use point override уменьшается в одной транзакции с reservation. Последнее использование
удаляет override из следующей версии профиля. `REPLAY` и `RECOVERY_REQUIRED` разрешаются до этой
транзакции и не списывают использование повторно; stale profile version приводит к fail-closed
`PAUSED` до вызова инструмента.
