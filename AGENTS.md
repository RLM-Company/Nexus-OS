# Product work rules

The owner started the second product stage on 2026-10-28. Read
[the stage-two workflow](docs/product/STAGE_TWO_WORKFLOW_RU.md) before planning or
changing product functionality.

- Start with Kosmora and Koswork. Do not choose another section autonomously.
- The owner directs each section, including visible features and internal behavior.
  Agree its purpose, scenarios, differentiation and implementation scope with the
  owner before implementing or expanding it. Generic earlier permission to work
  autonomously does not authorize a new feature scope in this stage.
- Within an agreed scope, handle routine implementation and necessary fixes without
  asking the owner to approve every file or technical detail. Bring substantive
  product tradeoffs back to the owner.
- Leave Multi-Agent implementation and redesign until the final section.
- Preserve existing UI boundaries in `apps/web/UI_RULES.md`. Do not change the chat,
  sidebar, logo or styling without a targeted request or agreed design scope.
- Research actual competitor behavior before making comparisons. Distinguish
  verified current features, observations and proposed Kosmora improvements.
- Stage-one live acceptance remains outstanding; do not claim it complete. VPS
  work, owner-laptop Windows acceptance and Jarvis remain deferred as instructed.
