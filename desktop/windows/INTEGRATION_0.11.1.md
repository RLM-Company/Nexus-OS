## New desktop behavior

- Native text-only draft API (`draft-store.cjs`), physically under existing `%APPDATA%/cosmora-windows-desktop/desktop-text-drafts-v1`; file names are SHA-256 keyed by **verified** `origin+owner_id` and entries keyed by `new-chat`, `chat:<id>` or `project:<id>`. Electron `safeStorage` requires Windows OS-backed encryption. No plaintext, attachments, PAT, API key, password fields, session cookie or HTTP bearer are stored in this file. Obvious secret strings are rejected. 128K-char maximum, 40 scopes and 30-day expiry. Missing OS encryption fails closed; the web UI shows an error.
- Native bridge is restricted to main-frame events from the current HTTPS origin, owner identity re-fetched via existing `/api/v1/identity/sessions` cookie-authenticated route. It refuses restoration if owner/session cannot be confirmed; no user ID supplied by remote renderer is trusted. The web `page.tsx` integration hooks text-only load/save/clear (300ms debounce plus pagehide flush) without changing model submission. Old Chromium draft keys/files are **not** migrated between accounts and are purged after the first verified native load. Ordinary web browser behavior is unchanged.
- Existing explicit single-instance lock and `second-instance`/`open-url` dispatch stay in place. Deep links now allow **only** sanitized project/chat/Code/work space paths on the same origin (no credentials, unknown params, duplicate params, foreign URLs or arbitrary paths); extra windows are not started. The active UI route is stored without tokens or hash fragments and restored only after valid owner authentication. Stale/deleted scope goes through the normal server authorization and may show the server's unavailable view.
- A saved origin starts in the usual authenticated web UI. A failed main-frame load, crashed renderer or periodic (30 s) health failure shows the existing monochrome offline page with an explicit `Повторить` action. No silent retry of paid messages; the server still owns message acceptance and any usage accounting. Temporary network outage can cause a draft less than 300ms old to be missing if the renderer dies before both the debounce and pagehide flush are processed; that cannot be guaranteed without a successful disk write.
- Native menu **Kosmora → Выйти и удалить локальные черновики…** asks for destructive confirmation, clears all locally saved drafts and the Chromium session cookies/storage in the existing `persist:cosmora` partition, then opens login. Clearing a specific native draft happens after server accepts a message, or when the user explicitly starts a fresh unnamed chat. The `.clear(scope)` bridge is available to future server-authoritative scope-delete hooks. Do not infer a server-side logout or erase server account data from this native action.
- Only active webContents+same-origin download chains (`https/http` or **same-origin blob**) can save. Invalid/unwritable chosen directory aborts with Russian explanation, interrupted downloads report an actionable error, and **Файлы → Отменить текущие скачивания** calls Electron `DownloadItem.cancel()`. Standard Chromium `<input type=file>` upload remains unchanged; no desktop file-system IPC or broad permission grants were added.
- `sandbox: true`, `contextIsolation: true`, `nodeIntegration: false`, existing browser partition/profile, remote origin guard, and Ed25519 trust/update code unchanged. Unsigned auto-update/auto-install remains disabled. No backend/Code/owneraccess/migration changes.

## Windows GUI/installer smoke and upgrade (must be performed by integrator)

1. Back up test profile `%APPDATA%\cosmora-windows-desktop` on a disposable Windows test account. Verify existing unsigned 0.11.0 launches, 30-day browser session, and no custom OS credentials; quit. Install locally built unsigned NSIS 0.11.1 with `CSC_IDENTITY_AUTO_DISCOVERY=false`; **do not** enable auto-updates or trust unsigned update channel. Confirm same appID/profile/partition; no extra Electron window.
2. In a logged-in owner session, type distinct text in ordinary chat, project chat, and Code-selected project; quit abruptly with Task Manager and relaunch. Verify only the matching text is restored, no file attachment, no user-to-user bleed, and that no message is auto-sent or paid. Reopen after authentication expires; route should defer until owner verified. Verify `/?chat=<real-id>`, `/?project=<real-id>&view=chat&surface=code`, and `kosmora://open?path=<percent-encoded-safe-route>` while app already open, minimized and offline; malicious foreign/scheme/path/parameter deep links must be ignored.
3. Disable network while a message is unsent; expect Russian offline screen within health interval, `Повторить` fails clearly, re-enable network and click `Повторить`. Re-auth as needed. Confirm correct chat/Code route and existing draft; **no POST** until pressing Send yourself. Observe server history/usage to exclude repeat requests.
4. Normal site upload through paperclip: select valid test text/PNG, confirm server-side limits, retry manually on failure; Electron must never store upload bytes in draft file. Download ordinary response/CSV and same-origin blob with user-selected writable destination; corrupt/missing destination must warn without falling back secretly. Start a large legal download, use **Файлы → Отменить текущие скачивания**, check `cancelled` and no automatic restart. Foreign origin, `file:`, `data:`, redirect-to-foreign remain denied.
5. Verify native explicit logout confirmation clears encrypted desktop draft files + Chromium remembered login, while cancel does nothing; second owner login cannot read previous draft. If OS encryption is disabled/unavailable, observe visible saving failure rather than plaintext fallback. Ensure app profile is retained on upgrade unless explicit native logout occurred.
6. Run existing NSIS install/upgrade/uninstall cycle and signature checks in the integration Windows environment. Check signed manifest fetch/installer hash/origin and rollback hardening on integrated `update-service`. Key absent means updater still OFF, no installer auto-run, no claimed Authenticode certificate. Verify tray/notifications remain opt-in.
