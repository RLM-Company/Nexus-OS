# Выбор 3D runtime для Games

**Дата:** 27 ноября 2026. **База:** `3af92583`.

## Кандидаты

| Кандидат | Лицензия | Редактируемость | Экспорт | Производительность | Безопасность | Итог |
| -------- | -------- | --------------- | ------- | ------------------ | ------------ | ---- |
| Текущий OBJ-lite software rasterizer | собственный код | только `v`/`f`, без камеры/света/материалов | статика PNG в ZIP | низкая (CPU), до 2048 вершин | изоляция `sandbox=""` | стартовая база, не полноценный runtime |
| three.js 0.187.0 | MIT (проверено `npm view three license`) | scene graph, камера, свет, материалы, glTF/OBJ loader, анимация | модель/сцена — данные, экспорт в ZIP как JSON | WebGL, GPU | trusted runtime в изолированном frame; пользовательские данные — JSON, не код | **выбран** |
| Godot / Blender | open source | мощные редакторы | нативные проекты/бинарники | высокие | требуют нативный рантайм/исполняемый код | не подходит без расширения прав и отдельного адаптера |
| Другие browser-native (Babylon и т.п.) | проверять отдельно | близко к three.js | близко | близко | близко | нет причины менять выбранный MIT-стек |

## Решение

Выбрать **three.js 0.187.0 (MIT)** как настоящий 3D runtime. Зависимость
добавляется явно в `apps/web/package.json` с зафиксированной версией; исходная
лицензия/уведомление сохраняются в `THIRD_PARTY_NOTICES.md`.

Интеграция сохраняет границы:

- пользовательская модель/сцена остаётся **неактивными данными** v2 (`obj-lite`
  или `gltf-json`), как и сейчас;
- исполняемый код модели не загружается: в sandboxed frame передаётся
  только доверенный runtime-скрипт приложения и JSON-данные;
- CSP frame: `default-src 'none'; script-src 'nonce-…' blob:; img-src data: blob:;
  connect-src 'none'; worker-src 'none'; object-src 'none'; frame-src 'none'`;
- сетевые/нативные права не расширяются скрытно; экспорт/импорт остаются в
  проверенных ZIP-путях.

## Фактически проверено

- `three@0.187.0` и `@types/three@0.187.0` добавлены с зафиксированной версией;
  лицензии MIT отмечены в `THIRD_PARTY_NOTICES.md`;
- `three-scene.ts` строит настоящую сцену three.js из инертных данных v2:
  mesh, камера, направленный/фоновый свет, материал, трансформации; 3 targeted
  теста проходят;
- `three-game-view.tsx` подключён в `GameSourcePreview` для `web3d_sandbox`:
  вместо статического PNG запускается WebGL-сцена; изоляция worker-игр не изменена;
- сборка приложения с зависимостью прошла (`pnpm --filter @cosmora/web build`, exit 0);
  web typecheck — exit 0.

## Осталось проверить в полном сценарии

- сохранение/перезапуск/экспорт/распаковка с новой 3D-сценой;
- реальные object/camera/light/material правки в интерфейсе и поведение после reload.
