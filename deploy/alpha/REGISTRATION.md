# Регистрация Kosmora: Google и email

Этот пакет добавляет самостоятельные аккаунты владельцев. Каждый новый аккаунт получает
отдельный `owner_id`; запросы к API проходят через обычный `IdentityStore`. Старый
owner-only вход по умолчанию продолжает работать до переключения маршрута Caddy.
На VPS этот пакет ничего не меняет автоматически.

## Перед переключением

1. Сохранить проверенный backup SQLite и выполнить миграцию `0036_account_registration`.
   Миграция `0035_canvas_artifacts` уже занята и должна остаться перед ней.
2. Существующего владельца привязать к его **текущему** `owner_id` офлайн командой
   `claim-owner-registration.mjs`. Нужны абсолютные пути в переменных
   `KOSMORA_CLAIM_DATABASE` и `KOSMORA_CLAIM_PASSWORD_HASH_FILE` (существующий
   `private/owner-login.env`), а также `KOSMORA_CLAIM_OWNER_ID` и
   `KOSMORA_CLAIM_EMAIL`. Скрипт откажется перезаписать уже созданную учётную запись.
   Действие выполняет главный чат/оператор при остановленных API и edge.
3. Для Google создать OAuth Web Client у Google: точный redirect URI
   `https://<домен>/auth/google/callback`. Передать API через закрытую конфигурацию
   `KOSMORA_GOOGLE_CLIENT_ID` и `KOSMORA_GOOGLE_CLIENT_SECRET`. Приложение использует
   Authorization Code + PKCE, state, nonce и проверяет подпись/claims ID token.
4. Для email нужна локальная программа, совместимая с `sendmail -t -i`, внутри
   контейнера API. Передать её абсолютный путь `KOSMORA_SENDMAIL_PATH` и адрес
   `KOSMORA_EMAIL_FROM`. Без рабочей доставки email-регистрация не предлагается.
   Google также скрыт без обеих OAuth-переменных. Пароли и ключи не хранятся в Git.
5. После отдельной проверки входа существующего владельца и двух тестовых аккаунтов
   включить `KOSMORA_REGISTRATION_ENABLED=1` для API и
   `COSMORA_AUTH_ROUTE_FILE=registration-routes.caddy` для edge. Эти переключатели
   должны меняться вместе: новый proxy без включённых маршрутов API закрывает доступ.

## Поведение

- Email: регистрация → письмо с одноразовой ссылкой на 30 минут → явное подтверждение
  кнопкой → собственная сессия. GET ссылки не расходует её (почтовый сканер не
  активирует аккаунт). Пароль от 12 символов хранится только как scrypt-хеш.
- Google: Google OAuth возвращает код на сервер; ID token проверяется по ключу Google,
  issuer, audience, времени, nonce и `email_verified`. Стойкий ключ связи — `sub`.
  Космора выпускает собственную отзывную сессию; токен Google не сохраняется.
- Совпадение email само по себе **не** объединяет аккаунты. Уже вошедший владелец может
  открыть `/auth/account` и явно привязать Google к текущему аккаунту либо добавить
  пароль к аккаунту, созданному через Google.
- Cookie `__Host-kosmora-session` содержит случайный API-токен, доступный только
  серверу через HttpOnly/Secure/SameSite=Lax. Caddy проверяет его перед каждым запросом
  и подставляет владельцу соответствующий Bearer-токен; браузерный Authorization
  удаляется. Для изменяющих API-запросов proxy требует точный Origin. Выход
  отзывает сессию в SQLite.
- Пока route switch не сделан, остаётся прежняя owner-only альфа. Новую регистрацию
  нельзя считать запущенной только по наличию этой ветки.

## Проверки перед живым включением

Нужны Caddy config validation, реальная доставка письма и подтверждение, Google OAuth
с тестовым клиентом и точным redirect URI, logout/restart и двухпользовательский
browser E2E. Автоматические тесты в PR покрывают SQLite/API и криптографическую
проверку Google на локальном ключе; живой Google и SMTP не вызываются.
