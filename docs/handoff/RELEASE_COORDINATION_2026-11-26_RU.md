## Решения по пересечениям

- #665, `d4c6a84c60b24980b270992464dbb7c4708aba9a`. Обычный запуск сравнения уже сохраняет снимок включённых правил и применяет правило доставки к CSV и Markdown перед публикацией. Проверен полный цикл без правила, с версией 1 и после отключения в версии 2. Форматирование произвольных результатов в отдельном маршруте требует отдельного согласования поддерживаемых правил и доступа к материалу. Владелец этой части — DeepSeek, границу API ведёт Codex.
- #673, `74a3e358ff35c2cb97f70d794ed92c6376446483`, и #676, `e226b6778b556cdad764877417c0970d77cc0314`. Использован существующий извлекатель из #666 и статус Work. Если есть неполный набор требований или предложений, задача ожидает недостающую часть. Маршрут `POST /api/v1/projects/:projectId/work/:id/supplier-answer` принимает добавление под `expected_version`. Перезапись уже принятых частей запрещена. Введённые данные проверяет нормальный расчёт. Ошибочный ответ сохраняет вопрос. Повтор принятого ответа возвращает исходную задачу. После ответа существующий исполнитель сохраняет проверяемые CSV, Markdown и квитанцию. Для исправления отдельных полей повреждённого входа пока используется исходный сценарий повторной подготовки. Владелец продолжения — OpenCode, центральный контракт ведёт Codex.
- Koscode фиксирует изменение исходной ветки до первого GitHub-запроса записи. Предыдущий diff и проверка остаются доступны для просмотра. Подтверждение публикации аннулируется. При потерянном HTTP-ответе интерфейс перечитывает состояние задачи и восстанавливает подтверждённый конфликт или найденный Draft PR.
- В текущем Agent Studio проверен существующий путь от состава команды к двум задачам Work и одному проверяемому набору файлов. Браузерное создание команд Stars и общая многосторонняя отметка принятия зависят от объёма выпуска, который утверждает владелец Stars. Тестирование использует фикстурную модель и настоящий серверный механизм Work.

Повторная миграция оставила 72 записи журнала, нарушений `foreign_key_check` нет. Живой прогон Koscode требует тестового репозитория, ветки, согласованного модельного провайдера и права публикации. Команды и сверка результата описаны в [инструкции живого прогона](TEAM_KOSCODE_LIVE_WORKFLOW_RU.md).

## Поведение продуктов для сверки

- Пользователь ChatGPT Work может следить за ходом работы, отвечать на вопросы и подтверждать важные действия. Здесь аналогичная точка контроля проверяется через предварительный просмотр материалов Koswork и отдельное принятие сохранённого результата. [ChatGPT Work](https://help.openai.com/en/articles/20001275-chatgpt-work-and-codex)
- Codex описывает сквозную проверку на наблюдаемом результате. В Claude Code облачная задача показывает diff относительно базовой ветки и позволяет открыть PR после завершения. В Koscode критерий приёмки — актуальный SHA, проверка точного diff и восстановление подтверждённой ссылки после потери ответа. [Codex](https://developers.openai.com/cookbook/articles/codex_exec_plans) · [Claude Code](https://code.claude.com/docs/en/claude-code-on-the-web)
- Cowork использует разрешённые материалы и сохраняет результат между поверхностями. Для закупки Koswork фиксирует входные версии и хеши, сохраняет проверяемые файлы и возвращает их по той же ссылке. [Claude Cowork](https://support.claude.com/en/articles/13345190-get-started-with-claude-cowork)
