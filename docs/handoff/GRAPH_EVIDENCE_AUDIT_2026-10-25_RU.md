# Проверка источников по всей ревизии графа

База: `codex/integrate-work-presentations-20261017`,
`9ff5eb034310b190261c84b8e8aadf9d652982cf`.
Восстановленный пакет Gemini / PR380 не используется и не изменяется.

## Рабочий сценарий

Открыть граф в `/graph-workspace`, нажать «Проверить источники».
Проверка читает одну сохранённую ревизию целиком, а не поисковую выборку.
Действующие Claim разделяются на три группы: есть цитата из действующей
версии Source/Document, есть только исторические цитаты, цитат нет.
Учитываются только действующие входящие SUPPORTS к точной версии Claim.
REFERENCES, исходящие связи и прежние версии утверждений не дают покрытие.

Для каждой связи доступны точные id@version, статусы, название источника,
место и исходная цитата, включая CRLF, HTML и Unicode как обычный текст.
Статус «есть цитата» не подтверждает истинность утверждения, качество источника
или смысловое соответствие цитаты. Это явно указано в UI и поле usage отчёта.
Даже discovered/disputed источники остаются с исходными статусами.

Изменение источника не переносит цитату на новую версию. Отчёт показывает
старый текст и superseded. Удаление источника/отзыв цитаты снимает текущее
покрытие по существующим правилам редактора. Исторический отчёт воспроизводится
без переписывания прошлых ревизий.

## API и хранение

`GET /api/v1/projects/:projectId/intelligence-graphs/:graphId/evidence-audit?revision=N`
возвращает `{ report, sha256 }`, формат `kosmora.graph-evidence-audit.v1`.
Хеш — SHA-256 UTF-8 `JSON.stringify(report)`; в отчёт не включены owner/project IDs.
Сортировка утверждений и связей детерминирована по точным ссылкам.

Существующий флаг графов, authentication и ACTIVE owner-scoped project gates
сохранены. Чтение идёт через существующий SQLite repository и validation
снимка; история/материалы/статусы не меняются. Миграции, модели, фоновые задачи
и платные вызовы не добавлены. GET отвечает Cache-Control: no-store.
Неизвестные query-поля запрещены; номер ревизии проверяется как строка целого
числа, чтобы TypeBox Convert не превращал `1.5` в `1`.

## Выгрузки

JSON содержит весь проверенный отчёт. Браузер сверяет graph ID, revision,
format и SHA-256 перед показом/выгрузкой; скачиваются те же байты JSON,
для которых показана контрольная сумма.

CSV также включает весь отчёт независимо от фильтра в UI. Одна строка — одна
поддерживающая связь; утверждение без связей получает строку с пустыми полями
связи/источника. Есть версии/статусы, направления, место и полная цитата.
UTF-8 BOM, CSV quoting и CRLF сохраняют русские и многострочные поля.
Формульные значения с невидимыми префиксами защищены апострофом. Для точных
исходных значений предназначен JSON. Общие csvField/safeSpreadsheetCell
вынесены в небольшой модуль с прежним re-export для Data Workbench;
поведение его экспорта сохранено.

Фильтр работает локально. Загрузка/повтор выполняются по явному нажатию;
автоматических повторов нет. При новой загрузке предыдущий отчёт очищается,
при смене графа/ревизии панель пересоздаётся, текущий запрос отменяется.

## Проверки

- 83 core/API проверки в пяти graph-файлах, включая семь новых core и четыре
  HTTP-проверки: полный охват, исторические источники, отзыв, удаление,
  несколько источников, owner/project/feature gates, no-write и SHA.
- Все 248 web-тестов в 47 файлах: HTML/CRLF, фильтр, неверные graph/revision/hash,
  HTTP-ошибки, полный CSV, формулы/невидимые префиксы и отсутствие выдуманных строк.
- Contracts/core build, API typecheck, полный E2E TypeScript, scoped ESLint,
  Prettier и secret/diff checks. Production Next webpack build: 20 страниц.
- Chromium acceptance: 12/12 в dev (девять существующих context-сценариев и три
  новых audit, до добавления CSV), затем 3/3 новых audit на финальной production
  сборке, включая CSV. Production JSON reporter: expected=3, unexpected=0,
  skipped=0, flaky=0.
  Новые сценарии используют настоящий API/SQLite, проверяют фильтр/загрузку,
  историческую цитату, отказ при неверном хеше, ручной retry и отсутствие записи.
  Production-прогон также проверяет CSV download и его BOM.

Браузер запускается через существующий `playwright.acceptance.config.ts`,
путь задаётся `KOSMORA_E2E_CHROMIUM_EXECUTABLE`, production —
`KOSMORA_E2E_PRODUCTION=true`. Browser runtime не добавлен в зависимости.
Тестовый API использует local development identity и mock provider; это не
проверка deployed authentication/edge и не полный E2E suite. Hosted CI pass
и выкладка на VPS не заявляются.
