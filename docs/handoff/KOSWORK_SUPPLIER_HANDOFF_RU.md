# Сравнение поставщиков из сообщения Kosmora

Пользователь отправляет сообщение с JSON-спецификацией и предложениями, открывает
«Сравнить поставщиков в Koswork», проверяет точное сообщение, выбранные файлы и
инструкции проекта, затем создаёт задачу. Можно выбрать доступный проект либо
создать новый. Сохраняется только явно выбранное сообщение. Расчёт берёт данные
из его текста в формате BIZ-013 или из выбранных JSON-вложений. Вложения могут
содержать отдельные массивы `requirements` и `offers`. Их общий нормализованный
ввод ограничен 8 000 символов. Данные иных форматов видны среди исключённых.

Существующий расчёт BIZ-013 сопоставляет позиции, составляет CSV и Markdown.
Экран сдачи показывает исходное сообщение, состояние инструкций на момент
запуска, хеши сохранённого текста входных файлов, выполненные проверки,
расхождения и неизвестные значения. Дополнительные файлы
`supplier-input.json` и `supplier-evidence.json` дают второму человеку вход
расчёта и машиночитаемую квитанцию для независимой проверки. Ссылка задачи
открывает конкретный идентификатор и возвращает сохранённый результат после
перезагрузки. Отметка принятия использует действующие полномочия проекта.

## Контракт для интеграции

| Слой     | Поля и источник                                                                                                                                                                                                                                                             |
| -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Запуск   | `POST /api/v1/projects/:projectId/work/supplier-handoff` с `client_request_id`, `chat_id`, `message_id`, `attachment_indexes`, `materials_version`. Ссылка и хеши вычисляются сервером из сообщения владельца.                                                              |
| Снимок   | `ManagerWork.supplier_handoff` содержит исходный чат, сообщение, его текст, индексы, версию материалов и `inputs[]` с именем и SHA-256. `ManagerWork.materials` уже сохраняет проектные инструкции и материалы. Детерминированный расчёт использует структурированный JSON. |
| Сдача    | `supplier-evidence.json` содержит `format`, `input_sha256`, `source_files`, `checks[]`, `disputes[]`. Расхождение содержит `supplier`, `item_id` и `reason`. Отчёт использует строки существующего сравнения.                                                               |
| Повтор   | Идентичный запрос с тем же `client_request_id` возвращает ту же задачу. Изменившиеся после предпросмотра материалы требуют нового согласования.                                                                                                                             |
| Открытие | `/?project=…&view=plan&mode=work&work=…` загружает указанную задачу. Исходное сообщение доступно по `/?chat=…&message=…&mode=kosmora`.                                                                                                                                      |
| Принятие | Действующий `POST /work/:id/result/accept` принимает `expected_version`. Сервер сверяет опубликованные файлы и сохраняет автора и время один раз.                                                                                                                           |

Основа интеграции — [BIZ-013 #655](https://github.com/RLM-Company/Nexus-OS/pull/655)
в [сведённом main #659](https://github.com/RLM-Company/Nexus-OS/pull/659) и
[сквозная приёмка Work #646](https://github.com/RLM-Company/Nexus-OS/pull/646).
Поля интерфейса привязаны к этим контрактам. При поступлении отдельных поставок
OpenCode и DeepSeek их можно проверять по одному на этом сценарии. Открытые
[#650](https://github.com/RLM-Company/Nexus-OS/pull/650) (локальный исполнитель)
и [#660](https://github.com/RLM-Company/Nexus-OS/pull/660) (PDF-реестр) в эту ветку
не включены. Расширения разрешений и миграции не требуются.

## Браузерная приёмка

```bash
KOSMORA_E2E_PRODUCTION=1 pnpm --filter @cosmora/web exec playwright test e2e/supplier-work-handoff.spec.ts --workers=1 --retries=0
```

Фикстура использует два JSON-файла, исключённое текстовое вложение, код `00123`,
итог `19700` и недокомплект у «Беты». Проверяет конфликт версии инструкций,
скачивание, принятие, повторное открытие той же задачи без локального состояния
и возврат к исходному сообщению. Ответ обычного чата даёт фикстурная модель.
Сравнение, сохранение, скачивание и принятие выполняет реальный код Work.
