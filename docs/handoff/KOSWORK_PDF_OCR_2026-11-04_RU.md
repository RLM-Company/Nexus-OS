# Koswork: локальное чтение PDF и OCR

## Назначение и база

Продолжение согласованного Gemini November adoption: настоящий PDF/vision reader
вместо архивного ASCII/regex-парсера. База main 4481cef2, после PR #438.
Новый инструмент workspace_read_pdf работает в разрешённой рабочей папке Windows.
Интерфейс чата, sidebar, логотип, права устройства и VPS этим пакетом не меняются.

## Повторно использованные решения

- PDF.js / pdfjs-dist **6.3.289**, тот же закреплённый пакет, что уже используется
  веб-импортом проекта: [исходник и лицензия](https://github.com/mozilla/pdf.js).
- Tesseract.js **7.0.0**, tesseract.js-core **7.0.0**, Apache-2.0:
  [официальный API](https://github.com/naptha/tesseract.js/blob/master/docs/api.md),
  [локальное размещение](https://github.com/naptha/tesseract.js/blob/master/docs/local-installation.md).
- Английские/русские данные @tesseract.js-data/eng и /rus **1.0.0**, LSTM best_int.
  Npm-обёртки объявлены MIT; исходный naptha/tessdata содержит Apache-2.0. Лицензия
  сохранена по blob 261eeb9e9f8b2b4b0d119366dda99c6fd7d35c64. В дистрибутив
  включаются package notices, лицензии PDF.js/Tesseract/core и tessdata.
- Все зависимости фиксируются отдельным npm package-lock с integrity. Сборка
  npm ci --ignore-scripts --omit=optional; native Canvas/новый Node daemon не нужны.
  prepare.cjs копирует только браузерные assets, 3 варианта LSTM core и 2 языка,
  записывает manifest SHA256. Текущий полный набор — 32 728 438 байт (~31,2 МиБ).

## Исполнение и результат

Действие содержит относительный path, page_index (с 0), mode auto/text/ocr,
offset_utf16, expected_version и expected_text_sha256. При auto текстовый слой
читается без OCR; пустая страница распознаётся локально. text запрещает OCR,
ocr явно распознаёт изображение страницы даже при наличии текстового слоя.
Это не анализ смысла картинок или диаграмм и не восстановление структуры таблиц.

Возвращаются исходные SHA256/version, номер и количество страниц, метод, хеш
извлечённого текста, OCR confidence и ограничения. Метка untrusted_pdf_page_excerpt
означает данные источника, а не инструкции. Результат до 10 000 UTF-8 байт всего
JSON, без обрыва Unicode. next_offset продолжает текущую страницу; требуются
версия оригинала и предыдущий хеш текста. Смена представления или OCR-результата
не позволяет незаметно объединить несовместимые выдержки. complete_document=false
всегда: одна страница не выдаётся за прочитанный документ.

Исходный файл ограничен **25 МиБ**, документ — 2000 страниц, выдаётся одна выбранная
страница за действие. Извлечённый текст ограничен 180 000 UTF-16 units; обрезка явно
помечается. OCR render не больше 4 млн пикселей, изображения PDF.js не более
16 млн пикселей. Один renderer job одновременно, timeout 60 секунд. Это не hard
quota всей native/WASM RAM и не измерение пикового потребления.

## Границы устройства и данных

Host создаёт скрытый sandboxed Electron renderer без Node integration, в отдельной
непостоянной session, с deny permissions/popups/navigation/downloads. Собственный
[asset protocol](https://www.electronjs.org/docs/latest/api/protocol) зарегистрирован
до app.ready, CSP не обходится. В reader доступны только статические файлы из
manifest и фиксированные HTML/JS. HTTP/HTTPS/WS/WSS/file requests блокируются;
PDF передаётся как данные из уже проверенного snapshot, не как URL. PDF actions,
JavaScript и внешние relationships не запускаются как пользовательская программа.
Модели/языки не скачиваются при работе, OCR cache отключён. Renderer уничтожается
по завершении, отмене и timeout; session storage очищается. Основной рабочий стол
не захватывается и мышь/клавиатура не используются.

Действующие root/path/owner/source grants сохраняются. После async обработки
повторно проверяются права и корень, перечитывается и хешируется оригинал: одинаковый
размер и восстановленный mtime не скрывают изменение. Отзыв отменяет worker и
блокирует поздний результат. Оригинал не изменяется и не отправляется серверу этим
инструментом; выбранный текст затем поступает обычной модели в рабочем контексте.

## Согласование версий

API возвращает supports_workspace_pdf_reads. Observation.read_pdf появляется
только при поддержке сервера, локального reader и подключённой обычной папки.
Vault adapter сохраняет поддержку для обычной папки; источники .kosmora-vault
не превращаются в произвольные PDF paths. Без capability API не предлагает и не
принимает инструмент. Старые API/клиенты продолжают прежние инструменты.

Клиент **0.19.0** включает assets и reader в NSIS/ASAR. Windows CI готовит assets
и проверяет реальный packaged Electron transport, текст PDF и скан через WASM.
Локальная unsigned-сборка использует ту же подготовку. Никакой установки клиента
на основной ноутбук или выкладки API/VPS этим пакетом не выполняется.

## Проверки

- Независимые ReportLab/Pillow fixtures: 2-страничный русский/английский PDF и
  растровый PDF без текстового слоя; это не файлы, созданные самим reader.
- Настоящий headless Chromium: обе страницы, обнаружение отсутствия текстового
  слоя, OCR русского/английского скана, сохранение 00123, 19700 и исключения
  «кроме доставки»; внешних запросов нет. Эталон PDF отрендерен и просмотрен.
  Один небольшой локальный прогон всей связки занял 1311 мс; это не общий benchmark.
- Workspace: версия/хеш текста, длинный Unicode и 10 КБ JSON, подмена файла с
  восстановленным mtime, отзыв во время обработки, namespace и параметры.
- Host: sandbox/network permissions, отмена, уничтожение renderer, cleanup,
  concurrency slot, ограничения ответа и доступ только к фиксированным assets.
- API: поддерживаемый и legacy client, неверные режимы/страницы/расширение/continuation.

На момент подготовки: 252 desktop tests, 67 computer-control API tests и API
TypeScript/ESLint проходят; финальный полный CI и native report фиксируются в PR.
Planner и документы тестовые; платная модель, личные файлы и приёмка установленного
клиента владельца в этот пакет не входят. OCR confidence не считается процентом
правильных фактов. Нечитаемые страницы и пределы форматов нужно сообщать пользователю.
