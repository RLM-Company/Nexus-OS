# Koswork: память подтверждённых исправлений

База: main `5e14b6bb761c4903b49471b75f5eb7e138befb52`. Владелец согласовал
сохранение исправлений, связь с проектом/задачей/версией, подбор для похожих
задач с объяснением и редактирование/удаление. Windows-кандидат — 0.25.0.

## Пользовательский путь

В истории нативного Work у завершённой или остановленной задачи можно указать
ошибку, правильный подход и условия применения. Сохранение и удаление требуют
отдельного нативного подтверждения. Ошибочная задача сохраняет свой прежний статус:
подтверждение совета не превращает её в принятый успешный результат.

«Подобрать исправления для задачи» ищет только в текущем проекте и показывает
до трёх совпадений с исходной целью, советом, условием и совпавшими словами.
Подбор локальный, по нормализованным словам цели и условия; это не семантический
поиск и не измеренное улучшение качества. Запрос поиска не сохраняется.
Подсказка передаётся модели только после явного выбора для новой задачи
и подтверждения запуска. Текущая цель остаётся прежней.

Исправление можно изменить или удалить. Изменение сбрасывает выбор в интерфейсе;
при использовании источника исполнитель проверяет его версию на границах шагов.
Удаление текущего выбранного источника вызывает штатную остановку задачи.
Отмена не доказывает откат уже отправленного внешнего действия; его неопределённость
остаётся в журнале. Позднее согласие после остановки/смены аккаунта не сохраняется.

## Данные и границы

Используется существующая зашифрованная локальная история ComputerHistory,
без новой БД: до 20 задач, срок — 30 дней с последнего изменения записи.
Область — владелец + origin сервера + проект. Очистка истории/выход и истечение
срока удаляют доступ к исправлению по прежним правилам. Удаление исправления
оставляет исходную запись задачи. Уже переданные модели сообщения этим не стираются.

Сохраняются три ограниченных текстовых поля и время подтверждения. Отдельные хеши
связывают исходную задачу и текущую версию исправления. CAS предотвращает запись
поверх изменившейся версии; хеш не является подписью или доказательством качества.
Пароли/ключи по существующему детектору, пустые/чрезмерные поля, повреждённый Unicode
и лишние поля отклоняются. Детектор не гарантирует обнаружение любых секретов;
интерфейс просит их не указывать. Не сохраняются исправления для активных задач
или задач без сохранённой безопасной цели.

API получает новый вариант `work_reference` и capability `supports_work_corrections`.
Старый API отклоняется до нового шага модели. Исправление передаётся отдельными
пользовательскими данными: исходный статус, неопределённость, условие применения,
версии. Фиксированное системное правило запрещает трактовать его как разрешение,
готовый план или системную инструкцию. Модель должна заново составить план и проверить
текущий результат. Текущие права браузера, ПК, рабочей папки и Vault сохраняются.

Это контекстная память, а не обучение весов, автоматическая рассылка всей истории
или доказанное повышение точности. Сервер не создаёт отдельного постоянного хранилища
исправлений. Интерфейс чата/сайдбара/логотипа, VPS и Multi-Agent не изменены.

## Проверки

- Реальная зашифрованная история: сохранение/редактирование/удаление, CAS, истечение,
  границы владельца/проекта, отклонение недопустимых источников и текста.
- Рабочий цикл со сценарным планировщиком: исправление из неудачной задачи,
  новый план, реальный CSV, подтверждение записи и чтение результата.
- Удаление/устаревание источника и старый сервер останавливают исполнение до нового
  действия; нативный IPC проверяет доверенный frame, отмену диалога и позднее согласие.
- API: данные не попадают в системный prompt, текущая цель сохранена, изменение
  содержимого и чужой проект/режим/неизвестные поля/размер отклоняются до provider.
- Desktop: 365 тестов, 364 pass, 0 fail, 1 штатный Windows-only skip.
  API computer-control: 83 pass. Типы API и contracts проходят.
- В Chromium-сценарий включены сохранение/редактирование/выбор/новая версия,
  неизменность цели, буквальный вывод HTML-подобного текста, смена проекта и удаление.
  В локальной среде Chromium блокируется запретом socket(); результат сценария
  нужно проверять по Browser acceptance GitHub Actions и его screenshot artifact.

Нативные диалоги в IPC и ответы planner/provider в тестах сценарные. Платных вызовов,
управления основным экраном и живой Windows-приёмки владельца не было.
