# Репетиция миграции профиля на актуальной базе

Продолжение [#626](https://github.com/RLM-Company/Nexus-OS/pull/626) на базе
main `890bc2e1`. API и офлайн-проверка теперь вызывают одну и ту же
`upgradeAccountProfileColumns` после штатных Drizzle-миграций. Функция
в одной транзакции добавляет только отсутствующие колонки. Существующие
значения, версии профиля и журнал Drizzle не переписываются. Новая миграция
или зависимость не добавлена.

Офлайн-проверка применяет весь путь обновления к своей временной копии,
повторяет обновление профиля и проверяет целостность. Поле отчёта
`profile_columns_upgraded_on_disposable_copy` показывает действительно
добавленные поля. Если в канонической истории поля неожиданно отсутствуют,
проверка останавливается. Исключения для истории ограничены точными парами
хешей и датами #626. Неизвестная запись и повреждённый вход по-прежнему
отклоняются; исходная копия и проверенный бэкап остаются побайтно прежними.

Проверено локально: 11 тестов резервного копирования и репетиции, 20 тестов
настроек и границ аккаунта, сборка зависимостей БД, типизация API и lint.
Отдельно дважды запущен штатный `apps/api/src/server.ts` с тестовой моделью
на синтетической SQLite-базе: оригинальная схема 0027, CRLF в 0063/0068,
68 записей в истории перед стартом и 70 после. Сверены все 68 предыдущих
записей, настройки и версия профиля; изменение настройки через HTTP
сохранилось после второго запуска.

Свежий бэкап реальной базы не использовался. Следующий шаг перед выкладкой —
повторить репетицию этим коммитом на независимой копии актуального проверенного
бэкапа. Рабочая БД, сервер и контейнеры не менялись.
