# Актуальность сохранённого контекста графа

База: `codex/integrate-work-presentations-20261017` @
`85e0bbc71aa5d83b120f50aa7ff930ccc6b839ac`.

При открытии графа панель контекста читает состояние уже сохранённого снимка
без ввода поискового запроса. Показываются отсутствие снимка, текущая ревизия,
устаревшая ревизия либо невозможность подтвердить содержимое файла.
Состояние относится к актуальной серверной ревизии, даже если открыт старый
срез графа. Оно не подтверждает истинность утверждений и обновляется при
открытии панели, после подтверждённых записей и вручную, без фонового опроса.

`GET /api/v1/projects/:projectId/intelligence-graphs/:graphId/context/status`
использует существующие owner/project/feature gates и `Cache-Control: no-store`.
Сохранённый файл сверяется целиком по SHA-256 с детерминированным контекстом
его исторической ревизии и запроса. Имени файла и правдоподобного заголовка
недостаточно. Повреждённый JSON, подмена текста, другой граф, будущая ревизия
и неполный заголовок дают `unrecognized`; ошибки хранилища остаются ошибками.
Ответ имеет общий контракт и проверяется в браузере до показа метаданных.

Из панели можно просмотреть сохранённый снимок или подготовить текущую
ревизию с тем же запросом. Это только чтение. Замена по-прежнему требует
просмотра, явного подтверждения, совпадения хеша и версии материалов проекта.
Проверка потерянного ответа и чтение после удаления сохраняют именно
просматриваемую ревизию, а не молча переключаются на выбранную в редакторе.
При неизвестном результате записи новые действия подготовки заблокированы
до существующей проверки сохранения. Поздний ответ проверки состояния после
закрытия панели игнорируется через AbortController.

Новых таблиц, миграций, зависимостей и модельных вызовов нет. История runs,
квоты, инструкции проекта, другие вложения и существующие privacy fences
сохраняют прежнюю семантику. Восстановление старого содержимого графа создаёт
новую ревизию и не делает прежний контекст актуальным автоматически.
Сайдбар и начальный экран чата не изменены.

Проверки на точном дереве базы с этим изменением:

- Backend: 1208 tests passed, 4 skipped, 156 test files passed, 1 skipped.
  Включены реальные управляемые миграции SQLite, owner export/delete,
  неизменяемые снимки runs, материалы/CAS и проверки графов. Новый объём:
  7 API cases и 14 cases проверки контракта ответа.
- Web: 210 tests passed, 44 files passed, с репозиторным vitest.config.mjs.
- Сборки всех семи packages, API и production Next webpack build успешны;
  API/web TypeScript, scoped ESLint, форматирование, secrets и diff checks.
- Шесть Playwright-сценариев контекста обнаружены и типизированы. Выполнение
  остановилось до первого действия: Chromium headless shell отсутствует.
  Успешная браузерная приёмка и hosted CI не заявляются.

Сопутствующим отдельным коммитом исправлены существующие ошибки типов E2E:
фиксированные названия трёх тестовых чатов больше не имеют тип `undefined`,
проверка выделения Canvas сужает DOM-элемент до textarea, интеграционный
конфиг Playwright не передаёт `undefined` в обязательные свойства.
После этого TypeScript проходит для всего каталога E2E и всех шести
playwright-конфигов; integration discovery находит 333 сценария в 94 файлах.
Discovery не означает выполнение этих сценариев.

Исходники восстановлены через подключённый GitHub на точном SHA; все 1277
исходных blob hashes сверены перед редактированием. Использованы локально
доступные зависимости. pnpm пытался пересоздать кешированные node_modules,
поэтому builds выполнены прямыми tsc/Next CLI; тестовые серверы запущены
прямыми командами с Next webpack (Turbopack не видит зависимости за пределами
восстановленного workspace). Эти временные настройки не входят в поставку.
VPS, feature flags, видимость репозитория и main не менялись.
