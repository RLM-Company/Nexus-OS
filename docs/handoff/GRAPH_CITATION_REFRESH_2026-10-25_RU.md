# Ручная сверка цитат после изменения источника

База: `codex/integrate-work-presentations-20261017` на
`f8229cc78f63d1c1f9da03e0f57695464f423553` (PR381).
Пакет Gemini / PR380 не используется и не изменяется.

## Пользовательский сценарий

В проверке источников раскрыть связь с исторической цитатой и нажать
«Сверить с новой версией источника». Просмотр строится локально по уже
загруженной ревизии и ничего не записывает. Панель показывает исходную цитату,
прежний текст и полный текст действующей версии того же Source/Document.

Перенос доступен только при точном буквальном совпадении цитаты в новом
тексте, без нормализации CRLF, пробелов, Unicode или HTML. Источники выбираются
по одной identity и точным версиям; одинаковое название другого узла не даёт
совпадения. Нет действующей версии, несколько действующих версий, повреждённые
записи или отсутствующая цитата закрывают путь сохранения.

Место в новой версии нужно ввести заново: прежние номера строк могли
измениться. Обязательна явная сверка цитаты, контекста и места. Изменение
введённого места сбрасывает подтверждение. Рендер использует обычный текст
React, включая строки с HTML; фокус переводится на заголовок панели.

Буквальное совпадение не подтверждает смысловую связь или достоверность.
Новая версия связи остаётся discovered. Старые версии/цитаты и отчёты
сохранённых ревизий остаются в истории. Если фрагмент исчез, предлагается
использовать существующий редактор цитат для ручного выбора нового текста.

## Сохранение и восстановление

Используется существующий `POST .../intelligence-graphs/:graphId/edits` с
операцией cite_edge и expected_revision просмотренного графа. Новый API,
миграции, модели и обходы owner/project/privacy gates не добавлены. Сервер
независимо проверяет точную цитату, доступность источника, статусы и revision CAS.
Номера версий узлов и ревизий графа не отождествляются.

При конфликте или неизвестном результате записи черновик места остаётся,
подтверждение сбрасывается, повторная запись блокируется. Автоматических
повторов POST нет. Кнопка «Загрузить состояние графа» выполняет чтение текущего
графа и истории через обычный UI-путь. Если ответ потерян после commit,
повторный перенос не отправляется, а чтение показывает фактический результат.

Полученный ответ записи проверяется по graph ID и следующей ревизии. Новая
ревизия принимается до вспомогательных чтений списка/истории: ошибка списка
не выдаётся за неуспех уже подтверждённой записи. При смене графа или ревизии
старая панель сверки скрывается, чтение графа очищает выбранную сверку.
Материалы для модели и сохранённый контекст автоматически не заменяются.

## Проверки

- Все 267 web-тестов: 19 новых случаев точных версий/байтов, отсутствующей цитаты,
  другой identity, удаления/повреждения, обязательной сверки/нового места и
  безопасного рендера.
- 84 core/API graph tests в пяти файлах, включая новый HTTP lifecycle переноса,
  историю, неизменяемый прежний отчёт, discovered и отклонение старого CAS.
- API typecheck, web production build (20 страниц), полный E2E TypeScript,
  scoped ESLint, Prettier, secret/diff checks.
- 7/7 audit-сценариев в dev Chromium: три прежних и четыре новых.
  Новые проходят через настоящий API/SQLite: просмотр без записи, ручная
  сверка с сохранением CRLF/HTML, исчезнувший фрагмент, конкурентная правка,
  потеря ответа после commit и восстановление чтением.
- 16/16 на финальной production-сборке: семь audit-сценариев и девять прежних
  context-сценариев. JSON reporter: expected=16, unexpected=0, skipped=0, flaky=0.

проверка deployed auth/edge; hosted CI pass и выкладка на VPS не заявляются.
