# Koswork: полные ответы инструментов в пределах бюджета

Продолжение укрепления исполнителя из PR #452.

`ComputerSession` больше не обрезает JSON ответа на 16 000-м символе. Если полный
сериализованный ответ превышает 16 000 UTF-8 байт, планировщик получает небольшой
валидный JSON с `COMPUTER_RESULT_TOO_LARGE`, `result_omitted: true`, видом действия
и инструкцией проверить свежий результат либо сузить чтение. Исходный ответ не
подменяется частичной цитатой. Размер проверяется в байтах, включая экранирование.

Действие к этому моменту уже было отправлено исполнителю. Поэтому пропуск большого
ответа не становится `not_executed`, не запускает retry и не доказывает отсутствие
внешнего эффекта. История сохраняет `requested` и необходимость review для записи;
полезная нагрузка ответа в recovery context не сохраняется.

Для `browser_tabs` предотвращается сам переполненный ответ. Все восемь ID, порядок,
названия и состояние загрузки сохраняются в пределах 14 000 UTF-8 байт. При
необходимости самые длинные URL целиком заменяются на `null` с `url_omitted: true`;
они не сокращаются в ложный пригодный адрес. Короткие URL сохраняются точно,
секретные параметры по-прежнему скрывает существующий `agentUrl`. Название
ограничивается 180 UTF-16 элементами по целой Unicode-границе с явным флагом
дополнительного сокращения. Штатное состояние вкладок и интерфейс не изменяются.

## Проверки

- До исправления длинный ответ приводил к `Unterminated string in JSON`, а список
  восьми длинных URL выходил за бюджет. Оба воспроизведения теперь проходят.
- ASCII и русский текст с эмодзи; одна отправка действия, без повтора для получения
  пропущенного ответа; сохранённая неопределённость записи после перезапуска.
- Восемь вкладок, длинные и короткий URL, экранированные названия и Unicode-граница;
  все ID сохранены в исходном порядке.
- `npm run check --prefix desktop/windows`: **305 tests, 304 passed, 0 failed,
  1 штатный Windows-only skip**.
- Последующий профильный прогон browser/controller/history: 84 passed, 0 failed.
- `git diff --check`, проверка секретов, Prettier и `verify-unsigned-policy`.

Проверены действующие сессия, история и browser engine на сценарных нативных
адаптерах. Живые модели, ноутбук владельца и серверная выкладка не использовались.
Новых OS-разрешений или автоматического повторения действий нет.
