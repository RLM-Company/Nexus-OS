# Исправление результата в цепочке Koswork

База `2a3109e79e1b722e8096ddb6fd691824f4c12338`. Ветка
`team/koswork-plan-repair`.

В панели **План проекта** владелец может выбрать «Проверять шаги и один раз
исправить результат после замечания критика», задать общий лимит запросов и
подтвердить расход перед запуском. Для запущенных в этом режиме шагов
обязательна проверка содержания. При первом подходящем отклонении план ставит
новую попытку в очередь, передаёт конкретное замечание критика и повторно
проверяет результат. Зависящие шаги используют только опубликованные файлы,
которые заново проверены по хешу и байтам.

Исправление ограничено одной попыткой на весь план. Отказ политики, ошибки
провайдера, отмена и повторное отклонение не запускают новых исправлений.
Использованные запросы и выделенные текущим шагам резервы учитываются в лимите.
Для принятия новой попытки требуется место для трёх запросов. Если лимит исчерпан,
владелец может подтвердить продолжение с повышенным лимитом. В истории попыток
видны исходное замечание, исправление и результат повторной проверки. После
перезапуска новые шаги ждут явного возобновления, как у других планов.

Поставка описывает один сценарий адаптации. Замечание критика проверяет содержание
файлов. Выполнение кода, произвольное расширение цели и автоматическая активация
из свободного текста здесь не реализованы. Живой провайдер не вызывался.
Миграции и новые зависимости не нужны. Для отката достаточно отключить опцию
на следующем запуске или вернуть код этой ветки.

## Проверки

```sh
NODE_OPTIONS=--conditions=development pnpm exec vitest run --root apps/api test/work-dag.test.ts test/manager-work.test.ts test/workflows.test.ts
pnpm exec tsc -p apps/api/tsconfig.json --noEmit --incremental false
pnpm exec tsc -p apps/web/tsconfig.json --noEmit --incremental false
```

Сценарии с временной SQLite и модельной фикстурой проверяют отказ критика,
передачу замечания, отсутствие публикации отклонённого результата, повторную
проверку, зависимый шаг, лимит, явную остановку и отсутствие дубликата попытки.
Браузерный сценарий выбора режима и лимита находится в
`apps/web/e2e/work-manager-dag.spec.ts`.
