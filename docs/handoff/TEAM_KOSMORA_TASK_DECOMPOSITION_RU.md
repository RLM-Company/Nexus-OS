# Дробление задач Kosmora

База `2a3109e79e1b722e8096ddb6fd691824f4c12338`. Ветка
`team/kosmora-task-decomposition`.

В **Настройки → Модель и чат** доступен переключатель **Дробление задач**. Он
выключен по умолчанию и сохраняется для аккаунта. Старые клиенты сохраняют
текущее значение, если не передают поле `task_decomposition`.

- В Turbo или профиле Mercurius дробятся запросы Kosmora с 2–8 пронумерованными
  пунктами верхнего уровня. В остальных профилях порог составляет 3–8 пунктов
  и 600 символов. Короткие одиночные запросы идут обычным путём.
- Последний запрос размечается как последовательность шагов для одного
  потокового вызова с исходной целью, условиями и форматом ответа. Длинные
  дословно повторяющиеся строки могут передаваться один раз со ссылками в остальных
  местах. Такое представление используется только при уменьшении консервативной
  оценки входа с учётом служебной разметки. История сохраняет исходный текст.
- Запросы с вложениями, активным English Relay, блоками кода или цитатами
  используют обычный путь. Настройка действует на обычный чат Kosmora, включая
  фоновое выполнение, и не меняет самостоятельные проекты Koswork или Coscode.

## Выбор моделей при дальнейшей разработке

Два необязательных параметра сервера принимают `provider:model`.

- `CHAT_TASK_SPLIT_FAST_ROUTE` для Turbo и Mercurius.
- `CHAT_TASK_SPLIT_LARGE_ROUTE` для крупных задач в остальных профилях.

Пустая конфигурация использует текущую модель чата. Шлюз проверяет выбранный
маршрут, контекст, стоимость и наличие адаптера до отправки. Если маршрут
недоступен, применяется текущий маршрут. Для новых провайдеров и моделей
сначала требуется подключить соответствующий адаптер и зарегистрировать маршрут.
Лимиты, квоты и учёт вызовов остаются общими с обычным чатом.

## Проверка и откат

Фикстуры используют настоящие запуск, поток, SQLite, учёт и один вызов
mock-провайдера. Проверяемые детали запроса включают сохранение артикула
`00123`, суммы `19 700 ₽`, даты и исключения «кроме доставки». Снижение
оценки входа проверено на повторяющейся инструкции. Фактический расход и
качество ответа живой модели не измерялись.

```sh
NODE_OPTIONS=--conditions=development pnpm exec vitest run --root apps/api test/account-settings.test.ts test/profile-chat-path.test.ts test/general-chat-background-run-coordinator.test.ts test/relay-main-accounting.test.ts test/owner-identity.test.ts
NODE_OPTIONS=--conditions=development pnpm exec vitest run --root packages/config test/config.test.ts
pnpm exec tsc -p apps/api/tsconfig.json --noEmit --incremental false
pnpm exec tsc -p apps/web/tsconfig.json --noEmit --incremental false
```

Браузерный сценарий `apps/web/e2e/chat-polish-20261025.spec.ts` проверяет
включение, обновление страницы и выключение. При откате можно выключить
переключатель или вернуть предыдущий код. Дополнительное поле SQLite создаётся
идемпотентно в существующем обновлении схемы аккаунта и совместимо со старым
кодом. Удалять столбец или историю для отката не требуется.
