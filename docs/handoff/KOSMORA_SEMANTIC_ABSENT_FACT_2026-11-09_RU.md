# Semantic absent-fact оценка на реальном E5

## Согласованный объём

Measurement-only продолжение семантического индекса (PR #436, PR #474): владелец
согласовал следующий блок «absent-fact случаи + крупная независимая оценка»,
отложенный в 2026-11-03 handoff как отдельную очередь. Поведение продукта не
меняется: пакет состоит из замороженной fixture, отдельного bench-скрипта и
отчёта прогона. UI и полномочия не затрагиваются. Модель ставится оператором
отдельно по прежнему pinned manifest (multilingual-e5-small:761b726:q8, SHA256
проверен).

[Отчёт прогона](../research/semantic-absent-fact-2026-11-09.json) сохранён
в репозитории; bench воспроизводит его метрики повторными запусками.

## Панель

- Frozen fixture `packages/db/test/fixtures/semantic-absent-fact-evaluation.json`
  (version `kosmora-semantic-absent-eval-v1`, SHA256
  `036ea87fdde79f379a1275cbe49aa3c7fffc64c2a4e62bfcd584f40b236809f9`):
  119 фактов RU/EN — офисные и процессные формулировки — плюс 12 вопросов
  про отсутствующие факты.
- В БД добавляются 240 детерминированных шумовых сообщений из трёх фиксированных
  шаблонов (`v2-240-three-fixed-templates`). Это синтетика, а не реальная
  история и не попытка её имитировать.
- Итого 359 документов, 48 вопросов: 36 present (в корпусе есть gold-факт)
  и 12 absent (факта в корпусе нет по замыслу панели).
- Основной запрос поступает штатным продуктовым путём: сначала bounded lexical
  resolve, затем тот же resolve с подключённым настоящим индексом
  (`indexedRecall`). Продуктовый absent-критерий — `semantic_added`: разность
  набора references до/после indexed resolve, то есть то, что индекс реально
  добавил бы в mergeSemantic.
- Зеркало для диагностики: продуктовой `scoreSemanticVector` по всем индексным
  chunk-строкам, независимо от поискового прохода, чтобы каждый вопрос имел
  точную лучшую cosine-величину. Для absent-вопросов сохраняются top-3
  references: без указания ближайших кандидатов измерение неинтерпретируемо.

## Результаты: present-вопросы

Encoder `multilingual-e5-small:761b726:q8:mean:l2:384:v1`, обычный профиль
batch=4/intra-op=2. Построение индекса по 359 сообщениям: 362 batches за 11,7 s.
RSS snapshot 183,2 MiB (не peak).

| Путь            | top-1 | top-3 | MRR     | медиана  |
| --------------- | ----- | ----- | ------- | -------- |
| Bounded lexical | 25/36 | 27/36 | 0,71759 | 715,0 ms |
| Индекс (hybrid) | 33/36 | 35/36 | 0,93981 | 57,7 ms  |

Панель больше и сложнее, чем 96 документов отчёта 2026-11-03, поэтому числа не
переносятся с той оценки напрямую. Вывод по скорости не меняется — PR #474 уже
измерял scan объёмом 100k; здесь проверено, что на 359-документном корпусе
сохраняется recall: пропусков gold после индекса 1 из 36, ещё 2 present-вопроса
ранжируются чуть хуже bounded-порядка. Если факт присутствует в корпусе, hybrid
связка находит его устойчиво. Что происходит, когда факта нет — ниже.

## Результаты: absent-вопросы

Все 12 отсутствующих фактов проходят продуктовый порог 0,72 и были бы добавлены
в mergeSemantic как semantic-источники (false_positive_count 12/12):

| absent-вопрос                                           | best cosine | top-1 (дистрактор)    |
| ------------------------------------------------------- | ----------- | --------------------- |
| Какой выделен бюджет на юристов в квартал?              | 0,7973      | budget-tools 0,7973   |
| Когда мы открываем второй офис в Казани?                | 0,8042      | office-lease 0,8042   |
| Сколько у нас каналов поддержки в телеграме?            | 0,8073      | job-postings 0,8073   |
| What is our official policy on cryptocurrency payments? | 0,7700      | шум 0,7700            |
| Кто ведёт YouTube-канал компании?                       | 0,7916      | holiday-cake 0,7916   |
| Каким сервисом мы отслеживаем курьеров на карте?        | 0,8116      | courier-codes 0,8116  |
| Какой у нас договор с гидропонной фермой?               | 0,8046      | contract-terms 0,8046 |
| Сколько налоговых вычетов закрыл финанс-отдел за год?   | 0,7927      | budget-report 0,7927  |
| Что записано про оклад стажёра в Питере?                | 0,8075      | canteen-card 0,8075   |
| Когда запускать собственный телефонный бот?             | 0,7999      | phone-forward 0,7999  |
| Какой процент зарплаты уходит в корпоративный фонд?     | 0,8124      | salary-day 0,8124     |
| Do we sponsor English courses for employees' children?  | 0,7650      | train-budget 0,7650   |

Распределения перекрываются: present p50 0,8504 (минимум 0,7722), absent p50
0,7999 (максимум 0,8124). Диагностика top-1 показывает закономерность, а не баг:
absent-вопрос почти всегда (11 из 12) ложится на присутствующий факт той же
области — ближайшего тематического соседа (бюджеты → budget-tools, курьеры
на карте → courier-codes, зарплата → salary-day); один вопрос (крипто) уходит
в шум. Область перекрытия 0,77–0,81 содержит и present-минимум, и
absent-максимум, поэтому порог между классами не разделяет их.

## Съёмка порога

Перебор gate по зеркальной cosine-панели:

| Gate | absent проходят фиктивно | present остаются источниками |
| ---- | ------------------------ | ---------------------------- |
| 0,72 | 12 из 12                 | 36 из 36                     |
| 0,76 | 12                       | 36                           |
| 0,78 | 10                       | 35                           |
| 0,80 | 6                        | 30                           |
| 0,82 | 0                        | 29                           |
| 0,85 | 0                        | 20                           |
| 0,88 | 0                        | 6                            |
| 0,92 | 0                        | 1                            |

Полного разделения нет: с 0,82 исчезают ложные absent-прохождения, но теряются
7 present-источников из 36; у 0,88 остаются 6, у 0,92 — 1. Порог не является
absent-честным механизмом и не может им стать: cosine — сила тематического
совпадения, а не подтверждение того, что факт существует.

## Вывод

Retrieval gate сам по себе не защищает absent-честность: для любой близкой
темы найдётся тематический дистрактор над порогом 0,72, распределения
present/absent перекрываются. Это не обвинение текущего продукта: sources
остаются кандидатами для оценки модели, цитаты проходят прежние source
lineage/quote checks, и «наличие числа где-то в корпусе не подтверждает
утверждение» уже зафиксировано в adoption-документе. Measurement-only результат
фиксирует иную вещь: если владелец захочет явную absent-честность (не показывать
«нашёлся источник» там, где факта нет), потребуется отдельный механизм —
например, LLM-оценка «отвечает ли найденный источник на вопрос» или структурный
отказ «данных нет». Он не входит в этот пакет: такое изменение продуктового
recall — решение владельца. Также измерение не доказывает обратного: отсутствие
совпадения ниже порога не доказывает отсутствия факта (recall-граница прежняя).

## Воспроизведение

```sh
pnpm --filter @cosmora/api exec node --import tsx --conditions=development ../../scripts/bench-semantic-absent-fact.mjs /absolute/model report.json
```

Модель ставится отдельно `scripts/install-semantic-memory-model.mjs` по pinned
manifest; bench отказывается работать без настоящего encoder («Actual model
required, no mock substitute»), подмена синтетикой невозможна. Метрики
повторных прогонов совпали (present/absent таблицы, пороги, дистракторы);
различаются только время build и медианы — машино-специфичные. Профиль
`--small` (batch=1/intra-op=1) на этой панели не прогонялся.

## Границы

Панель синтетическая и помечена синтетикой; шум — три фиксированных шаблона.
Все числа — одна Windows-машина, обычный профиль, snapshot RSS не peak. Это не
SLA, не оценка общего интеллекта модели и не активация продукта. Bench и
fixture — измерение, не продуктовые пути; merge выполняет владелец. HNSW/PQ
остаются исследовательской очередью после PR #474: полученные там числа (build
396,8 s на 25k-подмножестве, recall 0,469@ef128) не оправдали замену exact scan.
