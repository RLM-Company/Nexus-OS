# Koswork: прогресс и время конкретного запуска Work

Это замена [#629](https://github.com/RLM-Company/Nexus-OS/pull/629) на базе
сведённого main после #631. Прежний проект предлагал считать очередь между двумя
соседними SSE-сообщениями и передавать аргументы `tool.call` браузеру. Оба
замера не подтверждали исполнение шага Work.

- Панель над полем ввода отображает серверный статус выбранного плана проекта.
  Вкладка «План» использует уже загруженный снимок; чат читает точный ID плана
  по тому же API с проверкой права доступа. Публичные события обычного чата,
  повтор потока и уточнения чата не меняют шаг Work. После смены проекта прежний
  план не отображается.
- Очередь измеряется по сохранённым сервером входу и выходу из `queued`. Пауза,
  ожидание подтверждения и подготовка непривязанной DAG-попытки не входят в замер.
  При продолжении складываются закрытые интервалы той же попытки. Для старых
  работ без границы входа измерение не восстанавливается по косвенным данным.
- Время инструмента берётся внутри реально выполненной операции локальной
  публикации. Запрещённый вызов, повтор из журнала идемпотентности и чтение
  готового снимка нового времени не добавляют. Если операция была прервана
  между записью и фиксацией результата, её время не восстанавливается.
- В снимок DAG попадают только числа и идентификатор соответствующей попытки
  (`work_id`, номер). Проверяется совпадение проекта, графа, шага и номера
  попытки; браузер также проверяет идентификатор последней попытки. Новая
  попытка не наследует время прошлой. Аргументы инструментов, имена и содержимое
  файлов в поля времени не входят.
- Итог панели — сумма измеренных интервалов последних попыток, а не время
  с начала до конца параллельного плана. Модель, пауза и решение владельца пока
  остаются без замера. Формат панели и правила выполнения/разрешений сохранены.

Проверки: 141 тест API Work, включая реальные временные файлы и SQLite,
точные границы очереди с паузой, повтор готового результата, проверку владельца
и изоляцию повторной попытки. Web-тест проверяет привязку замеров к последней
попытке. Два Chromium-сценария покрывают реальный ответ чата, перезагрузку,
чужой проект и завершение двух зависимых шагов с проверкой таймеров. Локальный
Chromium блокируется запретом системного сокета; браузерную приёмку запускает CI.
Платных вызовов модели и действий на VPS нет.
