# Первый срез MCP в Kosmora

Раздел «Интеграции» позволяет выбрать проект, проверить настроенный MCP-сервер и увидеть первую страницу объявленных им инструментов. Вывод содержит имена и номер операции существующего журнала политики. Статус «сервер настроен» отражает конфигурацию. Список появляется после успешного ответа сервера.

Используется реестр из #603 и его GuardedToolRuntime. Владелец запускает проверку вручную в своём проекте. Политика `integration.private.use` действует через существующий центр управления. Повтор с тем же идентификатором возвращает сохранённый результат. Аварийная остановка проекта или аккаунта блокирует новую проверку и выдачу результата. Адрес сервера и учётные данные задаются оператором на сервере.

Транспорт реализует инициализацию и `tools/list` по MCP Streamable HTTP. Поддержаны версии `2025-11-25` и `2025-06-18`, JSON и SSE. Список ограничен 100 именами и 64 КиБ ответа, на запрос выделено до 10 секунд. При наличии идентификатора сессии клиент делает одну попытку её закрыть. Сайт получает только имена, признак следующей страницы и идентификатор операции. Инструменты, ресурсы и промпты этого сервера недоступны для исполнения моделью в данном срезе.

Сценарий на локальном HTTP-сервере использует обычные MCP-запросы и реальные Fastify, SQLite и реестр. Проверяются успешный JSON/SSE-обмен, отказ по политике, отказ чужого Origin, ограничение одним проектом, повтор без нового обращения к серверу, запись в журнале, отказ провайдера и аварийная остановка.

```sh
pnpm --filter @cosmora/api exec vitest run test/mcp-discovery.test.ts test/connector-status.test.ts --maxWorkers=1
pnpm --filter @cosmora/web exec playwright test e2e/navigation-integration.spec.ts --grep 'MCP tool catalog'
```

Пилот включается только при наличии трёх настроек оператора. `KOSMORA_MCP_URL` содержит утверждённый HTTPS endpoint на стандартном порту. `KOSMORA_MCP_PROJECT` и `KOSMORA_MCP_OWNER` задают одну пару проекта и владельца. Для сервера с авторизацией оператор передаёт `KOSMORA_MCP_BEARER` через секрет окружения. При смене подключения оператор меняет `KOSMORA_MCP_REVISION`. Развёртывание ограничивает исходящие соединения разрешённым публичным хостом. Клиент отклоняет редиректы. Для отключения удалить настройку URL и перезапустить API.

Для живой проверки на разрешённом стенде открыть `/?surface=apps`, выбрать проект и нажать «Проверить MCP и показать инструменты». Сверить имена с каталогом провайдера и найти операцию по идентификатору в центре управления. Общая совместимость конкретных провайдеров требует их подключения и отдельной приёмки. Следующий срез после выбора сервиса — одна явно разрешённая операция чтения с собственной схемой входа, ограничением ресурса и проверяемым результатом. OAuth и каталог подключаемых владельцем серверов потребуют отдельного среза.

Спецификация [Streamable HTTP](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports). Рассмотрен официальный `@modelcontextprotocol/sdk` 1.32.2 (MIT). Для узкой операции проверки подключение новой зависимости не потребовалось. За основу взят протокол, исходники SDK не переносились.

## Предпросмотр и перенос документа

Дополнительные настройки `KOSMORA_MCP_DOCUMENT_URI` и `KOSMORA_MCP_DOCUMENT_NAME` задают один разрешённый ресурс MCP и имя файла .txt или .md. Сервер должен объявить `resources` и ответить на `resources/read` текстом того же URI. Выберите настроенный проект в «Интеграциях», откройте предпросмотр, проверьте текст и источник, затем подтвердите сохранение. Копия появляется в материалах проекта. Проверка доступа и обе операции используют действующий журнал политики.

Предпросмотр с ограниченным сроком хранится в памяти сервера. Журнал содержит ссылку на операцию и хеш URI. Сам документ появляется в постоянном хранилище только после сохранения. Смена версии материалов требует нового предпросмотра. Повтор сохранения с тем же ключом возвращает прежнюю версию. Повтор с прежним ключом чтения требует нового предпросмотра, поэтому старый ответ не выдаёт текст после отзыва. Остановка проекта блокирует чтение и сохранение, отказ удалённого сервера виден при следующем чтении. Уже сохранённая копия остаётся в проекте.

Сквозной HTTP-сценарий входит в `test/mcp-discovery.test.ts`. Он проверяет отказ до сетевого запроса, подмену URI, точный текст, отсутствие сохранения на шаге предпросмотра, конфликт версии, явное сохранение, журнал, повтор и отказ после отзыва. Сценарий интерфейса запускается командой:

```sh
pnpm --filter @cosmora/web exec playwright test e2e/navigation-integration.spec.ts --grep 'MCP'
```
