# Первый срез MCP в Kosmora

Раздел «Интеграции» позволяет выбрать проект, проверить настроенный MCP-сервер и увидеть первую страницу объявленных им инструментов. Вывод содержит имена и номер операции существующего журнала политики. Статус «сервер настроен» отражает конфигурацию. Список появляется после успешного ответа сервера.

Используется реестр из #603 и его GuardedToolRuntime. Владелец запускает проверку вручную в своём проекте. Политика `integration.private.use` действует через существующий центр управления. Повтор с тем же идентификатором возвращает сохранённый результат. Аварийная остановка проекта или аккаунта блокирует новую проверку и выдачу результата. Адрес сервера и учётные данные задаются оператором на сервере.

Транспорт реализует инициализацию и `tools/list` по MCP Streamable HTTP. Поддержаны версии `2025-11-25` и `2025-06-18`, JSON и SSE. Список ограничен 100 именами и 64 КиБ ответа, на запрос выделено до 10 секунд. При наличии идентификатора сессии клиент делает одну попытку её закрыть. Сайт получает только имена, признак следующей страницы и идентификатор операции. Инструменты, ресурсы и промпты этого сервера недоступны для исполнения моделью в данном срезе.

Сценарий на локальном HTTP-сервере использует обычные MCP-запросы и реальные Fastify, SQLite и реестр. Проверяются успешный JSON/SSE-обмен, отказ по политике, отказ чужого Origin, ограничение одним проектом, повтор без нового обращения к серверу, запись в журнале, отказ провайдера и аварийная остановка.

```sh
pnpm --filter @cosmora/api exec vitest run test/mcp-discovery.test.ts test/connector-status.test.ts --maxWorkers=1
pnpm --filter @cosmora/web exec playwright test e2e/navigation-integration.spec.ts --grep 'MCP tool catalog'
```

Пилот включается только при наличии трёх настроек оператора. `KOSMORA_MCP_URL` содержит утверждённый HTTPS endpoint на стандартном порту. `KOSMORA_MCP_PROJECT` и `KOSMORA_MCP_OWNER` задают одну пару проекта и владельца. Для сервера с авторизацией оператор передаёт `KOSMORA_MCP_BEARER` через секрет окружения. При смене подключения оператор меняет `KOSMORA_MCP_REVISION`. Развёртывание ограничивает исходящие соединения разрешённым публичным хостом. Клиент отклоняет редиректы. Для отключения удалить настройку URL и перезапустить API.

Для живой проверки на разрешённом стенде открыть `/?surface=apps`, выбрать проект и нажать «Проверить MCP и показать инструменты». Сверить имена с каталогом провайдера и найти операцию по идентификатору в центре управления. Общая совместимость конкретных провайдеров требует их подключения и отдельной приёмки. Следующий срез после выбора сервиса — одна явно разрешённая операция чтения с собственной схемой входа, ограничением ресурса и проверяемым результатом. OAuth и каталог подключаемых владельцем серверов потребуют отдельного среза.

Спецификация [Streamable HTTP](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports). Рассмотрен официальный `@modelcontextprotocol/sdk` 1.32.2 (MIT). Для узкой операции проверки подключение новой зависимости не потребовалось. За основу взят протокол, исходники SDK не переносились.

## Предпросмотр и перенос документа

Дополнительные настройки `KOSMORA_MCP_DOCUMENT_URI` и `KOSMORA_MCP_DOCUMENT_NAME` задают один разрешённый ресурс MCP и имя файла .txt или .md. Сервер должен объявить `resources` и ответить на `resources/read` текстом того же URI. Выберите настроенный проект в «Интеграциях», откройте предпросмотр, проверьте текст и источник, затем подтвердите сохранение. Копия появляется в материалах проекта. Проверка доступа и обе операции используют действующий журнал политики.

Предпросмотр с ограниченным сроком хранится в памяти сервера. Журнал содержит ссылку на операцию и хеш URI. Сам документ появляется в постоянном хранилище только после сохранения. Смена версии материалов требует нового предпросмотра. Повтор сохранения с тем же ключом возвращает прежнюю версию. Повтор с прежним ключом чтения требует нового предпросмотра, поэтому старый ответ не выдаёт текст после отзыва. Остановка проекта блокирует чтение и сохранение, отказ удалённого сервера виден при следующем чтении. Уже сохранённая копия остаётся в проекте.

Сквозной HTTP-сценарий входит в `test/mcp-discovery.test.ts`. Он проверяет отказ до сетевого запроса, подмену URI, точный текст, отсутствие сохранения на шаге предпросмотра, конфликт версии, явное сохранение, журнал, повтор и отказ после отзыва. Сценарий интерфейса запускается командой:

```sh
pnpm --filter @cosmora/web exec playwright test e2e/navigation-integration.spec.ts --grep 'MCP'
```

## Живая приёмка с DeepWiki

Оператор может задать публичный репозиторий в `KOSMORA_MCP_DEEPWIKI_REPO` и имя файла в `KOSMORA_MCP_DOCUMENT_NAME` при точном endpoint `https://mcp.deepwiki.com/mcp`. Этот режим использует только `read_wiki_structure` с указанным репозиторием. Передавать bearer, настраивать URI ресурса одновременно или менять репозиторий из браузера в этом режиме нельзя. Результат представляет оглавление вики. Стандартный `resources/read` сохраняется для MCP-серверов, предоставляющих текстовые ресурсы.

Для воспроизведения живого прогона из корня репозитория:

```sh
COSMORA_MCP_ACCEPT_PUBLIC_READ=1 NODE_USE_ENV_PROXY=1 NODE_USE_SYSTEM_CA=1 \
pnpm --filter @cosmora/api exec node --import tsx --conditions=development test/mcp-deepwiki.live.ts
```

В живом прогоне 20 ноября 2026 года сервер вернул 1 594 байта оглавления `modelcontextprotocol/modelcontextprotocol`. SHA-256 совпавшего предпросмотра и сохранённой копии — `5a7a9560417d95edcc4280a54238f72ad11d3ad993693048a697ee33207cf49d`. SQLite работала в памяти. До сохранения вложений было ноль, после него появился один файл версии 1. Повтор вернул 200 без нового внешнего вызова. После остановки тестового проекта новый предпросмотр вернул 409 и сохранённая копия сохранилась. Операции чтения и записи подтверждены журналом. Прогон проверил локальный запрет Kosmora и действующую публичную сеть. У публичного сервера не было OAuth-гранта для отзыва. Отказ самого MCP-сервера проверяется отдельным сценарием на адаптере.

## Выбор из нескольких ресурсов

`KOSMORA_MCP_DOCUMENTS_JSON` принимает список до восьми заранее разрешённых текстовых ресурсов одного MCP-сервера. Пример:

```json
[
  { "uri": "fixture://workspace/report", "name": "report.txt" },
  { "uri": "fixture://workspace/notes", "name": "notes.txt" }
]
```

Используйте список отдельно от настроек одиночного ресурса и режима DeepWiki. Повторяющиеся URI и имена, неизвестные поля и недопустимые имена отключают доступ ко всему списку. В интерфейс передаются имена и идентификаторы, созданные сервером. URI выбранного ресурса возвращается с предпросмотром. Предпросмотр одного документа нельзя сохранить под идентификатором другого. Смена выбора в интерфейсе сбрасывает текущий предпросмотр. Конфигурации с одним ресурсом и с публичным оглавлением DeepWiki продолжают работать.

## Несколько публичных оглавлений DeepWiki

Для того же endpoint DeepWiki оператор может указать до восьми пар `repo` и `name` в `KOSMORA_MCP_DEEPWIKI_DOCUMENTS_JSON`. Например:

```json
[
  { "repo": "modelcontextprotocol/modelcontextprotocol", "name": "mcp-wiki-outline.txt" },
  { "repo": "octocat/Hello-World", "name": "hello-world-outline.txt" }
]
```

Эта настройка используется отдельно от одиночного DeepWiki, общего списка ресурсов и bearer. Список репозиториев сравнивается без учёта регистра. Браузер выбирает непрозрачный идентификатор, приложение вызывает один `read_wiki_structure` с привязанным репозиторием.

Двухфайловый живой прогон запускается той же командой, что указана выше, с добавлением `COSMORA_MCP_ACCEPT_MULTIPLE=1`. На 20 ноября 2026 года два запроса дали 1 594 и 149 байт. Копии побайтно совпали с предпросмотрами, версия материалов выросла до 2. SHA-256 второго оглавления — `9549ad2733efca23d7168189895d141c8d70f66fd1ca6f661287a498da0f7d33`. Неизвестный идентификатор вернул 404 до сетевого вызова. Подстановка ID второго документа при сохранении первого вернула 409. Повторы сохранения вернули исходные квитанции. После локальной остановки проекта новое чтение вернуло 409 без вызова DeepWiki, обе копии сохранились. OAuth в публичном прогоне отсутствовал.

## История сохранённых копий

Кнопка «История импорта MCP» показывает до 20 последних квитанций выбранного проекта из существующего журнала. Квитанция содержит источник, имя файла, SHA-256, версию материалов при сохранении и идентификатор операции. Текст остаётся в материалах проекта. При открытии истории Kosmora сверяет хеш с текущим содержимым одноимённых вложений и показывает точное совпадение, изменение или отсутствие. История доступна после перезагрузки и локальной остановки MCP. Проверка обращается только к локальным данным. Импорты, сделанные до появления квитанций, в историю не добавляются задним числом.

Тест API проверяет совпадение, изменение и удаление файла, отдельный проект и отсутствие сетевого запроса. Браузерная приёмка открывает историю после перезагрузки. Живой прогон DeepWiki дополнительно сверяет обе квитанции после остановки проекта.

## Повторный импорт

Если файл с тем же именем и точным текстом уже есть в материалах, повторный импорт возвращает текущую версию и не создаёт новую копию или квитанцию импорта. Если под таким именем лежит другой текст, сохранение возвращает конфликт и оставляет материалы прежними. Регистр имени не влияет на проверку коллизии. Проверка версии материалов по предпросмотру остаётся обязательной. Тесты проходят повтор с новым предпросмотром и ключом, повтор той же операции и конфликт с отличающимся содержимым.

После конфликта предпросмотр остаётся открытым. Kosmora предлагает свободное имя, например `report-mcp-1.txt`, и сохраняет входящий текст отдельным файлом только после нажатия «Сохранить как». Действие использует прежние разрешения на запись, а предложенное имя привязано к предпросмотру и версии материалов. При потере ответа повтор возвращает ту же квитанцию. В истории у новой копии своё имя и хеш. Исходный файл сохраняет прежнее содержимое.

Проверка API использует локальный HTTP-стенд MCP и временную SQLite. Она сверяет содержимое обеих копий, подтверждение, устаревший предпросмотр, потерянный ответ и остановку проекта. Браузерная проверка имитирует потерю ответа и сверяет ключ повторной отправки.

При повторном импорте с новым предпросмотром Kosmora проверяет точный текст исходного файла и копий с именами вида `report-mcp-1.txt`. Если подходящая копия уже есть, интерфейс показывает её имя и текущую версию материалов. Новое вложение и квитанция при этом не создаются. Если браузер получает 408 или неопределённый ответ 5xx, повторное нажатие отправляет прежний ключ операции.

## Восстановление квитанции после перезагрузки

До отправки сохранения браузер запоминает идентификатор запроса в текущей вкладке по проекту и документу. После перезагрузки откройте тот же документ и нажмите «Проверить результат сохранения». Запрос читает журнал и показывает подтверждённую версию с именем файла, явный отказ или пока неизвестный исход. Предпросмотр и текст документа в браузерное хранилище не попадают. Проверка доступна после аварийной остановки проекта и обращается только к журналу. Для поиска по идентификатору используется та же конфигурация пилота. После её смены детали завершённых импортов доступны в истории.

22 ноября 2026 года двухфайловый прогон DeepWiki вернул обе квитанции после остановки, подтвердил версии 1 и 2 и сохранил байты обеих копий. Новое чтение получило 409. Запросы за квитанциями не добавили внешних вызовов. Тот же сценарий воспроизводится командой живой приёмки с `COSMORA_MCP_ACCEPT_MULTIPLE=1`.

## Атомарное сохранение файла и квитанции

SQLite фиксирует новую версию материалов и квитанцию MCP в одной транзакции. Для этого хранилища материалов и политики используют одно соединение. Тест вводит отказ записи квитанции после обновления материалов и проверяет откат файла и версии. Повтор с тем же ключом остаётся в состоянии восстановления. Новая попытка с действующим предпросмотром фиксирует файл и квитанцию вместе.

```sh
pnpm --filter @cosmora/web exec playwright test e2e/navigation-integration.spec.ts --grep 'imports a reviewed MCP document'
```
