# Оценка масштаба vector scan и кандидатов int8/PQ/HNSW

## Согласованный объём

Продолжение пункта очереди [индекса истории](KOSMORA_SEMANTIC_HISTORY_INDEX_2026-11-03_RU.md)
(«отдельная крупная оценка, absent-fact случаи и при необходимости ускорение vector scan»).
Это пакет измерений, а не внедрение: продуктовый код, хранилища, схемы и зависимости не
менялись. Все кандидаты — measurement-only прототипы в одном bench-модуле; решение о
внедрении любого из них остаётся за владельцем. Semantic-качество с настоящим E5 и
absent-fact случаи — отдельная следующая очередь (нужна верифицированная установка модели
по прежней процедуре).

## Метод

- Детерминированный синтетический корпус: `node:crypto`-независимый seeded RNG (mulberry32),
  100000 строк × 384 dim на unit-сфере, 85% строк в 64 кластерах (σ 0.35), 15% шум —
  роль нерелевантной истории. 4 чанка на источник → 25000 ссылок. 48 запросов: половина на
  центрах кластеров, половина на смеси двух дальних кластеров. Seed датасета 20261108,
  запросов 99 — значения воспроизводимы на любой машине.
- Скан зеркалит продукт по документированным константам (apps/api/src/semantic-memory/
  index-service.ts, packages/db/src/semantic-index-store.ts): страницы 256 строк, на строку
  dot + накопление нормы, dedupe по reference (лучший чанк источника), prune после страницы
  сбрасывает оффкаповые ссылки целиком, топ-32 источника, бюджет 250ms проверяется только
  после страницы. Событийный yield event loop не моделируется.
- Отличие от производства: измеряется JS-стоимость dot/обхода, а не SQLite-доставка страниц;
  числа — относительные замеры одного ПК, не SLA и не интеллект-заявление.

## Измерения

[Полный отчёт](../research/vector-scan-scale-2026-11-08.json): Node v26.13.0, win32,
i5-13420H (12 ядер), стена 8.8 мин. Полный прогон 100000 строк; HNSW — на подмножестве
25000 строк (сборка на полной квоте оценочно существенно дольше; решение измерять на
подмножестве согласовано заранее; в отчёте `hnsw.measured_rows`).

| Конфигурация      | Память векторов | query p50 | p95     | recall@32 p50/p95 | Бюджет hit |
| ----------------- | --------------- | --------- | ------- | ----------------- | ---------- |
| exact float32     | 146.5 MiB       | 247.5 ms  | 270 ms  | 1.0 / 1.0         | 50%        |
| int8 + норма      | 37.4 MiB        | 170.2 ms  | 234 ms  | 1.0 / 1.0         | 2%         |
| PQ ADC (32 байта) | 3.05 MiB        | 42.7 ms   | 156 ms  | 0.125 / 0.19      | —          |
| HNSW ef=128 (25k) | +6.5 MiB граф   | 11.7 ms   | 18.9 ms | 0.469 / 0.69      | —          |

Основное:

1. При полной квоте чанков владельца точный скан впритык к бюджету: p50 247.5ms против
   250ms, половина запросов превысила бюджет — в продукте это именно `scan_limited`:
   частичный обход с явной пометкой. Чем больше чанков у владельца, тем выше доля
   ограниченных сканов; рост квоты усугубляет.
2. int8-кандидат (per-row max-abs scale, храненная кодовая норма, скан пере-выводит
   настоящий косинус квантованного направления) сохранил recall@32 = 1.0 на full-прогоне и
   на 4k smoke при памяти 37.4 MiB вместо 146.5 MiB (−74%) и p50 170ms. По профилю
   стоимость/качество это лидер среди кандидатов; внедрение остаётся решением владельца.
3. PQ без oversampling/refinement на full-прогоне непригоден для замены точного скана:
   0.125@32 recall при p50 42.7ms. Санити реализации: запрос строкой сам находит свой
   источник через ADC как top-1 (24 из 24) — это честная погрешность аппроксимации, не баг.
   Для продукта потребовался бы refine-этап по float32 поверх ADC — отдельное согласование.
4. HNSW-прототип на подмножестве 25000 строк: сборка 396.8s, 656928 рёбер, граф 6.5 MiB;
   recall@32 p50 0.469 / p95 0.688 при ef=128. На 4k smoke recall был 0.906 и сборка 42s:
   качество заметно деградирует с плотностью корпуса; ef — рабочий регулятор, но бо́льшие
   ef-развёрки в объём пакета не входили. Прототип measurement-only, никуда не ввязан.
5. Никаких миграций и новых runtime-зависимостей пакет не добавляет; `scripts/
bench-vector-scan-scale.mjs` — чистый Node без deps.

## Приёмка

`node --test scripts/test/vector-scan-scale.test.mjs` (подключён как `test:vector-scale` и
в `check:core`): 7 инвариант-тестов — детерминизм датасета по seed, self-recall точного
скана, dedupe лучшего чанка, prune при переполнении топ-32, пороги recall int8 ≥ 0.9 /
PQ ≥ 0.7 / HNSW ≥ 0.95 на засеянном малом корпусе (2000 строк × 64 dim; порог PQ ниже,
потому что там поды 2-dim). Временные ассерты отсутствуют сознательно — тесты проходят в CI
на Linux. prettier 3.9.6 (pinned) и check-secrets чисты.
