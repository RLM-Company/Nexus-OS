## 1. Назначение и передовые технологии

Этот блок выводит Kosmora и Koswork на технологический фронтир, внедряя четыре современные технологии, работающие полностью автономно без внешних платных сервисов или нативных бинарных зависимостей:

1. **Плотные семантические векторные эмбеддинги и гибридный поиск Dense + Sparse RRF (`packages/db/src/dense-vector-semantic-search.ts`):**
   - **Offline Dense Vector Engine (лемма Джонсона-Линденштрауса):** генератор 64-мерных плотных векторных эмбеддингов (`Float32Array`) на основе ортогонального случайного проецирования униграмм, стем, биграмм слов, символьных 3-грамм и семантических синонимических групп с L2-нормализацией.
   - **Косинусное сходство (`computeCosineSimilarity`):** вычисляет реальную семантическую близость между фразами без вызова внешних embedding API.
   - **Хранение в SQLite:** таблица `context_memory_dense_vectors` сохраняет векторы в переносимом представлении с SHA-256 контролем целостности.
   - **True Dense + Sparse RRF Hybrid Search (`hybridSearch`):** объединяет плотный косинусный ранг, разреженный лексический ранг и совпадение сущностей через **Reciprocal Rank Fusion (RRF, `k = 60`)**, ставя закреплённые ограничения (`pinned = 1`) на безусловное первое место.

2. **Модельно-ориентированный оптимизатор Prompt Caching с выравниванием по 1024 токенам (`packages/core/src/prompt-caching-optimizer.ts`):**
   - **Упорядочивание по стабильности:** выстраивает блоки контекста в строгом порядке неизменяемости: `system` (системный промпт) -> `tools` (схемы инструментов) -> `pinned_memory` (закреплённая память) -> `project_context` (материалы проекта) -> `conversation_history` (история) -> `active_turn` (динамический хвост).
   - **Контрольные точки кэширования:** расставляет до 4 чекпоинтов `{ "type": "ephemeral" }` на границах блоков, кратных 1024 токенам (стандарт Anthropic для Claude Fable 5 и CheapVibeCode Sol).
   - **Экономический эффект:** обеспечивает прогнозируемый коэффициент попадания в кэш (`estimatedCacheHitRate > 80%`) и расчётное снижение расходов на входные токены до `70–90%` при сохранении детерминированных SHA-256 префиксных хешей.

3. **Автономный протокол мультиагентного консенсуса и состязательной верификации (`packages/db/src/multi-agent-consensus-engine.ts`):**
   - **Трёхсторонняя арбитражная оценка:**
     1. **Агент-Инициатор (Proposer):** оценивает процент покрытия всех заявленных требований задачи и артефактов.
     2. **Состязательный Критик (Adversarial Critic):** активно ищет пустые разделы, логические противоречия и запрещённый маркетинговый флафф/суперлативы («безупречно», «идеально», «100% correct», «unrivaled»).
     3. **Аудитор Фактов (Fact-Auditor):** сверяет каждое число, дату и утверждение черновика со строгим наличием в исходных документах проекта.
   - **Вердикты консенсуса:** `consensus_reached` (при уверенности `>= 0.90`), `revisions_required` (с формированием точных корректирующих директив) или `vetoed` (при критических противоречиях или вымышленных метриках).

4. **Перцептивное хеширование (dHash) и топологический экстрактор схем DrawingML (`desktop/windows/vault-visual-diagram-extractor.cjs`):**
   - **64-битный разностный хеш (dHash):** вычисляет градиентный визуальный отпечаток изображений PNG/JPEG в Vault для дедупликации и поиска масштабированных копий по расстоянию Хэмминга (`Hamming distance <= 5`).
   - **Экстрактор топологии схем из OpenXML (.docx / .pptx):** парсит векторные фигуры DrawingML (`<p:sp>`, `<w:sp>`), текстовые метки и соединительные стрелки (`<p:cxnSp>`), восстанавливая граф связей `(fromNode -> toNode)` для архитектурных диаграмм и блок-схем без внешних OCR-серверов.
