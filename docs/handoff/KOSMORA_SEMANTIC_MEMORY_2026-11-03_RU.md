# Гибридная память Kosmora / Koswork

## Результат и границы

Поиск по смыслу дополняет текущий lexical/FTS recall. Отобранные фрагменты
проходят через тот же JSON/UTF-8 бюджет, source lineage, роли, обязательные
ограничения и квитанции фактической передачи в модель. Тексты остаются данными
в user-context; semantic rank не становится системной инструкцией или согласием.

Подключены обычный чат (streaming и background), серверный Work, native Work
и preview памяти. Сжатие истории сохраняет прежний lexical preview.
Внешний вид и Windows-клиент не меняются. Миграций и нового постоянного
хранилища приватных данных нет.

## Как работает

1. Сначала обычный синхронный scoped recall, чтобы сохранить прежние проверки.
2. Только при существующем включённом разрешении памяти готовятся кандидаты:
   выбранные чаты/проекты, разрешённые personal notes, активные источники.
   Исключены скрытые сообщения, архивы, чужие владельцы, credentials,
   просроченные/устаревшие notes и недавние сообщения, уже находящиеся в истории.
3. Семантический pool ограничен 48 notes и последними 48 сообщениями. На notes
   выделено до 48 фрагментов; общий максимум — 96 по 600 UTF-16 единиц с
   перекрытием 60. Обход по кругу не даёт одному большому сообщению занять все
   позиции. Surrogate pairs не разрываются. Неполный охват помечен `limited`.
   Полный прежний FTS-поиск по разрешённой истории сохраняется.
4. Один отдельный Node worker, CPU, q8 E5; batch=4, intra-op threads=2,
   inter-op threads=1. Нет очереди приватных запросов, удалённого inference,
   записи embeddings на диск или кэша текстов между запросами.
5. После await заново читаются настройки, владелец/lifecycle, разрешения,
   источник, версия note, полный SHA256 и точная цитата. Изменённые/отозванные
   источники не используются. При смене settings возвращается свежий lexical.
6. Максимум 8 semantic sources дополняют lexical через RRF (k=60), fixed cosine
   gate 0.72 и отступ от первого результата 0.06. Cosine не является вероятностью
   истинности факта. Обязательные записи всегда впереди; при их потере действует
   прежний явный отказ. Trusted retrieval order сохраняется при final packing.

Результаты за пределами pool не объявляются просмотренными. Вопрос для encoder
ограничен первыми 2 000 UTF-16 единицами; tokenizer может дополнительно обрезать
до 512 токенов. Исходный вопрос/история/сохранённые документы не изменяются.

## Отказы и ресурсы

При холодном запуске, занятости, неверной модели, malformed result или ошибке
encoder используется **заново проверенный** lexical recall. В рабочем API
inference ограничен 8 секундами, boot — 60 секундами. Отмена прекращает запрос,
а не превращается в успешный fallback. Worker завершается, пока старый worker
не вышел, второй не запускается; новые попытки boot — по следующему запросу,
не раньше 30 секунд, максимум 3 запуска за жизнь процесса. Без бесконечных
фоновых перезапусков. Shutdown освобождает worker.

SHA256 фиксирует загруженные публичные assets; путь установки контролирует
оператор. Worker изолирует CPU-работу от event loop, но не является sandbox ОС.
Отсутствие постоянных embeddings не означает гарантированное обнуление всей
native RAM. На диске остаются прежние исходники/БД и публичная модель.

## Включение

По умолчанию сервер продолжает прежний lexical-путь. Оператор устанавливает
проверенный комплект отдельной командой и задаёт абсолютный путь:

```sh
node scripts/install-semantic-memory-model.mjs /absolute/path/to/model
KOSMORA_SEMANTIC_MODEL_DIR=/absolute/path/to/model
```

Следующий штатный запуск API прогревает модель без задержки HTTP-старта.
Чат/проект всё равно должен иметь прежние явные grants памяти. Кнопка в UI,
новый провайдер и платный маршрут не добавляются.

API build явно копирует два plain-Node worker assets в dist. SDK не включён
в TS-программу всего API, чтобы его ambient types не меняли unrelated fetch
declarations. Реальная production-сборка проверяется запуском dist-worker.

В этой поставке VPS, локальный запущенный API и установленный клиент владельца
не обновляются. Живая модель/Windows-приёмка первого этапа остаётся отдельно.

## Проверка

- DB: доступ до inference, отзыв/удаление/редактирование/архив/expiry после await,
  межвладельческая изоляция и project history, роли, номера, ограничения,
  Unicode, размер и частичный охват, отмена, fallback и lifecycle fence.
- Core: trusted hybrid order, объединение источников/метаданных и точный размер.
- API: от semantic recall до capture модельного запроса и exact usage receipt;
  corruption локальной модели отклоняется до принятия приватных passages.
- [Настоящие веса, замороженный набор и результаты](../research/SEMANTIC_MEMORY_ENCODER_2026-11-03.md).

Дальше: более широкий инкрементальный индекс с privacy lifecycle, независимый
большой набор, ответы «источника нет», свежие исправления и reranker. Это очередь,
не уже реализованные функции; сохранение старого текста не обучает веса модели.
