## Что перенесено и исправлено

- Параметры image/STT/TTS проверяются до создания задачи, резерва и запроса.
  Размеры изображений: 1024×1024, 1536×1024, 1024×1536; качества low/medium/high/auto;
  PNG/JPEG/WebP; одна картинка за операцию. Соотношения 16:9 и 9:16 отклоняются,
  вместо выдачи 3:2/2:3 под другим названием. Параметры доступны в API и capabilities.
- Озвучка поддерживает голос, скорость 0.25–4 и форматы mp3/wav/opus.
  Для Ogg-контейнера провайдеру отправляется `response_format: opus`.
  STT принимает поддерживаемые аудио MIME, двухбуквенный язык и заявленную длительность.
  Для PCM WAV длительность независимо считается из RIFF-чанков, включая файл с
  дополнительными чанками. Неправильные заголовки и PCM дольше 60 секунд отклоняются.
  Для сжатых контейнеров подпись проверяется, но независимого декодера длительности
  нет: `duration_seconds` для них остаётся заявлением клиента, а не измерением сервера.
- `client_request_id`, `X-Client-Request-Id` и `Idempotency-Key` сохраняются с
  отпечатком нормализованных параметров. Один ID/владелец/тип операции возвращает
  ту же задачу до и после рестарта; изменение входа даёт 409. Противоречащие ID
  в теле и заголовках отклоняются. Удаление результата владельцем удаляет и задачу;
  после явного удаления новая операция с прежним ID возможна.
- Таймаут фиксируется как failed/timeout, пользовательская отмена как cancelled.
  Аварийная остановка и деактивация владельца прерывают выполнение. Задача,
  игнорирующая отмену, сохраняет свой слот до завершения транспорта: поздние байты
  не записываются, второй запрос параллельно не запускается. Резерв до выяснения
  результата сохраняется. Ошибка учёта при восстановлении не вызывает повторного запроса.
- Провайдерские ошибки нормализуются без сырых диагностик и промптов.
  Лимит времени действует на получение тела после заголовков; размер потока ограничен.
  Файлы проверяются по фактической сигнатуре, MIME, расширению, размеру и SHA-256
  при сохранении и скачивании. Приватные медиа-ответы имеют private/no-store.

## Что сохранено из актуального main

Действующие `AccountMediaBudget`, канонический финансовый учёт, серверные настройки
и миграции не заменялись старой копией Gemini. Нового кошелька и вымышленных цен нет.
Существующий настроенный API origin CheapVibeCode и запрет неподтверждённых audio-маршрутов
этого origin сохранены. Редактирование изображения с референсами, включая обычный чат,
сохранено; отпечаток идемпотентности включает содержимое референсов, исходные изображения
в метаданные задачи не записываются. Существующие задачи PNG/MP3 остаются читаемыми.

Динамическое скачивание `data[0].url` из пакета не перенесено: проверка имени хоста
без привязки DNS-адреса не исключала SSRF. Как и раньше, ожидаются встроенные бинарные
данные ответа; URL-only результат отклоняется без второго сетевого запроса.
Loopback/test-переключатель в производственный адаптер не добавлен.

UI, CSS, лого, сайдбар и общий экран чата не изменены. Предложенные визуальные
элементы записаны в `docs/design/VISUAL_WAITLIST.md`.
VPS, VPN, реальные данные пользователей и Windows-установка не затрагивались.

## Проверки и предел доказательств

Локально: 37 тестов в пяти медиа/chat-image файлах, включая 19 новых сценариев;
5 Node-проверок сценария приёмки. Использованы только локальные байты и подставной
транспорт, платных запросов не было. Полная CI-проверка привязывается к commit PR
и отдельно записывается в подготовленном release status.

В текущем пакете сохранены утверждённые идентификаторы моделей, автоматической
смены провайдера/ядра нет. Важное ограничение живого запуска: официальная документация
OpenAI на дату проверки сообщает об отключении `gpt-image-1` 23 октября 2026.
Доступность одноимённого маршрута у совместимого провайдера этим не подтверждается;
после восстановления VPS необходимо проверить его и при необходимости отдельно
выбрать поддерживаемую модель. `ready` означает локальную конфигурационную готовность,
а не успешную оплачиваемую генерацию или сверку счета провайдера.

Контракт сверялся с официальными страницами:

- [Создание изображения](https://developers.openai.com/api/reference/resources/images/methods/generate)
- [Синтез речи](https://developers.openai.com/api/reference/typescript/resources/audio/subresources/speech/methods/create)
- [Распознавание речи](https://developers.openai.com/api/reference/resources/audio/subresources/transcriptions/methods/create)

## Живая приёмка после восстановления сервера

`scripts/media-live-acceptance.mjs` ничего не делает при импорте. Для запуска нужны
оба подтверждения: CLI `--confirm-live-paid-media` и переменная
`KOSMORA_MEDIA_LIVE_CONFIRM=YES_RUN_PAID_ACCEPTANCE`.
Также требуются `KOSMORA_MEDIA_API_ORIGIN`, приватный
`KOSMORA_MEDIA_OWNER_BEARER_TOKEN` и абсолютный `KOSMORA_MEDIA_LIVE_REPORT_DIR`.
`KOSMORA_MEDIA_LIVE_MAX_OPS` — 1..3, по умолчанию 1: изображение, затем TTS, затем STT.
Для третьей операции нужен абсолютный `KOSMORA_MEDIA_LIVE_WAV_PATH` с коротким
собственным образцом русской речи; тишина не выдаётся за проверку качества STT.

Сценарий проверяет готовность всех выбранных возможностей перед первой отправкой,
использует один POST на операцию, запрещает редиректы и автоматические повторы,
проверяет ID задачи и SHA/байты/MIME скачанного файла. При неопределённом исходе
останавливается. Отчёт — в новом приватном подкаталоге, без ключей, записи голоса,
полного транскрипта и сырого текста ошибок. Стоимость и счета автоматически не сверяются.
Сам сценарий платной приёмки в этой интеграции не запускался.
