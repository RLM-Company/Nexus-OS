# Koswork: связанный итог локальной задачи и проверка серверных результатов

Поставка от8 ноября2026 года. Исходная база API-подрядчика:
`338536ee5946f96dcd18768143cc41af998c476a`. Codex проверил и адаптировал пакет HY4,
подключил общий main boundary и добавил настоящие регрессионные сценарии.

## Что меняется для пользователя

После локального поручения исходный проект получает краткий итог и число шагов,
отмеченных агентом завершёнными. Квитанция не заменяет проверку байтов файла,
запуск кода, оценку Critic или личное подтверждение владельца. Интерфейс прямо
указывает «По отчёту агента». Компоновка чата/сайдбара, оформление и логотип сохранены.

Локальная квитанция создаётся из текущего наблюдения и завершённого Work-плана.
Реальный `main.cjs` передаёт originating requestId и версию документа в native relay.
Проверяются nonce, запрос, владелец, origin, проект, документ и контекст. Обратная
доставка принимает только ticket, созданный этим relay, и сохраняет прежние проверки
identityEpoch/текущего документа, privacy lifecycle, проекта и права на передачу итога.
Отмена/повторная доставка/смена страницы не возвращают поздний результат другому запросу.

Ticket передаётся только между host-функциями; через IPC он не раскрывается.
Публичная квитанция содержит только наблюдение, среду, идентификатор задачи и числа
шагов. Из неё удаляются внутренние owner/origin/document/request/nonce; сырые критерии,
локальные пути, содержимое файлов, credentials и скриншоты автоматически не передаются.
`owner_accepted=false`, источник — `local_agent_report`. Старый вызов `show` без
новых параметров по-прежнему возвращает bounded summary без квитанции.

Серверный Work DAG повторно читает опубликованный артефакт и проверяет реальные
байты, длину, SHA-256, метаданные версии, связь с владельцем/проектом/работой/попыткой.
Используется фактический контракт `{metadata,content}`, без второго хранилища.
Повреждённая длина при корректном хеше тоже отклоняется до выдачи результата.
Оценка содержания моделью отделена от проверки байтов и исполнения кода.

ZIP остаётся совместимым с существующими графами без новых optional-полей.
Проверочные сведения выводятся из байтов и review, а не из произвольных меток.
Внутренний owner_id и дополнительные приватные поля в manifest не попадают.

## Проверка и исправление поставки API

Подрядчик возвращал исходники без терминала; все исполнения ниже выполнил Codex.
Обнаружены и исправлены несовместимая форма метаданных, обязательные «optional»
поля архива, утечка owner_id, невозможный validator квитанции, отсутствие связки
с реальным main callback, потеря receipt при повторной проекции и нарушение старого
вызова без binding options. Негативные проверки сохранены.

Сгенерированный CSV-сценарий с несогласованными индексами, зависающим ожиданием и
ложным completed при непроверенном плане заменён компактными рабочими сценариями.
Они читают настоящий бриф и CSV из временной scoped-папки, вычисляют24000 из
прочитанных19700 и4300, сохраняют файл, читают его обратно и завершают план.
Вариант с явной паузой продолжает через свежее наблюдение и сохраняет файл один раз.
Существующие проверки отзыва grants, recovery и изменившихся источников сохранены.

Выполнены:

```powershell
node --test --test-timeout=15000 desktop/windows/test/*.test.cjs
pnpm --filter @cosmora/api exec vitest run test/work-dag.test.ts test/work-results-archive.test.ts test/manager-work.test.ts --maxWorkers=2
pnpm --filter @cosmora/api typecheck
pnpm --filter @cosmora/web typecheck
```

Результат:347 native-тестов и121 серверная проверка прошли; API/web typecheck прошёл.
Native-набор включает VM-тест фактического IPC handler из main.cjs, а не копию его
логики: доставка в правильный запрос, повтор, смена документа/владельца и отзыв scope.
Нет управления реальным ПК владельца; модели/внешние API в этих сценариях — fixtures.

Локальный production E2E-запуск остановился на180-секундном ожидании холодной сборки
до исполнения браузерных сценариев. Это не успешный E2E-прогон. Изменённые проверки
`apps/web/e2e/manager-work.spec.ts` должны пройти в стандартном Browser acceptance CI
до объединения. Также требуется штатная Windows CI-сборка и installer lifecycle.

## Версия и границы

Нативный клиент:0.24.0. Новые миграции, зависимости, фоновые исполнители и разрешения
не добавлены; формат сохранённой истории не менялся. На ноутбуке владельца клиент
не обновлялся, на VPS эта поставка не выкладывалась. Откат — API/web предыдущего
релиза и клиент0.23.0; receipt хранится в памяти и не восстанавливает grants.

Это проверенный участок цикла Koswork. Полная приёмка с живой моделью, нативным
приложением владельца, реальными внешними действиями и оставшиеся workflow/история
критериев учитываются отдельно. Multi-Agent, Jarvis, Office и облачный ПК не входят.
