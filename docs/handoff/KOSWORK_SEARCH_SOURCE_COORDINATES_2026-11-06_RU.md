# Koswork: точные координаты и выдержки поиска в рабочей папке

Следующий блок целостности источников. Поиск в выбранной рабочей папке показывал
первые 240 UTF-16 единиц строки даже при совпадении значительно дальше. Модель
получала результат без самого найденного условия. `toLowerCase()` мог расширить
символ до нескольких единиц и сместить возвращаемую колонку оригинала.

Теперь запрос экранируется как буквальный текст и ищется Unicode-регулярным
выражением без пользовательских операторов. Для insensitive используется простое
Unicode-сопоставление `iu`, без нормализации, locale-specific/full case-fold
или соответствия нескольких букв одной. Это уточнение семантики: `İ` не считается
простой заменой `i`, а последующие совпадения получают координаты оригинала.

Выдержка строится вокруг первого совпадения строки, сохраняет целые Unicode-
символы и ограничение 240 UTF-16 единиц. `column` остаётся 1-based координатой
в исходной строке; `column_unit=utf16`, match length, начальная/конечная колонки
выдержки, `preview_excerpt_only` и `match_in_preview` делают её границы явными.
Если сервису передан запрос длиннее preview, полнота совпадения не выдумывается.
Обычный агентский запрос ограничен действующим API 200 символами.

SHA256/версия остаются от исходного файла, файл не переписывается. Права,
фильтрация бинарных/крупных/чувствительных файлов, отмена и границы количества
результатов прежние. Чтение полного контекста выполняется существующими
инструментами по версии. Дизайн и новые инструменты не добавляются.

Проверки на реальных временных файлах: смешанные CRLF, длинная строка,
`İ` перед совпадением, emoji на обеих границах выдержки, точная обратная адресация
source.slice, сохранность файла, 00123/19 700 ₽/«кроме доставки», case-sensitive
отказ и буквальные regex-метасимволы. Запрос длиннее preview честно отмечен.
Новая регрессия выявляет прежнее поведение. Windows-кандидат 0.21.2; CI,
server/owner installation и живая модель учитываются отдельно.
