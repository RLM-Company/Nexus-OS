# Koswork: буквальный поиск в тексте браузера

Источник сценария: [поставка Gemini](../research/gemini-delivery-2026-11-10/README.md).
Реализация адаптирована под действующий Chromium/CDP engine, без замены UI.
Windows package candidate: **0.26.0**; на устройство владельца не установлен.

## Контракт

`browser_find_text` принимает `query` (1–160 UTF-16 единиц, непустая строка),
`case_sensitive`, `offset_utf16` и `expected_version`.
Начало: offset 0, version null. Продолжение требует точной возвращённой версии.
API должен объявить `supports_browser_text_find=true`, а native observation —
`browser.find_text=true`; старые стороны не получают неоговорённое действие.

Ответ содержит до 20 непересекающихся совпадений с исходными UTF-16 start/end
и quote. Общий сериализованный ответ — до 10 000 UTF-8 байт. Есть next_offset,
matches_truncated и complete_scan_from_offset. Отмена отбрасывает запоздалый ответ.
Изменение страницы отменяет продолжение с прежней версией.
Регистронезависимый поиск использует Unicode simple matching, без нормализации,
транслитерации или языкового морфологического поиска.

Это поиск в ограниченном reader snapshot, **не во всём документе**:
скрытые/редактируемые области, iframe, shadow DOM, изображения и CSS-generated
текст исключены; source_truncated и остальные ограничения возвращаются явно.
Совпадение не является доказательством истинности фразы. Контекст можно прочесть
через browser_read_text с той же версией и полученной позицией.

## Проверено локально

- 60 native проверок: Unicode, буквальные метасимволы, длинные UTF-8/escaped
  ответы, пагинация, неизменность quote/offset, версии, отмена, API/native negotiation.
- 88 API проверок computer-control: в том числе отказ без native capability
  и принятие корректного действия при согласованных возможностях.
- Платные модели, сервер и управление приложениями владельца не использовались.

В реальную Chromium DOM smoke-проверку добавлены поиск вне viewport, сохранение
версии reader и отсутствие совпадений в исключённом скрытом/редактируемом тексте.
Полная приёмка сборки и CI фиксируется в Pull Request; локальные unit-тесты
не заменяют живую приёмку установленного Windows-клиента.
