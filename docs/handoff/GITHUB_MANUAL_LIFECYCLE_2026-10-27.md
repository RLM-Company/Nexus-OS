# Ожидание обычных GitHub-операций — 27 октября 2026

Продолжает исправление Code: обычные маршруты подготовки, публикации и сверки
GitHub draft теперь также учитывают текущие операции. Остановка веб-API и
privacy-адаптер ждут завершения их уже отправленных запросов.

- Новая операция не принимается после остановки, при локальном ограждении владельца
  или при неактивном durable lifecycle. Ограждение одного владельца не является
  глобальным разрешением или сменой привязанного репозитория.
- Перед каждой следующей внешней записью проверяются остановка, актуальный проект,
  lifecycle владельца и существующий аварийный выключатель. Архивный/ошибочный
  проект не публикуется. Пустой DRAFT-проект сохраняет прежний ручной сценарий.
- Если первая запись уже могла произойти, draft остаётся uncertain. Его нельзя
  повторно опубликовать; существующая сверка использует только чтение GitHub.
- Подтверждённый ответ PR или результат сверки записываются до завершения ожидания,
  чтобы экспорт отражал известный исход. Автоматического повторного POST нет.
- Локальный review не создаётся после ограждения, даже если чтение репозитория
  началось раньше. После экспорта доступ возвращается только при совпадающем
  epoch и законченном ожидании. Код не снимает SQLite-триггеры или durable fence.

`CodeIntegratedPrivacyAdapter` теперь ждёт и Code-сервис, и общие ручные draft
операции. Производственный server передаёт ему тот же GithubDraftStore, который
обслуживает маршруты. Сами draft-записи продолжают экспортироваться/удаляться
через account-core; дублирования записей в архиве нет.

Проверки задерживают ответы первой Git-записи, создания PR и GET-сверки на настоящих
Fastify-маршрутах с SQLite. Проверяются ожидание закрытия, ограждение/возобновление,
отказ при другом epoch, отсутствие следующих/повторных POST и сохранение известного
PR. GitHub и модель синтетические; платных запросов или живых PR эти проверки не
создают. Визуал, маршруты, зависимости и схема БД не меняются.
