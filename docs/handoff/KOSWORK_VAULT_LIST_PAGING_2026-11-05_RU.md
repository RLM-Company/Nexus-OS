# Koswork: устойчивый обход списка материалов Vault

Пакет поверх PR #446. workspace_list возвращает next_list_path, привязанный
к составу библиотеки и текущему grant. Следующая страница запрашивается тем же
workspace_list с cursor 0. Добавление/удаление источника или новое разрешение
делают старый путь непригодным: WORKSPACE_VERSION_CONFLICT требует свежего списка.
Оригиналы и содержимое не меняются, новый доступ к данным не выдаётся.

Совместимость: числовой nextCursor сохранён. Старый вызов с PREFIX/cursor>0
разрешён после первой страницы в том же grant и только при неизменном составе.
Предел — 10 записей и 14000 serialized UTF-8 bytes на ответ. Список — навигация,
не доказательство целостности содержимого; реальные read/get повторно проверяют
оригинальные байты и SHA256.

Проверки: 21 workspace test passed; полный desktop 272 tests, 271 passed,
0 failed, 1 штатный Windows-only skip. 25 источников без дублей/потерь, старые
числовые cursors, изменение состава, повторное grant, JSON-byte bounds.
Secrets/format/whitespace прошли. Нет UI/dependency/migration, платных вызовов,
установки Windows или VPS. Новый CI/review проверяются отдельно.

## Сквозной сценарий через настоящий ComputerSession/WorkCycleDriver

Добавлен scripted-planner сценарий: три страницы списка → несколько страниц
оглавления → поздний раздел 94 → подтверждённая запись report.md → чтение
результата с диска → checked/done → отзыв Vault. Проверяются 00123, 19 700 ₽
и «кроме доставки», отсутствие browser/computer grants. Это реальный файловый
исполнитель со сценарным планировщиком, не live LLM acceptance.
Итоговый полный набор: 273 tests, 272 passed, 0 failed, 1 штатный skip;
22 workspace tests passed. Финальный commit должен пройти новый CI.
