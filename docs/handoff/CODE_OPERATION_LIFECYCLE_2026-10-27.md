# Завершение операций Code — 27 октября 2026

Просмотр изменений, публикация и сверка результата теперь учитываются вместе с
генерацией и проверкой как текущие операции сервиса. Раньше `stop()` и
`quiesceOwner()` дожидались только генерации/проверки, поэтому могли сообщить об
остановке, пока публикация ещё ожидала GitHub.

## Поведение

- До двух операций сервиса одновременно; одна операция на Code run. Параллельный
  просмотр/проверка/публикация одного снимка отклоняется до изменения его состояния.
- Закрытие настоящего Fastify-приложения вызывает `CodeAgentService.stop()` до
  закрытия базы. Новые операции после остановки не запускаются.
- `stop()` и остановка владельца ждут завершения уже отправленного HTTP-запроса.
  Следующая запись в GitHub блокируется. Существующий тайм-аут HTTP сохраняется;
  остановка не объявляется завершённой до окончания запроса.
- Если запись уже могла произойти, сохраняется неопределённость. Повторная запись
  не выполняется. Результат подтверждается существующей сверкой чтением GitHub.
- Если валидный ответ уже подтвердил созданный PR, после снятия privacy-fence
  сохраняется подтверждённый результат, без повторного создания PR.
- Локальный GitHub review не вставляется после того, как владелец перешёл под
  durable privacy-fence во время чтения базы репозитория.
- Явный повтор подготовки review фиксирует отдельную версию попытки. Он не
  переиспользует ошибочный policy recovery предыдущей подготовки и не запускает
  новую генерацию модели. Хэши снимка и выбранных изменений проверяются заново.

## Экспорт данных

Code-адаптер блокирует новые операции владельца и ждёт все его текущие операции,
включая публикацию/сверку/просмотр. Существующие SQLite-триггеры по-прежнему
запрещают изменение Code run во время глобального ограждения; они не отключаются.

После экспорта адаптер возобновляет доступ только после завершения ожидания и при
совпадающем epoch с активным состоянием владельца. Захваченные незавершённые
генерации/проверки получают явную ошибку прерывания. Публикация согласуется с
сохранённым draft: подтверждена, не начиналась или требует сверки. Старое
подтверждение публикации аннулируется. Автоматического повтора и нового платного
запроса нет. Удаление дожидается операций до удаления принадлежащих владельцу строк.

`whenIdle()` — внутреннее ожидание уже текущих операций без их отмены. Оно
используется при проверке явного повторного запуска после завершившейся проверки;
не является командой остановки или разрешением на публикацию.

## Проверки и границы

Регрессии проходят через реальный сервис, Fastify, SQLite, политики и транспортный
адаптер. Задерживается ответ GitHub при первой записи и при создании PR; проверяется
ожидание, отсутствие последующих/повторных записей, правильный результат после
снятия ограждения и отказ при неверном epoch. Отдельно проверяются поздний review
и закрытие приложения во время модельного запроса.

Внешние GitHub/модель и OCI-результат в этих сценариях синтетические. Это проверка
жизненного цикла, а не новый живой PR или доказательство работы контейнерной
изоляции. Пользовательские данные, визуал, схема БД, разрешения и провайдеры не
меняются. Новых маршрутов и зависимостей нет.
