# Koswork: защита от повторов и чтение строк

## Результат

Два полезных отсутствующих механизма из согласованного разбора Ruflo подключены
к реальному пути локального Work. Нового framework, daemon или MCP-зависимости
нет. Изменения основаны на [проверенном исходном плане](../research/RUFLO_REVIEW_2026-11-03_RU.md),
а не на неподтверждённых заявлениях upstream о производительности.

## Защита от повторов

- Локальный `WorkRetryGuard` создаётся заново на один owner-approved Work-запуск.
  Состояние не разделяется с другими владельцами, задачами или перезапусками.
- Учитываются только явно разрешённые локальные ошибки до внешнего эффекта,
  ошибки проверки Work-плана и отказ адаптера вернуть слишком большой результат
  чтения. Строки из файлов/страниц и модельные заявления об ошибке не учитываются.
- После двух одинаковых отказов по одному действию, контексту и причине —
  рекомендация сменить подход; после третьего — `WORK_REPEATED_FAILURES` перед
  следующим наблюдением и planner-запросом. Остановка сохраняет текущую логику
  завершения сессии, журнала, отмены и отзыва прав.
- Ключ сохраняет буквальные аргументы, включая пробелы внутри строк. История
  ограничена 64 хешированными ключами, без сохранения путей/содержимого в ней.
  Workspace, tab и DOM generation разделяют действия в разных пространствах.
- Успех этого действия очищает его счётчик; успех посторонней команды не стирает
  ранее известные отказы. Другая причина отказа начинает новый счётчик.
- Смена окна, устаревшее наблюдение и активный пользователь не считаются
  повторяющейся ошибкой модели. Неизвестный частичный эффект по-прежнему
  останавливает выполнение сразу, без повторов.

Это защита от точных повторов, а не распознавание любого смыслового цикла.
Сильно меняющиеся аргументы, другая версия DOM или явный новый запуск могут
начать новый счётчик. Существующие лимиты шагов и разрешений сохраняются.
Самостоятельные legacy Computer/Browser сессии сохраняют прежнюю политику;
защита действует в Work, включая его браузерное и файловое окружение.

## Чтение больших файлов

`workspace_read_lines` проходит через контракт, проверку API и нативную проверку
действия, обычную выбранную папку и существующий защищённый файловый снимок.
Результат — точная подстрока декодированного UTF-8 текста, переводы строк
CRLF/CR/LF, номера строк, продолжение и SHA256/версия всех исходных байтов.
Неизвестные символы не заменяются: некорректный UTF-8/бинарный файл отклоняется.

Сканирование границ строк не создаёт массив на каждую строку. Сохраняется
внутренний предел исходника 2 МиБ по умолчанию; вывод — до 120 строк и 10 000
UTF-8 байт сериализованного поля `content`, плюс метаданные. Это предел одного
результата инструмента с продолжением, а не новый глобальный лимит модели.
При переполнении результат не обрезается: нужно сузить запрос.

`expected_version` обязателен как поле: `null` для нового снимка, либо точный
`sha256:...` для продолжения. При изменении файла старая версия отклоняется.
Полный overwrite дополнительно проверяет, что эта версия помещается в полный
read-инструмент: фрагмент большого файла не позволяет затереть его короткой
заменой. Нативное подтверждение записи и проверка версии перед commit сохранены.

## Совместимость и выпуск

Новый API объявляет `supports_workspace_read_lines`. Новый клиент передаёт
`workspace.read_lines: true` только после этого ответа и только для подключённой
обычной папки. Поэтому новый клиент со старым API сохраняет прежний wire format,
а новый API со старым клиентом не рекламирует и не отправляет новую команду.
Без этой возможности новый prompt-блок не добавляется в запрос модели.
Vault сохраняет свой read-only протокол: новая команда для него отклоняется.

Изменения находятся в исходниках. VPS и рабочие локальные службы не перезапускались;
новый Windows-бинарник не установлен. Живая Windows-приёмка остаётся отдельной.

## Проверка

Локально прошли 218 тестов полного desktop-набора и 49 тестов computer-control
API. Проверка нового пути включает реальный Work-драйвер, временный большой
файл, поиск версии и чтение точных строк с тестовым планировщиком без доступа
к экрану или браузеру. Сборка contracts и проверки типов/стиля выполняются отдельно.

- Полный `pnpm --dir desktop/windows test`: настоящие временные файлы, защита
  путей/владельца, цикл Work и тестовые драйверы/планировщики; без пользовательских
  файлов, Telegram и управления реальным рабочим столом.
- `pnpm --filter @cosmora/api exec vitest run test/computer-control.test.ts --maxWorkers=1 --no-file-parallelism`:
  API, контракт и тестовый Gateway, включая отклонение несовместимого клиента.
- Сборка contracts, typecheck API, ESLint изменённых API-файлов, форматирование,
  проверка секретов и whitespace.

Реальные платные AI-запросы для этой приёмки не нужны. Общая экономия токенов,
скорость и качество на пользовательских задачах ещё не измерены; не приписываем
двум локальным механизмам превосходство над целыми конкурентными системами.
