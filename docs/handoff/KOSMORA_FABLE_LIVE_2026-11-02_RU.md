# Fable через Kosmora: локальная интеграция и живая приёмка

Владелец 2 ноября разрешил подключить предоставленный ключ к Kosmora и выполнять
реальные задачи на `claude-fable-5`. Провайдер из его OpenCode — TokenShop,
`https://token-shop.online/v1`. `/models` принял ключ и вернул точный ID.
Это наблюдение маршрута провайдера, не доказательство происхождения весов модели.

## Подключение

Публичный профиль: `config/model-registry.tokenshop.fable.v1.json`.
Секретов в нём нет. Runtime использует штатный OpenAI-compatible адаптер:

```dotenv
MODEL_PROVIDER=openai-compatible
MODEL_PROVIDER_ID=tokenshop
MODEL_NAME=claude-fable-5
MODEL_BASE_URL=https://token-shop.online/v1
MODEL_REGISTRY_PATH=config/model-registry.tokenshop.fable.v1.json
MODEL_FALLBACK_TO_MOCK=false
MODEL_MAX_ATTEMPTS_PER_ROUTE=1
MANAGER_TIMEOUT_MS=600000
MANAGER_MAX_OUTPUT_TOKENS=100000
```

`MODEL_API_KEY` передаётся только через приватное окружение процесса. Для локального
профиля создан отдельный каталог оператора вне репозитория с приватной конфигурацией
и отдельной SQLite-базой. Локальный API слушает только `127.0.0.1:3310`, web —
`127.0.0.1:3300`. API использует существующую development identity `local-owner`;
этот профиль не предназначен для публикации в интернете. Локальный лимит аккаунта
`max_total_tokens=null`, Relay выключен, подмена mock отключена.

Окно настроено на 1 000 000, ответ — до 100 000 токенов. Это эксплуатационные
настройки по верхним границам исходной модели, а не нагрузочная проверка полного
окна у посредника. Источник спецификаций:
[Anthropic Fable 5](https://platform.claude.com/docs/en/models/fable-5/overview).
Фактические границы relay требуют отдельного измерения. Его цены/retention неизвестны;
в реестре они не подменены тарифами/гарантиями Anthropic. Discovery действительно до
9 ноября: перед дальнейшей эксплуатацией выполнить новое обнаружение, не стирать TTL.

## Изменения интеграции

- Убран старый контрактный потолок Work 32К входа/8К выхода. Общий бюджет трёх
  этапов допускает до 3 000 000 входных и 300 000 выходных токенов. Это сумма
  этапов, не увеличение физического окна одной модели. Маршрутизатор продолжает
  проверять лимиты модели и политики владельца.
- API сообщает настроенное окно из реестра. Существующая панель Work рассчитывает
  бюджет по нему и максимальному ответу; показанное значение совпадает с POST.
  Старые API без поля окна сохраняют совместимый fallback. Визуал/сайдбар не менялись.
- В реальном ответе критика обнаружена полная обёртка `<escape>JSON</escape>`.
  Work принимает один такой контейнер и затем строго проверяет схему этапа.
  Произвольный текст, вложенные обёртки и HTML-entity JSON отвергаются. Содержимое
  строк/файлов не преобразуется, FAIL остаётся отказом, внешние права не расширяются.

## Что реально прошло

Локальные настоящие API, SQLite, web, HTTP/SSE адаптер и внешний провайдер;
mock не использовался для модельных ответов.

1. Чат прочитал синтетическое вложение и вернул точный marker/сумму.
2. Последующий успешный запрос восстановил их из истории без нового вложения.
3. Koswork создала модуль упаковки контекста, тесты и документацию. Первые версии
   критик отклонил за реальные дефекты дат и sparse-массивов. Исправления переданы
   явно новыми задачами; автоматического саморедактирования репозитория не заявляем.
4. Финальная задача `4c354b9b-fec2-43eb-9689-52cc8e524238` завершилась `completed`,
   критик — `PASS`. Все три файла скачаны через API и побайтно совпали с результатом.
5. Созданные моделью тесты реально запущены оператором в Node permission mode
   с чтением только каталога артефактов, без разрешения сети/дочерних процессов.
   Они прошли. Ещё 11 независимых сценариев прошли; 100 000 кандидатов обработаны
   за 270 мс на ноутбуке в одном измерении. Это не benchmark всей модели/системы.
6. Headless Chromium проверил настоящий интерфейс Work: POST содержит бюджеты
   3 000 000/300 000. POST перехвачен тестом, дополнительного модельного вызова не было.

На момент отчёта: 12 успешных модельных вызовов приложения, 116 185 суммарных
токенов по известным usage провайдера, два неуспешных вызова с HTTP 502. Консервативный
счётчик Kosmora выше — включает верхние оценки при неизвестной цене/расходе;
его нельзя выдавать за фактическое списание провайдера. Заявленный владельцем
баланс 1 млрд отдельно не проверялся. Доступность провайдера нестабильна:
один короткий повтор прошёл, но отсутствие будущих 502 не гарантируется.

Артефакты находятся в операторском каталоге `2026-11-02/kosmora-fable-live/`:
`acceptance-report.json`, `final/`, `ui-check.json`, `work-ui.png`, квитанции запусков.
Код модуля не подключён к действующему алгоритму памяти без отдельного ревью интеграции.

Исходниковые проверки: 79 API-тестов (Work/runtime/структурированный JSON),
2 контрактных теста больших бюджетов, API/web typecheck, сборка API с зависимостями,
ESLint, форматирование, secret scan. Все проверки использовали fixtures, кроме
явно описанной выше отдельной живой приёмки.

## VPS остаётся отдельным шагом

SSH нового VPS доступен, контейнеры здоровы, внешний HTTPS не подтвердился.
Read-only проверка показала прежний `cheapvibecode/gpt-6.1-sol`, output cap 1200,
`RUNTIME_EMERGENCY_STOP=true`. Конфигурация, код, БД и остановка VPS не менялись.
Локальный профиль не является завершённой серверной выкладкой. Будущая активация
требует нормального HTTPS, резервной копии/проверки миграций и совместимой версии
API/web. Не переносить локальный development identity и тестовую БД на публичный сервер.
