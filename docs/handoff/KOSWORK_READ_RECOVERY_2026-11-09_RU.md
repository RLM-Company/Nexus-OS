# Koswork: предупреждения после восстановления чтения

Списки Work и планов записывали ошибки фонового чтения в одно состояние с ошибками
команд владельца. Успешный последующий опрос не очищал сообщение о недоступности;
безусловная очистка общего состояния, в свою очередь, скрыла бы неудачную команду.

Ошибки фонового чтения теперь хранятся отдельно. Только принятый актуальный снимок
очищает предупреждение чтения: сохраняются проверки abort, epoch и блокировки
внесения изменений. Ошибки команд, ссылок и валидации остаются в прежнем состоянии
и имеют приоритет в том же существующем блоке предупреждения. Ни успешный опрос,
ни следующий сетевой сбой их не перезаписывают. Новых элементов или стилей нет.

## Проверка

Браузерный сценарий с реальными HTTP/SQLite:

1. Показать рабочие данные, затем вернуть HTTP 503 при чтении обоих списков.
2. Восстановить чтение без изменения версии работы: оба сетевых предупреждения исчезают.
3. Отклонить переименование плана: ошибка команды сохраняется после успешных опросов.
4. Повторить сбой чтения и восстановление: ошибка команды остаётся, предупреждение
   независимой панели Work появляется и очищается.

Регрессионный тест до исправления подтверждал оставшееся предупреждение после
восстановления. Существующие сценарии выполнения, потерянного подтверждения,
версий файлов, памяти и скрытия вкладки проверяются вместе с новым сценарием.
Команды не повторяются автоматически, API и их права не меняются. Модель,
устройство владельца и VPS не используются.
