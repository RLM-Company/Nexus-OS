# Koswork: чтение прогресса по версии работы

Панель `WorkManagerProgress` перечитывала runtime с точками сохранения и версиями
файлов каждые две секунды, даже когда родитель уже передал ту же неизменившуюся
версию работы. Успешное чтение больше не запускает этот постоянный таймер.
Первоначальный снимок и новая принятая родителем версия вызывают чтение; текущий
опрос списка работ родителем сохраняется, поэтому обновления выполнения приходят
прежним путём. Разметка, стили, кнопки и боковая панель не меняются.

Временная ошибка чтения повторяется с задержкой 2–30 секунд. После успеха повтор
останавливается, предупреждение очищается. В скрытой вкладке новые runtime-чтения
не начинаются. Возвращение вкладки, фокус окна и событие восстановления сети
запрашивают актуальный снимок сразу; одновременно выполняется только одно чтение.
Запущенное до скрытия чтение может завершиться. При смене версии/работы или
размонтировании сохраняются отмена запроса и очистка таймеров/обработчиков.

Это оптимизация чтения состояния, а не расходов токенов модели и не остановка
всех сетевых запросов приложения. Фоновые задачи агента не приостанавливаются,
новый запуск модели, разрешения или подтверждение действий не создаются.

## Проверки

Chromium с реальными UI, HTTP/SQLite и тестовым ModelGateway:

- неизменившийся завершённый снимок не перечитывается после продвижения часов;
- временный HTTP 503 восстанавливается без новой версии работы, без дальнейшего опроса после успеха;
- подтверждение плана меняет версию и обновляет видимый прогресс;
- при смоделированной скрытой вкладке изменённая работа загружается после возвращения;
- повторные focus/online/visibility события не создают параллельных запросов.

Часы и visibility управляются тестом; это не приёмка окон установленного Windows
приложения или общий бенчмарк сервера. Остальные опросы интерфейса, серверная
выкладка и тестирование на ПК владельца не входят в этот блок.
