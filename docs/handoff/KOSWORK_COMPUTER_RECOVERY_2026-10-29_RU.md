# Koswork: локальные результаты и восстановление задач ПК

Дата: 29 октября 2026 года. База — `7d6be59bec41deda0bbb695be4266d9317178229`,
Draft PR [#411](https://github.com/RLM-Company/Nexus-OS/pull/411).
Ветка: `codex/koswork-computer-recovery-20261029`. Windows-кандидат: **0.13.0**.

## Утверждённый блок

Сохранять прогресс локальных задач, явно показывать неизвестный исход и позволять
восстановить задачу после сбоя с новым разрешением владельца. Выбранная рабочая
папка — отдельный блок Gemini; `desktop/windows/workspace/` не изменяется.
Веб-чат, сайдбар, логотип, серверная схема и модели не изменены.

## Что реализовано

- Локальный журнал в `userData/computer-tasks-v1/`, разделённый по подтверждённому
  владельцу и origin. Имя файла — SHA-256 области; владелец и origin проверяются
  также внутри шифротекста. В приложении используется Windows `safeStorage`, общий
  с существующим хранилищем текстовых черновиков; незашифрованного fallback нет.
- До 20 задач на область. При записи вытесняется самая старая завершённая запись;
  активные записи не вытесняются ради нового запуска. Каждая область ограничена
  1 МБ расшифрованного содержимого / 1,5 МБ файла. Это **не глобальная квота профиля**.
- Цель, проект, даты, состояние, номер и вид шага, стадия исполнения и идентификатор
  Gateway-запроса. Не сохраняются снимки экрана, UIA-дерево, ответ модели, итоговый
  текст, введённые строки, URL/пути из действий, grant, session token или разрешения.
  Цель сохраняется зашифрованной; для распознанных паролей, PIN и ключей цель
  вообще не сохраняется, восстановление по ней недоступно. Этот фильтр эвристический:
  он не гарантирует обнаружение произвольно записанного секрета. Владелец вводит
  пароли непосредственно в приложении во время человеческой паузы.
- Синхронная запись во временный файл с `fsync` и переименованием **до** передачи
  команды нативному исполнителю. Ошибка журнала прекращает управление; при
  неопределённом результате требуется перезапуск исполнителя. Это защита от
  прерывания процесса; полная стойкость к потере питания/сбою файловой системы
  отдельно не подтверждена.
- Нативная консоль показывает задачи и шаги, позволяет восстановить прерванную
  задачу, принять результат завершённой или явно удалить локальную историю.
  Новые IPC доступны только точному главному фрейму пакетной локальной страницы.
  Разрешение на управление и экстренная остановка остаются нативными.

## Значение стадий

| Стадия         | Что установлено                                                                                      |
| -------------- | ---------------------------------------------------------------------------------------------------- |
| `planned`      | Предложение записано, нативная передача ещё не начиналась                                            |
| `not_executed` | Шаг не выполнялся: решение модели, подтверждение с перепланированием или известный отказ до ввода    |
| `dispatching`  | Передача исполнителю начата; после сбоя исход может быть неизвестен                                  |
| `requested`    | Исполнитель подтвердил команду; полезный результат ещё не проверен                                   |
| `observed`     | После команды получен новый снимок; это не доказательство сохранённого файла/отправленного сообщения |

`completed` означает, что **модель сообщила о завершении**. Отдельная отметка
`acceptedAt` появляется только после нажатия владельцем «Результат проверен мной».
Автоматической семантической проверки документа или доставки сообщения этот блок
не добавляет. При ошибке остановки helper задача записывается как неуспешная.

## Восстановление

1. После нового запуска процесса оставшиеся `running`/`paused` считаются прерванными.
   Старое разрешение и старый сеанс никогда не восстанавливаются.
2. Нажатие «Восстановить» передаёт только ID. Main-процесс получает оригинальную цель
   и проект из той же области, заново проверяет владельца и сервер.
3. Требуются новое нативное согласие и **новый серверный сеанс**. Первая команда
   модели строится по свежему наблюдению и краткому описанию стадий прежних шагов;
   в описание не попадают исполняемые действия и прежние разрешения.
4. Если прошлая попытка могла изменить данные, открытие приложений/сайтов/файлов,
   клики, перетаскивание, текст и клавиши требуют отдельного нативного подтверждения
   с новым наблюдением и перепланированием. Флаг сохраняется и при повторных
   восстановлениях. Наблюдение, поиск приложений, фокус, наведение, прокрутка и
   ожидание могут использоваться для осмотра. Это консервативная проверка владельцем,
   **не гарантия автоматического распознавания дублей**.
5. Модель не получает старые команды для автоматического воспроизведения. При
   сомнениях ей предписано проверить существующий результат или спросить владельца.
   Автоматического восстановления при запуске приложения нет.

Обычная ручная пауза входа внутри действующего сеанса также сбрасывает ранее
выданное разовое подтверждение действия.

## Приватность и удаление

Локальная история не входит в серверный экспорт данных. Перед чтением/восстановлением
проверяется существующий `/api/v1/personal-settings/privacy`: неактивный lifecycle
блокирует доступ; наблюдаемое `deleted` удаляет текущую локальную область.
Сервер отдельно проверяет свои запреты на каждом модельном запросе/разрешении действия.
Без подтверждённого аккаунта и доступного API история в консоли не раскрывается.

Выход из аккаунта и смена сервера очищают историю вместе с локальными черновиками.
Есть отдельная кнопка очистки текущей области с нативным подтверждением.
Обычный сетевой сбой/истечение входа её не стирает. Записи старше 30 дней исключаются
при чтении и физически удаляются при следующей записи этой области или явной очистке;
это не фоновая зачистка выключенного устройства. При удалении аккаунта на другом
устройстве локальный офлайн-профиль не может быть удалён сервером мгновенно.
Повреждённый/подменённый/слишком большой файл не перезаписывается молча: управление
останавливается, нужна явная очистка. Хранилище рассчитано на один desktop-процесс,
не является защитой от вредоносного процесса с правами того же Windows-пользователя.

## Проверки и границы приёмки

Локально: `pnpm --dir desktop/windows check` (112 тестов),
`pnpm --dir desktop/windows verify:unsigned`, `pnpm check:secrets`, форматирование
изменённых файлов и `git diff --check`. Проверены шифрование/изоляция, повреждение,
лимиты/старение, остановка до ввода, сбой после ввода, смена владельца, очистка при
остановке, повторное восстановление, одобрение результата и граница native IPC.
Renderer проверен на искусственном DOM, без запуска приложений владельца.

Все тестовые профили — временные; модель, экран и исполнитель в тестах подставные.
Число тестов не является числом выполненных пользовательских задач.
Обновления по-прежнему выключены, кандидат unsigned, установки нет.
VPS, платные AI-запросы, мышь/клавиатура владельца и живой тест Kosmora → Word/Telegram
**не запускались**. Реальная связка API + модель + установленный Windows-клиент и
сценарий восстановления ещё требуют отдельной живой приёмки после восстановления сервера.
