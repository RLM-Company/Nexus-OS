# Повторяемые сценарии Koswork — 2 ноября 2026

Сценарий сохраняет последовательность шагов и запускается с новыми параметрами через существующий исполнитель Work. Это рабочая вертикаль для создания документов и текстовых материалов. Управление ПК, браузерные действия, расписания и рекурсивный запуск сценариев в этот блок не входят. Неизвестные требования к инструментам возвращают `WORKFLOW_TOOL_UNAVAILABLE` до создания плана.

## Пользовательский путь

В существующем разделе плана проекта раскрыть «Сценарии Koswork». Создать определение или выбрать один из трёх шаблонов: отчёт по документу, текст в рабочие материалы, анализ источника с итоговой запиской. Параметры: текст, число, логическое значение, вариант из списка, документ текущего проекта, ссылка. Ссылка передаётся как справочная строка; загрузки её содержимого не происходит.

Редактор поддерживает шаги, зависимости, проверку Критиком и перестановку шагов. Изменение создаёт новую неизменяемую версию. Старую версию можно открыть и сохранить следующей редакцией. Доступны копирование, архивирование, восстановление и перенос определений JSON-файлом.

По умолчанию кнопка только подготавливает план: запросов модели нет. Флажок немедленного выполнения прямо обозначает расход токенов. Управление, подтверждения и возобновление остаются в существующем плане. История показывает версию, исходные значения, состояние и ZIP готовых результатов.

## Данные и выполнение

- Миграция `0062_reusable_workflows.sql`: определения, версии, запуски; ключи владельца/проекта, ограничения, индексы и SQL-защита от изменения истории.
- Создание определения имеет `client_creation_id`; повтор того же запроса не создаёт копию. Изменение использует проверку ожидаемой версии.
- Запуск имеет отдельный `client_request_id`. В одной транзакции фиксируются определение, параметры, материалы проекта, исходный текст выбранных файлов и бюджет шагов; создаётся настоящий Work DAG. Потерянный ответ можно повторить с прежним идентификатором даже после изменения определения.
- Повтор с тем же идентификатором и другим содержимым отклоняется. Ошибка инструмента или файла откатывает и создание плана, и активацию черновика проекта.
- Передача параметров однократная: текст параметра не становится новым шаблоном подстановки. Это не гарантия отсутствия prompt injection; инструменты и разрешения всё равно контролирует существующий исполнитель.
- Для файлов проверяются текущие владелец, проект, готовность и непустой текст. TXT/CSV используют исходный UTF-8; для прочих форматов явно помечены индексированные выдержки с возможным перекрытием. Слишком большие материалы отклоняются целиком.
- В переносимый пакет входят только поля определения. Значения параметров, история, разрешения, подключённые аккаунты и серверный контекст выполнения не экспортируются.
- Экспорт и удаление данных владельца включают определения, версии и запуски. Новые записи блокируются глобальным состоянием удаления и Work-fence.
- В закрытой панели нет опроса. Открытая панель обновляет компактные статусы без повторной передачи всех материалов; запросы не пересекаются и отменяются при уходе.

Ограничения текущей вертикали: пакет до 64 000 UTF-8 байт, до 32 параметров/шагов, до 100 определений на проект и 200 версий определения; действуют прежние лимиты DAG и вложений. Бюджет одного шага фиксируется сервером по текущему профилю модели, максимум на три запроса. Квоты владельца и аварийная остановка продолжают действовать. Перезапуск API не возобновляет расход токенов автоматически.

## HTTP

База: `/api/v1/projects/:projectId/workflows`.

| Метод      | Путь                  | Назначение                                            |
| ---------- | --------------------- | ----------------------------------------------------- |
| GET / POST | база                  | Определения и шаблоны / идемпотентное создание        |
| PUT        | `/:id`                | Изменение с `expected_version`                        |
| POST       | `/:id/archive`        | Архивирование или восстановление                      |
| GET        | `/:id/versions`       | История определений                                   |
| GET        | `/:id/package`        | Переносимый JSON                                      |
| POST       | `/import`             | Импорт `{client_creation_id, package}` без выполнения |
| POST       | `/:id/runs`           | Подготовка или явный запуск плана                     |
| GET        | `/:id/runs`           | История со снимками входных данных                    |
| GET        | `/:id/runs?summary=1` | Только идентификаторы и компактное состояние планов   |

## Проверка и статус

Локально проверены контракты (4), хранилище (6), новый HTTP/исполнитель/приватность (3), регрессия Work DAG (40) и два браузерных пути. Браузерные и серверные проверки используют тестовый адаптер, настоящий HTTP, SQLite, исполнитель и скачиваемые ZIP; это не проверка качества ответов платного провайдера. Отдельно проходят TypeScript и ESLint изменённых исходников.

Браузер: `pnpm --filter @cosmora/web exec playwright test --config=playwright.workflows.config.ts`. Тестовый API/интерфейс используют изолированные порты 3346/3347, отдельную базу и очищенное окружение провайдера.
