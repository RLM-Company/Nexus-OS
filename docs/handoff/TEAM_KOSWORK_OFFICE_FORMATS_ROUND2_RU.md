# Рабочие документы Koswork — понятный конфликт версии и полные сценарии

Владелец реализации: Разработчик + GPT. Репозиторий: RLM-Company/Nexus-OS.
Фактическая база: `e6736e0ba87b1db0c1460f002dbbe2e4a42d2932` (актуальный main на 25 ноября 2026).
Ветка: `developer/koswork-office-formats-round2`. Merge/deploy не выполнялись.

## Что было

Office-модуль уже реализовывал адресуемые правки DOCX/XLSX/PPTX, версии/хеши,
preview, подтверждение копии, readback, а также структурированный ответ API
`409 {error:{code:"VERSION_CONFLICT"}}`. 48 нативных Office-тестов проходили.

Пробел: веб-редактор превращал 409 в общее сообщение «Откройте файл заново»
без действия. Пользователь не получал понятного выбора продолжения, хотя план
правок оставался в состоянии. Для запрошенных трёх форматов не было одного
воспроизводимого сквозного сценария «создать → повторно открыть → исправить
созданный файл → проверить чтением» в существующем пользовательском входе.

## Что работает теперь

- При конфликте версии (`VERSION_CONFLICT`) или устаревшем подтверждении
  (`PREVIEW_EXPIRED`) веб-редактор различает код ошибки и показывает понятное
  сообщение. Для конфликта версии доступна группа «Конфликт версии: выбор
  продолжения» с двумя явными действиями:
  - «Переоткрыть файл и сохранить план» — повторно открывает выбранный снимок
    байтов на актуальной версии, сохраняя накопленный план правок;
  - «Отменить правки» — отменяет операцию и очищает устаревший план.
- Сообщение об устаревшем preview явно говорит, что план не изменён и нужно
  заново «Посмотреть изменения».
- Ни один из путей не перезаписывает исходник и не создаёт ссылку на скачивание
  без проверенной копии. Изменения — только в Office-owned web-файле; общие
  контракты, маршруты, миграции и настройки прав не тронуты.

## Воспроизводимые сценарии по форматам

Сквозной прогон через существующий native workspace service (.fixture, без
провайдера/модели) запускается командой из корня чистого checkout:

```sh
node desktop/windows/test/fixtures/run-office-edit-brief.cjs docs/handoff/fixtures/koswork-office-formats-round2
```

Сценарий для каждого формата: создать исходник → открыть (
`inspectOfficeDocument`) → подготовить план → preview → подтвердить копию →
прочитать сохранённый файл (`extractOfficeText`) → сверить обязательные литералы
(`19 700`, `00123`, `07.11.2026`, «кроме доставки»), версии, SHA и неизменность
исходника. Результат — `work/office-formats-round2/results.json` и
`*.readback.json`.

Повторное открытие уже созданной копии и её повторная правка покрыты web e2e в
`apps/web/e2e/office-workspace.spec.ts`: сценарий Drive save → restore →
переоткрытие копии (`officeRestore`) → новая правка и проверка байтов.

Конфликт версии с выбором продолжения воспроизводится e2e-перехватом ответа
preview: `409 {error:{code:"VERSION_CONFLICT"}}`. Проверяются оба действия,
сохранение/очистка плана и отсутствие download до подтверждения.

## Ограничения

Выбранный файл остаётся снимком байтов: веб-редактор не следит за изменением
оригинала на диске после выбора. «Переоткрыть файл» перечитывает этот снимок на
актуальной версии серверного разбора, а не читает диск заново. Визуальный рендер и
Microsoft Office не проверялись; HY4/платные вызовы не использовались. VPS и ПК
владельца не затрагивались. Общий экран сдачи и любые общие контракты остаются
за интегратором.
