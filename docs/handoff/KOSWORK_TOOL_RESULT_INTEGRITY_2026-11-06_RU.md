# Koswork: большие результаты инструментов

Следующий блок после чтения страниц. Ранее `ComputerSession` выполнял
`JSON.stringify(response).slice(0, 16000)`. Для большого результата это могло
создать невалидный JSON без отметки сокращения и разделить Unicode-символ.

Обычная квитанция до 16 000 сериализованных UTF-8 байт сохраняется точно.
Больший результат превращается в отдельный JSON-envelope с `excerpt_only`,
исходной длиной, видом действия и префиксом сериализованного результата.
Полный envelope ограничен 10 000 UTF-8 байтами. Повторно используется существующий
`fitDocumentExcerpt`; отдельный курсор не возвращается, поскольку transient
результат нельзя получить заново безопасным повтором произвольного действия.

Фиксированное пояснение явно говорит: драйвер уже вернул ответ, внешнее действие
могло иметь эффект, префикс может быть незавершённым JSON. Для недостающих данных
нужно проверить текущее состояние чтением или спросить владельца; нельзя повторять
изменение/отправку, додумывать числа или хеши. Это информация для планирования,
не автоматическая гарантия поведения модели или доказательство внешнего эффекта.

Порядок журнала неизвестных эффектов, однократная авторизация, права и бюджеты не
меняются. Невозможно сериализовать результат — сессия останавливается по прежней
границе неопределённости; успешное выполнение не выдумывается. Новых хранилищ нет.

Проверки: обычная квитанция с версиями/числами сохранена побайтно; большие CJK,
emoji и JSON-экранирование дают валидный bounded envelope с точным префиксом.
Реальный ComputerSession получает большой результат от fixture-драйвера и
передаёт его дальше как валидную выдержку, действие выполнено ровно один раз.
Платной модели и управления рабочим столом нет. Windows-кандидат 0.21.1;
VPS, установка владельцу, дизайн и живая приёмка остаются отдельно.
