# Drive: выбор результатов и совместимые снимки

Поставка от 8 ноября 2026 года. База: `338536ee5946f96dcd18768143cc41af998c476a`.
Первый кандидат подготовлен прямым API-подрядчиком HY4; Codex независимо проверил,
исправил регрессии, ограничения размера и интегрировал клиентский путь.

## Пользовательский результат

В существующих настройках Drive можно выбрать отдельные локальные результаты Work,
увидеть их проект, версию и размер и сохранить только отмеченные файлы вместе с
выбранными чатами. При изменении версии выбранного результата возвращается конфликт;
новое содержимое не подставляется молча. Ссылка открывает только уже подготовленную
папку Kosmora, без перечисления всего Google Drive.

Старый `GET /sources.items` сохранён. Новые клиенты включают индивидуальный выбор
только при `file_selection=true`; старый сервер продолжает работать с прежним UI.
Запрос без `file_ids` сохраняет старое значение `include_results=true`: опубликованные
и завершённые legacy Work результаты без дублирования. Явные `file_ids` входят в
идентичность операции; прежние хеши не изменены.

## Исправления проверки кандидата

- Файлы, не включённые в снимок, не читаются и не проверяются на контрольную сумму.
  Копия только чатов не падает из-за исключённого повреждённого результата.
- Предварительно проверяются метаданные, число файлов/сообщений и общий объём,
  затем читаются выбранные тела. Код больше не материализует все файлы владельца.
- После предварительной проверки считывается точная строка выбранного источника
  с повторным сравнением версии/размера/контрольной суммы и привязкой к владельцу.
- Убрано полное повторное перечисление метаданных для каждого выбранного файла.
- Убраны повторное сложение размера файлов и ошибочная оценка, которые отклоняли
  корректные снимки больше16 МиБ при каноническом ограничении32 МиБ. Точный размер
  JSON по-прежнему ограничен32 МиБ; данные не обрезаются.
- Сохранены канонический формат снимка, шифрование временного payload, restore,
  owner fences и проверка удалённых байтов существующим транспортом.

Новые controls находятся только внутри настроек Drive. Чат, сайдбар, логотип,
палитра и глобальные стили не менялись. Новая копия остаётся отдельным архивом;
перезаписи исходных файлов на Drive и нового scheduler нет.

## Выполненные проверки

Команды из корня репозитория:

```powershell
pnpm --filter @cosmora/api exec vitest run test/google-drive-snapshots.test.ts --maxWorkers=2
pnpm --filter @cosmora/api exec vitest run test/google-drive-store.test.ts test/google-drive-storage.test.ts test/google-drive-connection.test.ts test/google-drive-backups.test.ts test/google-drive-authorization.test.ts --maxWorkers=2
$env:KOSMORA_E2E_PRODUCTION='1'
pnpm --filter @cosmora/web exec playwright test e2e/google-drive-settings.spec.ts --workers=1
pnpm --filter @cosmora/contracts build
pnpm --filter @cosmora/api typecheck
pnpm --filter @cosmora/web typecheck
pnpm --filter @cosmora/web lint
pnpm check:secrets
git diff --check
```

Результаты:22 snapshot-теста,83 проверки соседних модулей и6 Chromium-сценариев
на production-сборке прошли. Проверки типов API/web, сборка contracts/web, линтер,
форматирование изменённых файлов и поиск секретов прошли. Скриншот выбора файлов
проверен визуально. Непосредственно после первой API-поставки неизменённая исходная
suite обнаружила регрессию legacy Work; дополнительная независимая проверка выявила
чтение исключённых файлов. После исправлений исходная suite тоже прошла; её дубликат
не включён в репозиторий, полезные дополнительные регрессии перенесены в основную.

В первом браузерном запуске обнаружен отсутствующий публичный экспорт нового типа;
экспорт исправлен, повторная сборка и все6 сценариев прошли. Эти результаты получил
Codex, а не API-модель без терминала. Проверки используют реальные SQLite/архивные
байты и программируемый Google transport; OAuth и удалённое хранилище Google
заменены явными fixtures. Пользовательские данные и аккаунт Google не использовались.

## Граница поставки и дальнейшая работа

Это законченный выбор источников и исправление снимков, а не объявление всего блока
Drive завершённым. Отдельно остаются live Google OAuth/backup/restore с разрешённым
аккаунтом, полный разбор постоянного отзыва гранта/refresh ошибок и оставшиеся
сценарии recovery/backoff. Существующая очередь и запрет слепого создания нового
ID при неизвестном исходе сохранены, новая фоновая синхронизация не заявляется.

Production не обновлялся. Для этой поставки миграции и новые зависимости не нужны.
При штатной выкладке обновить API и web совместно; новые controls защищены capability
флагом. Откат — предыдущие API/web образы. Канонический snapshot v1 и прежние данные
не менялись; временный код выбора не выдаёт новых OAuth/device grants.
