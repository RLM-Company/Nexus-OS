# Koswork: большие текстовые файлы и переход к найденному месту

Следующий блок согласованной очереди контекста и source pagination. Раньше
`workspace_read` был ограничен небольшим полным файлом, а `workspace_read_lines`
возвращал целые строки. Длинная строка JSON/CSV/исходника могла не поместиться
даже при запросе одной строки. Поиск находил условие, но не давал прочитать его
контекст как полноценную версионированную выдержку.

## Реализация

Новый `workspace_read_text(path,offset_utf16,expected_version)` использует
существующий `readTextFile`, тот же bounded file snapshot, strict UTF-8 decoder,
проверку пути/владельца/гранта и `fitDocumentExcerpt`. Второго файлового читателя,
кеша, хранилища или внешней зависимости нет. Старый `workspace_read` и чтение
целых строк сохраняют поведение и лимиты.

Источник ограничен 2 MiB; крупнее — отказ, не скрытое сокращение. Одна часть с
метаданными укладывается в 10 000 сериализованных UTF-8 байт. Внутренний предел
части — 6000 UTF-16 единиц, при необходимости меньше по wire budget. Граница
не разделяет surrogate pair. Версия/SHA256 относятся к исходным байтам; отдельный
text_sha256 — к декодированному тексту. Начальный UTF-8 BOM удаляется как в прежнем
decoder, `bom_stripped` сообщает об этом. Курсоры относятся к тексту без BOM,
остальные пробелы и смешанные CRLF/CR/LF сохраняются.

Начало с нуля может использовать null-версию. Продолжение или переход в середину
требуют точной версии. Изменившийся файл, позиция вне текста или внутри Unicode-
символа отклоняются. `excerpt_only`/`next_offset` обозначают часть, не целый
JSON/CSV record или всю программу. Модель получает фиксированное пояснение:
не придумывать пропуски и не заменять целый файл содержимым выдержки.

Поиск по рабочей папке дополнен точными `offset_utf16` и `match_end_utf16` в
декодированном тексте. Они учитывают реальные окончания строк и Unicode. Агент
может передать найденные path/version/offset прямо reader и получить контекст
одним чтением, без последовательного прохода через весь префикс. Поиск по-прежнему
возвращает первое совпадение в строке, с прежними лимитами файлов/результатов.

## Права и совместимость

Согласование: API `supports_workspace_text_reads=true` + native `supportsTextReads`
для текущей выбранной папки → `observation.workspace.read_text_pages=true`.
Старый сервер не получает нового поля; неподдержанный инструмент отклоняется
как API, так и native boundary. Без выбранной обычной рабочей папки capability
не появляется. Vault-only mount использует прежние opaque paths/reader;
новый инструмент не открывает виртуальное хранилище или произвольные файлы.

Нет shell/code execution или новых браузерных/PC permissions. Чтение использует
существующий folder grant; отзыв, смена владельца/источника, symlink/hardlink,
чувствительные имена, бинарные/повреждённые UTF-8 данные и отмена сохраняют
действующие ограничения. Обязательный источник при конфликте не заменяется
догадкой или чужим файлом. На диск не записывается новая копия текста.

## Проверки и границы

- Реальные временные файлы: восстановление из частей, UTF-8/JSON byte budget,
  BOM, смешанные окончания строк, CJK/emoji/экранирование, source/text hashes.
- Курсоры, плохие версии, изменение файла, превышение 2 MiB, бинарные данные,
  выход из папки, ссылки, отмена и отзыв доступа отклоняются.
- Настоящие Work driver/ComputerSession/workspace: 8 шагов, поиск после 24 000
  символов → чтение по offset/version → подтверждённая запись → обратное чтение.
  `00123`, `19 700 ₽` и «кроме доставки» сохранены; source не меняется,
  browser/PC grants отсутствуют. Planner — сценарная фикстура.
- API/native capability negotiation исключает старые стороны; API не принимает
  unversioned continuation. Платные модели не вызываются.
- Windows packaged acceptance дополнен тем же файловым циклом в реальном
  Electron/ASAR с выбранной CI-папкой, AES-GCM codec и проверкой изменения файла.
  Это работает только в прежнем disposable-runner acceptance режиме.

Кандидат Windows 0.22.0. Прогон CI и точные числа фиксируются в PR/операторском
отчёте. VPS и клиент владельца не обновляются, дизайн не меняется. Это не
измерение качества живой модели и не заявление о готовности всего Koswork.
Файлы >2 MiB, автоматическое понимание целого JSON/CSV по одной части и
модификация большого файла частичным overwrite не заявляются.
