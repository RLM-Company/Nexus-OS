# Koswork: выбранная работа за пределами окна истории

История Work возвращает не больше 80 записей с приоритетом незавершённых задач.
Если явно выбранная работа выпадала из этого окна, панель сбрасывала выбор и
открывала первую запись. Кнопки управления после этого относились к другой работе.

Панель теперь читает явно выбранную работу по её ID, если её нет в ответе списка.
В существующей истории сохраняется дополнительная выбранная строка: максимум
80 записей списка плюс одна выбранная, без расширения серверного запроса.
Версионные, epoch, abort и mutation-lock проверки остаются. Когда работа есть
в списке, дополнительного GET нет. Сбой точечного чтения оставляет последний
снимок с существующим предупреждением; другую задачу панель не выбирает.

## Приёмка

Браузерный тест создаёт две настоящие задачи с синтетической моделью в локальном
API/SQLite и ожидает подтверждения планов. Подмена только ответа списка имитирует
уход выбранной работы за его ограниченное окно. Проверяется:

1. Выбранная строка остаётся выбранной, точечный GET читает исходную задачу.
2. HTTP 503 точечного чтения показывает предупреждение без смены выбора.
3. После восстановления предупреждение исчезает.
4. Подтверждение плана отправляется исходной задаче; вторая остаётся неподтверждённой.

До исправления тест фиксировал отсутствие точечного GET, а снимок интерфейса
показывал выбранной вторую задачу. Тест не заявляет создание 81 работы: границу
окна моделирует управляемая фильтрация реального ответа списка.

Не добавляются автоматические команды, новые права, API, стили или навигация.
Чтение по ID использует существующую проверку владельца и проекта. Недоступная
запись не объявляется удалённой по одному сбою. Обработка ошибок команд остаётся
отдельной. VPS, платная модель и приёмка на основном устройстве не используются.
