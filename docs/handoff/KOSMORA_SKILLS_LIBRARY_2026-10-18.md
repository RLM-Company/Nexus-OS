# Kosmora: библиотека Skills с проверкой импорта и версий

База: PR361, `fb90037883f7362e932e638937c789f554cd7e60`.

## Возможности

- Импорт JSON сначала выполняется локально: проверяются форма, 64 000 UTF-8 байт,
  лимиты полей, отсутствие разрешений и SHA-256 исходного пакета. Показан полный
  текст после той же обрезки краевых пробелов, что выполняет сервер. Только
  явная отметка о просмотре открывает кнопку создания новой копии. Проверка хеша
  означает целостность, а не авторство. Сервер повторно проверяет пакет.
- Отмена чтения/импорта и выбор нового файла инвалидируют поздний результат.
  Выбор файла не пишет на сервер, не подключает Skill к чату/Work и не исполняет
  инструкцию. Пакеты с чужими owner/version/permission-полями отклоняются.
- Поиск библиотеки по названиям и кратким описаниям, без изменения порядка.
- Копирование текущего Skill создаёт независимый локальный черновик, включая
  несохранённые правки. Новый ID создаётся только кнопкой сохранения. История и
  подключения исходного Skill не копируются. Источник не изменяется.
- Пакет можно скачать отдельно из текущего валидного черновика, сохранённой
  актуальной версии либо выбранной исторической версии. Формат остаётся
  совместимым с существующим сервером. Экспорт черновика нормализует краевые
  пробелы и требует заполненных валидных полей.
- Сравнение старой версии с открытым черновиком показывает все три поля целиком,
  включая пробелы и переводы строк. Подтверждение связано с ID, текущей версией,
  точным черновиком и исходной исторической версией. Любая правка требует нового
  просмотра. Восстановление создаёт следующую версию с expected_version; уже
  закреплённые версии в чатах и Work не меняются автоматически.

## Защита черновиков и ошибки связи

Переключение/новая инструкция/импорт/переход назад предупреждают о несохранённом
тексте. Выход или reload защищён стандартным beforeunload. Черновик хранится в
памяти вкладки: автоматического восстановления после закрытия нет.

Чтение/запись сериализованы синхронным lock, а поля и выбор инструкции заблокированы
на время операции. Поздние ответы после ухода со страницы не применяются.
Конфликт версий оставляет черновик для скачивания или независимой копии.

После неоднозначного PUT/restore выполняется один GET без повторения записи.
Подтверждение возможно только для того же ID, ровно следующей версии и полного
совпадения нормализованного текста. Чужой/более новый результат и ошибка чтения
оставляют исходную ошибку. Успешный ответ записи также сверяется чтением.

Создание/импорт сервером пока не идемпотентны. Поэтому потерянный ответ не вызывает
автоматического повторного POST: создание в этой вкладке блокируется, список
обновляется для проверки. Если ID успел вернуться, доступно повторное чтение
именно созданной инструкции. Иначе новое создание требует явной проверки списка.
Эта защита локальна вкладке и не заменяет серверные receipts; после reload нужно
самостоятельно проверить наличие предыдущей копии.

## Проверки

- Все 139 web unit cases прошли, включая 14 новых проверок пакета, нормализации,
  буквального HTML, сравнения, readback и запрета обхода lifecycle/permission errors.
- 35 профильных backend/interop cases прошли: owner Skills, закрепления chat/Work,
  совместимость browser/server SHA-256 и переносимого пакета.
- Web, API, interop и selected E2E TypeScript; scoped ESLint и Prettier: прошли.
- Production Next webpack build: 19 routes, прошёл.
- Добавлены пять Playwright-сценариев (импорт, копия, restore, конфликт, потерянное
  создание); с тремя существующими preview-сценариями обнаружено восемь. Типы
  проверены. Browser execution не подтверждён: Chromium в этой среде отсутствует;
  последняя стандартная установка дала повреждённый ZIP. Результаты PR360 не
  считаются приёмкой новых интерфейсных изменений.

Новых зависимостей, миграций и серверных runtime-изменений нет. Модель, бюджет,
разрешения и privacy adapters не менялись. Paid AI, deployment и main merge не
выполнялись. Hosted CI pass не заявляется.
