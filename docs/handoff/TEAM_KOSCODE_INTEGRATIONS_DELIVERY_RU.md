# Koscode, GitHub и Drive

База `815b8f95359bc23744a0d237078dc8088f7b42c0`. Ветка `team/koscode-integrations-delivery`. В базе уже слиты #581 и #603. Поставка в [Draft PR #609](https://github.com/RLM-Company/Nexus-OS/pull/609).

- Koscode загружает список веток подключённого репозитория по запросу. Первая страница дополняет ручной ввод. Выбор файлов для чтения ограничен действующим контрактом репозитория. После создания задачи или выбора в истории URL сохраняет проект и задачу. При обновлении страницы открывается эта задача. Если обычное обновление, явная загрузка или опрос вернут другую задачу, ответ будет отклонён. Локальные правки при конфликте ведут себя по контракту #581. Подтверждённый уход без сохранения сбрасывает редактор.
- GitHub проверяется существующим сценарием API и адаптера. Задача получает реальные байты из временного Git-репозитория, делает проверку в OCI и сверяет патч с индексом Git. В отдельном сценарии потерянный ответ на создание PR восстанавливается чтением статуса, число внешних POST не растёт. История задачи показывает события и ссылку на черновик.
- Drive по явному запросу повторно проверяет метаданные папки, в том числе после прежнего успеха. Ошибки отзыва OAuth и отсутствия доступа различаются. Проверочный адаптер возвращает 401 и 403, при этом новых папок и архивов не создаётся. Сценарий выбора сохраняет один разрешённый файл, проверяет запись в журнале, скачивает восстановленные байты и сохраняет их в материалы проекта через действующий API. После отключения новая операция отвергается, локальный материал и журнал сохраняются.

Запуск из корня с установленными зависимостями.

```sh
pnpm --filter @cosmora/api exec vitest run test/code-agent.test.ts test/github-integration.test.ts test/google-drive-{connection,snapshots,storage,store,authorization,backups}.test.ts --maxWorkers=1
pnpm --filter @cosmora/web exec playwright test e2e/code-agent.spec.ts e2e/google-drive-settings.spec.ts
```

На текущих исходниках локально прошли 242 API-теста, один OCI opt-in пропущен. После расширения Drive-проверки отдельно прошли все 29 тестов файла `google-drive-snapshots.test.ts`. Первый запуск API на старых связанных workspace-пакетах упал из-за отсутствующего ConnectorRegistry и несовместимых схем. Рабочие ссылки перенастроены на исходники этой ветки. Локальный браузерный стенд ограничен диском и зависимостями старой копии. Результаты полной проверки публикуются в PR.

Живая проверка GitHub возможна на подготовленной тестовой ветке при разрешении владельца. Сценарий жёстко привязан к синтетической ветке и её исходному SHA. `GH_TOKEN` и `CODE_AGENT_TEST_IMAGE` задаются оператором в окружении. Каталог отчёта должен быть новым.

```sh
COSCODE_LIVE_GITHUB_APPROVE=RLM-Company/Nexus-OS:ops/coscode-live-base-2026-11-12 \
COSCODE_LIVE_REPORT_DIR=/tmp/koscode-team-live-unique \
pnpm --filter @cosmora/api exec tsx test/code-agent-live-github.acceptance.ts
```

Для живого Drive на согласованном стенде открыть `/personal-settings#drive-storage`. Подключить тестовый Google-аккаунт, выбрать один синтетический результат из «Что сохранить», сохранить копию и проверить её запись в журнале. Открыть предпросмотр и восстановить копию, скачать TXT и добавить его через материалы тестового проекта, сверить содержимое. Отозвать разрешение в Google и нажать «Проверить подключение». Затем отключить Drive в Kosmora и проверить сохранённый журнал. Живой GitHub-путь и реальный Drive OAuth в этой поставке не запускались. Транспорт реестра #603 по-прежнему описательный.

Следующий срез каталога по согласованию с владельцем — карточка Google Drive с фактическим статусом и переходом в существующий выбор материалов. Для повторного использования файла предложить явную кнопку добавления поддерживаемого восстановленного текста в выбранный проект с подтверждением и проверкой версии материалов. Путь скачивания и ручной загрузки уже использует текущие разрешения.
