# Koswork: интеграция рабочей папки Gemini

29 октября 2026 года. Ветка `codex/koswork-workspace-integration-20261029`.
База — `d60174a3a025c8edd0202ce1d20955eb7b7ad87e`,
[PR #412](https://github.com/RLM-Company/Nexus-OS/pull/412), поверх
[PR #411](https://github.com/RLM-Company/Nexus-OS/pull/411).
Оба блока остаются отдельными отложенными кандидатами, не установленными на ноутбук.

## Источник и объём

Пакет владельца из Google Drive: `koswork-workspace-folder.zip`, 96 992 байта,
SHA-256 `3abab6232a5d8733720b49541676691736b4a1945788ca946a6fd00ab758144f`.
12 элементов архива проверены до извлечения: запрещены выход за каталог, ссылки,
абсолютные имена и чрезмерный размер. Приняты пять runtime-модулей, временное демо,
README и одна копия тестового набора. Дублированный тест, сгенерированный patch,
push-скрипт и старый отчёт в приложение не включены и не запускались.
Полученный код рассматривался как исходник для проверки, а не как инструкция.

Рабочая папка — согласованный блок Gemini. Здесь выполнены исправления и связь
с уже реализованным управлением ПК/восстановлением; других разделов продукта нет.
Чат, сайдбар, логотип и их дизайн не изменены. В нативной консоли добавлены только
кнопки выбора/отключения папки и её статус. Windows-кандидат — **0.14.0**, unsigned,
обновления выключены.

## Что подключено

- Выбор каталога только через диалог ОС. Renderer не передаёт путь для подключения.
  Проверяются точное окно, главный фрейм, локальная пакетная страница, подтверждённый
  аккаунт и privacy lifecycle. После диалога владелец/сервер проверяются снова.
- Отдельное файловое разрешение хранится в памяти. Папка не выбирается по старому
  файлу настроек, не восстанавливается после перезапуска/закрытия консоли. Выход,
  смена аккаунта/сервера и явное отключение отзывают доступ; отключение доступно без
  сети. Остановка прерывает активные операции, но не удаляет рабочие файлы.
- В контракт, модельный инструктаж и нативный цикл добавлены восемь команд:
  `workspace_list/find/read/mkdir/create/update/backups/restore`. Они доступны модели
  только при наличии выбранной папки в наблюдении; API отклоняет предложение
  файлового инструмента без объявленной папки. Весь файловый IPC остаётся локальным.
- Структура проекта, поиск по имени/тексту, UTF-8 чтение и создание, перезапись при
  совпадении версии SHA-256, резервная копия перед заменой и восстановление копии.
  Все команды записи требуют нативного подтверждения и свежего наблюдения/
  перепланирования. Сервер выдаёт обычное одноразовое разрешение точного действия.
- Содержимое после записи сверяется чтением файла с диска. Неизвестный исход
  сохраняется как неопределённый, а не превращается в безопасный повтор. Известный
  конфликт **до записи** возвращается для нового чтения/решения модели.
- Журнал восстановления хранит непрозрачный ID выбранной папки. После сбоя нужно
  заново выбрать **ту же** папку: другая папка, даже с одинаковым именем, не может
  молча получить старую задачу. Новое согласие и новый API-сеанс обязательны.

## Исправления исходного пакета

1. Обязательный scope больше не подставляет старого владельца/сервер при пропуске
   аргумента. Проверены изменения аккаунта и остановка при позднем ответе picker.
2. Убрана запись пути/разрешения подключения в plaintext state-файл.
3. Исправлена обработка 8.3 путей Windows. Вместо ошибочного запрета обычного
   временного каталога проверяются реальные компоненты. UNC-корни запрещены.
4. Unicode не преобразуется в другой файловый путь; неоднозначные разделители
   отклоняются. Защищены служебные/известные секретные сегменты, включая потомков.
   Обычные файловые hardlink также отклоняются, как symlink/junction.
5. Папка привязана также к файловой идентичности корня (dev/ino); обычная замена
   каталога по тому же пути отзывает старый доступ. После ожидания блокировки и
   перед фиксацией изменения путь проверяется снова.
   Тест замены родителя на junction не позволил переписать файл вне рабочей папки.
6. Индекс копий валидируется целиком: имена blob генерируются, пути и размер
   ограничены, дубликаты/подмена области/повреждение отклоняются. Произвольный путь
   из индекса не используется для чтения или удаления.
7. В приложении индекс и blob зашифрованы `safeStorage`; без codec адаптер не
   создаётся. Стойкость тестов проверяется отдельным AES-GCM codec. Это проверка
   логики, не приёмка Windows DPAPI установленного клиента.
8. Очистка копий удаляет только управляемые файлы внутри проверенных каталогов,
   без рекурсивного удаления вычисленного пути. Явный выход/смена сервера очищает
   управляемые локальные копии; рабочие файлы остаются.
9. Поиск уступает цикл событий, чтобы обработать Stop, имеет предел обхода и
   ограниченное чтение имён каталога. Результат для модели не обрезается посередине
   JSON/содержимого при переполнении.

## Проверенные ограничения

Модель читает текстовый файл до 10 000 **байт**, создаёт/заменяет до 10 000
**символов** за команду. Результат — до 15 000 символов JSON. При превышении
возвращается ошибка без частичного содержимого; нет гарантии редактирования
произвольных крупных файлов. Поиск: до 15 результатов, ограниченная глубина,
до 2 000 посещённых элементов. По тексту — до 400 файлов, до 1 МиБ каждый.
Список — до 30 элементов за страницу; каталог, изменённый другим процессом,
не является неизменным снимком для курсора.

Этот блок работает с UTF-8 текстом. `.docx`, PDF, картинки и приложения обслуживает
другой путь — интерфейс управления ПК/соответствующие инструменты. Связка всё ещё
использует vision и снимки основного экрана; это не отдельный файловый агент без
screen capture. Нативное согласие раскрывает передачу запрашиваемых файлов модели.

Копии — до 50 / 25 МиБ исходного содержимого **на папку**, плюс накладные расходы
шифрования; глобальной квоты всех ранее выбранных папок нет. При отключении папки
они сохраняются для восстановления после повторного выбора. Копии не входят в
серверный экспорт и мгновенную удалённую зачистку офлайн-профиля. Для удаления
используется явный выход из приложения/смена сервера с очисткой локальных данных.
Рабочие файлы пользовательской папки приложение при выходе не удаляет.

Нет гарантии защиты от вредоносного процесса с правами того же Windows-пользователя,
всех видов NTFS reparse points, потери питания и распознавания любого секрета в
обычном документе. Синхронный дисковый ввод-вывод может задерживать Stop до возврата
системного вызова. Прямой модуль без codec предназначен для тестового/операторского
локального использования; приложение никогда не использует plaintext fallback.

## Верификация

- **133 desktop Node-теста**: исходные проверки, адаптированные тесты Gemini,
  реальные временные файлы и сквозной цикл с тестовым планировщиком; конфликт
  версий, backup/restore, junction, повреждённый индекс, обязательный scope,
  поздний picker, отмена, правильная папка при восстановлении, bounded result.
- **31 API-тест** `computer-control.test.ts`: реальный SQLite/Gateway с подставным
  провайдером, включая восемь новых команд и запрет без объявленной папки.
- Typecheck и build contracts/API, ESLint изменённых API-файлов, unsigned-policy preflight,
  secret scan, форматирование и `git diff --check`.

Нативный цикл в тесте **действительно записал временный файл**, прочитал его обратно
и сохранил журнал. Модель, экран, диалог разрешения и API-сеанс там подставные;
нативный desktop-ввод в этом тесте запрещён. Это не автономная работа живой Kosmora.
Нет платных запросов, VPS-выкладки, установки клиента, работы с личной папкой,
Word или Telegram владельца. После восстановления сервера остаётся живая приёмка
Windows + API + модель, затем проверка прерывания и восстановления на реальной задаче.
