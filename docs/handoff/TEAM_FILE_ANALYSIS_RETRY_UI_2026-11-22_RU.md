# Повтор глубокого анализа: результаты проверки (этап 3)

Ветка `team/file-analysis-retry-ui`, база `main` `6fa5b0bc` (после PR #618).
Один Draft PR с кодом, результатами и ограничениями. Живые вызовы моделей и VPS
не использовались; все проверки — на локальных фикстурах.

## Что сделано по пунктам задачи

1. **Кнопка «Повторить анализ»** — рядом со статусом failed/cancelled глубокого
   прогона (`studio-files-library.tsx`, блок ответа): вызывает существующий
   `POST /api/v1/projects/:projectId/document-library/answers/:id/retry`, после
   202 новый run попадает в список и подключается к штатному polling через
   `setActiveAnswerId` (существующий effect 1200 ms). Исходная попытка остаётся
   в истории с диагностикой `error_code` и coverage.
2. **Защита повтора** — до POST в sessionStorage пишется маркер
   (`answer-retry.ts`, `cosmora:document-answer-retries:v1`, до 8 записей);
   `busy`/`retryPending`/`activeAnswerId` блокируют двойной клик в UI. При
   сетевом сбое маркер остаётся: следующим действием приложение **сначала**
   сверяет историю (`GET /answers`) и ищет уже принятый повтор; если сервер
   подтверждения не дал — показывает «исход запроса неизвестен» и требует
   **нового явного клика** перед любым повторным POST к модели.
3. **INCOMPLETE_COVERAGE** — теперь видны **все** строки coverage (разобрано,
   ошибки, не обработано), включая per-file «N из M фрагментов, ошибок: K» и
   страницы PDF с текстом; добавлено явное пояснение о прерванной обработке.
   Правила публикации и доступ не менялись: экспорт/Canvas остаются
   включёнными только при `status === "done"`, оригиналы показываются только
   для сохранённых source в рамках проекта.
4. **Chromium-проверка** — добавлен e2e `document-answer-retry.spec.ts` с тремя
   сценариями на локальных фикстурах: неполное покрытие → повтор → новый run →
   готовый отчёт с источниками; двойной клик (ровно 1 POST); потеря ответа и
   перезагрузка со сверкой истории; отдельно отменённый deep-run → повтор.

## Ограничения

- Локальный Chromium-запуск заблокирован этой Windows-средой: `playwright.config.ts`
  использует `pnpm` (нет в PATH), а прямой запуск упирается в расхождение
  exports `@cosmora/contracts` при resolution из src. Поэтому e2e выполняется
  в CI, а не локально; фикстуры полностью локальные.
- Живые/plated вызовы моделей, VPS и платные запросы — вне задачи.
- Ручной UI-приёмки на стенде владельца не было; статус live-приёмки этапа 1
  не менялся.
