# Собственная выдача Kosmora

Владелец уточнил 29 октября: при поиске пользователь должен видеть интерфейс
Kosmora, без перехода на страницу DuckDuckGo. DuckDuckGo остаётся источником
поисковых данных. Это изменение отдельного браузера Koswork; основной чат,
сайдбар и логотип веб-приложения не менялись.

## Поведение

Ввод адреса HTTP(S) открывает сайт. Обычный запрос до 240 символов открывает нашу
локальную страницу результатов: заголовок, домен источника, ссылка и выдержка.
Внешняя страница поисковика автоматически не открывается. Явно введённый адрес
duckduckgo.com, как и любой другой допустимый сайт, остаётся обычной навигацией.

Выдача получает до пяти источников через существующий серверный
`POST /api/v1/web-search`, с фиксированным `engine: "duckduckgo"`.
Сервер обращается только к разрешённому внутреннему origin SearXNG.
Предыдущие клиенты без `engine` сохраняют прежнее поведение. Новых ключей,
платных API, миграций и внешних сервисных аккаунтов патч не создаёт.

Это собственный интерфейс поиска поверх внешних данных, а не собственный индекс
интернета. Подключённый источник и условия его использования должны быть отражены
в документации/настройках продукта; скрытие чужой страницы не отменяет требований
поставщика данных.

При недоступном поиске остаётся наша страница с ошибкой. Нет выдуманной выдачи,
скрытого перехода на другой поисковик, автоматических повторов или обхода CAPTCHA.
Явная перезагрузка поисковой вкладки повторяет запрос. В памяти хранится последняя
выдача вкладки, без постоянной истории запросов. Полный журнал всех предыдущих
поисковых выдач и пагинация в этот проход не входят.

## Агент и изоляция

- Новый фиксированный инструмент `browser_search` получает только строку запроса.
  Агент видит реальный DOM выдачи и открывает источник по свежему ref.
- Результаты ограничиваются и проверяются повторно на клиенте. Ссылки — только
  HTTP(S), без паролей и повторов. Заголовки/выдержки вставляются через `textContent`;
  внешний HTML и скрипты не выполняются.
- Локальная страница не имеет preload, Node или разрешения на выполнение скриптов;
  её заполняет фиксированная функция приложения в изолированном мире Chromium.
  В модельное наблюдение не попадает файловый URL страницы приложения.
- Поиск требует подтверждённого аккаунта и активной приватности. Отмена, закрытие
  вкладки и переход на другой сайт не дают позднему ответу восстановить выдачу.
- Сайты остаются недоверенными данными. Их происхождение видно по доменам и URL;
  адрес открытого сайта не подменяется на Kosmora.

## Проверки и оставшаяся приёмка

Desktop: 160 тестов, syntax check и unsigned policy для 0.15.1 прошли.
API: 35 тестов планировщика и 4 теста поиска прошли; typecheck, build и lint прошли.
Реальный Chromium/CDP: наша страница получила сгенерированный источник, отдала
его как DOM-ref и открыла ссылку на локальную тестовую форму. Основной тест
формы с Unicode и файлом сохранён. Поисковый провайдер и планировщик тестовые;
это не приёмка живой выдачи DuckDuckGo. Проверены отмена зависшего провайдера,
запоздалая запись после навигации, некорректные ссылки и ошибка upstream.

Доказательства: [прогон Chromium](evidence/koswork-own-search-20261029/dom-smoke.json),
[скриншот с тестовым источником](evidence/koswork-own-search-20261029/search-fixture.png).

VPS не изменялся. После восстановления нужен существующий SearXNG с включённым
JSON и движком duckduckgo, обновлённый API и Windows-клиент. На сервере предстоит
проверить доступность upstream и ограничения частоты. Установка приложения,
живая модель, реальные сайты и платные запросы здесь не выполнялись.

Веб-предпросмотр отдельно помечен: оформление нашей выдачи доступно, но сервер
поиска и агент в нём не подключены. Страница ошибки не выдаётся за работающий
интернет-поиск. Нативный Chromium работает в Windows-кандидате.

Документация источника: [Search API SearXNG](https://docs.searxng.org/dev/search_api.html),
[движок DuckDuckGo](https://docs.searxng.org/dev/engines/online/duckduckgo.html).
