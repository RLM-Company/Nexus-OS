# Koswork: полный набор файлов и корректные отказы экспорта

## Поведение

Упаковщик ZIP сверяет состав переданного набора с версиями, заявленными в
завершённых шагах плана. Пропуск, повтор файла, лишняя копия и повтор идентификатора
в декларации приводят к `DEPENDENCY_ARTIFACT_MISSING`: архив не отдаётся как
корректный полный результат. Сохраняются проверки каждого файла по байтам,
размеру, версии, работе и проекту. Одинаковые имена разных версий разрешены;
порядок входного набора не обязан совпадать с порядком шагов.

Частичные планы продолжают экспортировать все заявленные файлы именно завершённых
шагов. Отменённые/незавершённые шаги не превращаются в готовые результаты; пустые
частичные архивы содержат отчёт и manifest. Старые корректные наборы без новых
необязательных полей проверки/попыток сохраняют совместимость.

JSON-экспорт сначала проверяет и собирает результат, затем устанавливает заголовок
вложения. При повреждении возвращается JSON с ошибкой, без имени скачиваемого файла.
Оба маршрута JSON/ZIP устанавливают `private, no-store` также для отказов 404/409.
Состояние работы, файлы, журнал расходов, права и число вызовов модели не меняются.

## Проверки

Независимое чтение центрального каталога ZIP и CRC: неполный набор, повтор,
лишняя копия, повтор декларации, переставленный корректный набор и частичный план.
Прежние проверки точных UTF-8 байтов, одинаковых имён, приватных полей, опасных
путей и предела размера остаются. Реальные Fastify/SQLite проверяют безопасные
отказы при повреждении файла и отсутствии доступа к плану, корректные скачивания
и отсутствие повторного запуска модели. Интерфейс, миграции и VPS не меняются.
