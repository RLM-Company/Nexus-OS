## Контракт и границы

- Для BIZ-013 `GET /api/v1/projects/:projectId/sources/run/:runId` принимает ID
  Work. Квитанция фиксирует выбранные файлы и канонический JSON, использованный
  расчётом. Для модельного Work этот же маршрут принимает ID модельного вызова
  из `ManagerWork.result_sources`. Список приходит из упакованного запуска,
  включая фактически переданные проектные инструкции и материалы. Источники
  памяти содержат ссылки и хеши без второй копии текста. Квитанции доступны
  владельцу, входят в экспорт аккаунта и удаляются вместе с проектом.
- Для правил `POST .../propose` возвращает предложение, `POST .../accept`
  подтверждает выбранную формулировку. `enable`, `disable` и `rollback`
  принимают `expected_version` и добавляют новую ревизию. Старый работающий
  или завершённый Work сохраняет принятый снимок. Однозначная команда
  «Всегда показывай доставку отдельной строкой» применяется к BIZ-013.
  Остальные формулировки сохраняются с явным статусом отсутствия поддержки.
- Старые задания могут не содержать квитанцию нового формата. Приёмка остаётся
  под существующими правами владельца.
- Поставки #650 (локальный цикл Windows) и #660 (PDF-реестр) относятся к другим
  сценариям. Они не входят в этот кандидат.

## Воспроизводимые проверки

```bash
pnpm --filter @cosmora/api exec vitest run test/manager-work.test.ts test/supplier-work-handoff.test.ts test/project-correction-rules-api.test.ts test/project-sources.test.ts test/code-agent.test.ts test/github-integration.test.ts
pnpm --filter @cosmora/db exec vitest run test/project-correction-rules.test.ts test/project-sources-store.test.ts
pnpm --filter @cosmora/core exec vitest run test/project-correction-rules.test.ts test/supplier-offer-comparison.test.ts
KOSMORA_E2E_PRODUCTION=1 pnpm --filter @cosmora/web exec playwright test e2e/supplier-work-handoff.spec.ts e2e/code-agent.spec.ts --workers=1 --retries=0
```

В браузере передать два файла JSON из сообщения, подтвердить изменившиеся
инструкции, скачать CSV с итогом `19700` и недокомплектом `00123`, принять
результат, открыть прежний URL в новой сессии. Затем подтвердить правило и
повторить сравнение: строка доставки появляется во втором CSV, первый CSV
и первая отметка принятия сохраняются.

Koscode использует действующий сценарий предложения, отказа проверки,
исправления, новой проверки и подтверждения одного Draft PR при потере
ответа. Браузерная проверка использует фикстуры API. Отдельная проверка
`Code sandbox isolation` в CI запускает настоящий OCI-исполнитель с
временным Git-репозиторием и фикстурами модели и GitHub. Живой прогон
требует согласованного тестового назначения, стенда, разрешения на
провайдера и публикацию. [Сценарий Koscode](TEAM_KOSCODE_LIVE_WORKFLOW_RU.md)
