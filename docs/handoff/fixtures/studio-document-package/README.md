# Studio: синтетический пакет документов (блок A)

Переносимый набор для проверки загрузки и анализа документов в Kosmora Studio.
Создан по заданию владельца от 20 ноября 2026: сначала простой архив
PDF/DOCX/TXT/CSV, затем вложенный архив, скан, неполные и повторяющиеся
материалы; ожидаемый манифест с файлами, страницами, цитатами и пропусками.

## Состав

| Файл             | Назначение                                                                                                                                                                      |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `generate.mjs`   | детерминированный генератор архивов и манифеста (без внешних зависимостей)                                                                                                      |
| `simple.zip`     | базовый архив: `brief.txt`, `budget.csv`, `report.pdf`, `memo.docx`                                                                                                             |
| `extended.zip`   | расширенный: базовый + `appendix/long.pdf` (3 стр.), `scans/scan.pdf` (скан), `partial/truncated.csv`, `nested.zip`, `duplicates/BRIEF.TXT`, `__MACOSX/._brief.txt`, `notes.md` |
| `manifest.json`  | ожидаемые члены, байты, SHA-256, страницы, цитаты, пропуски, неполные и дубли                                                                                                   |
| `self-check.mjs` | машинная самопроверка пакета                                                                                                                                                    |
| `SHA256SUMS`     | контрольные суммы скрипта, архивов и манифеста                                                                                                                                  |

## Запуск

```bash
node generate.mjs            # пересоздать simple.zip, extended.zip, manifest.json, SHA256SUMS
node self-check.mjs          # проверить пакет; exit 0 = всё сходится
node generate.mjs --out DIR  # записать в другую директорию
node self-check.mjs --dir DIR
```

`generate.mjs` детерминирован: повторный запуск даёт те же SHA-256 архивов.
Самопроверка проверяет: контрольные суммы, состав/байты/хеши членов ZIP,
сигнатуры PDF/DOCX, Word XML namespace, наличие цитат вtxt/csv и DOCX,
число страниц PDF, а также полноту описаний пропусков/неполных/дублей.

## Вопрос и эталоны

Вопрос: «Какой итоговый бюджет и срок сдачи по лунной станции?»
Ожидается в ответе: `24 000`, `19 700`, `4 300`, `12 октября 2027`, `SELENE-047`.
Цитаты и их координаты (файл, страница, строка) — в `manifest.json.citations`.

## Что должно быть отчитано импортером/анализатором

1. **Простой пакет**: 4 документа, все поддерживаемые расширения, без пропусков.
2. **Расширенный пакет**:
   - пропуски: `__MACOSX/._brief.txt`, `notes.md`;
   - вложенный архив разворачивается в один уровень с breadcrumb
     (`nested.zip › nested › brief.txt`, `nested.zip › nested › extra.csv`);
   - неполные: `partial/truncated.csv` (только заголовок), `scans/scan.pdf`
     (изображение без текстового слоя);
   - похожие имена: `duplicates/BRIEF.TXT` и вложенные копии сохраняются под
     разными путями, коллизии не сливаются;
   - страницы: `appendix/long.pdf` — 3, `scans/scan.pdf` — 1 (0 с текстом).
3. Имена в библиотеке плоские: `a/b.txt` → `a › b.txt` (см.
   `apps/web/src/app/library-archive-import.ts`).

## Связь с реальным продуктом

`apps/web/src/app/studio-fixture-import.test.ts` читает оба архива этого пакета
и прогоняет их через **настоящий** `prepareLibraryUpload` из
`library-archive-import.ts`, сравнивая результат с `manifest.json`. Два теста
проверяют: простой пакет импортируется без пропусков; расширенный даёт ровно
ожидаемые имена (с разделителем `›`), скан/неполный CSV сохраняются, а
неподдерживаемые/`__MACOSX`/вложенный архив `-- skipped`. Это исключает
ситуацию, когда пакет самосогласован, но не соответствует продукту.

`apps/api/test/studio-fixture-deep-analysis.test.ts` прогоняет цитаты пакета через
**настоящий** `DocumentAnswerService` в `deep`-режиме (in-memory SQLite, mock
провайдер без платных вызовов) и сверяет `coverage`: все переданные документы
разобраны, `analyzed + failed = total`, а пропуски/неполные из манифеста остаются
честно описанными. Важное ограничение реального сервиса: скан без текстового
слоя даёт 0 чанков и не может быть передан как анализируемый файл — в манифесте
он помечен `incomplete` и в deep-анализ не включается.

`first-gemini-run.mjs` запускает реальные локальные проверки пакета и пишет
`first-gemini-run/result.json` + `diff.md`. Это **не живой Gemini**: симулятор
честно помечает источник как `local-simulation-NOT-live-Gemini`. Он проверяет,
что формат адаптации работает и расхождений с манифестом нет; живой отчёт
позднее заменяет каталог целиком.

## Адаптация под первый прогон Gemini

Этот раздел — точка входа для внешнего исполнителя Gemini. Порядок:

1. Запустить `node generate.mjs`, затем `node self-check.mjs` — локальный
   эталон должен быть зелёным до передачи пакета.
2. Прогнать оба архива через загрузчик/анализатор и сравнить результат с
   `manifest.json` по каждому полю: файлы, страницы, цитаты, пропуски.
3. Записать фактический отчёт в `first-gemini-run/` (создаётся при первом
   прогоне): `result.json` + `diff.md`, где явно перечислены расхождения.
4. Исправить расхождения **в генераторе**, а не в манифесте вручную:
   манифест пересоздаётся из `generate.mjs`, поэтому источник истины один.
   Фактические расхождения, уже найденные и исправленные до первой передачи:
   - цитата `budget.csv` была записана как `19700;00123;...` вместо
     фактического `00123;19700;...`;
   - дубль из вложенного архива был описан как мнимого члена
     `nested.zip › nested/brief.txt`; теперь указан реальный成员 `nested.zip`
     с полем `inner_name`.
5. После исправлений повторить `generate.mjs`→`self-check.mjs` и зафиксировать
   новые SHA-256 в отчёте. Не подменять реальные результаты фикстурами.

## Границы

Пакет синтетический: модель и внешние сервисы не вызываются. Реальные провайдеры
и живая приёмка — отдельное поручение владельца. Секреты в пакет не добавляются.
