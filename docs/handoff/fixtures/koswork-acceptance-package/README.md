# Приёмочный набор Koswork: малый бриф + два источника

Переносимый пакет для проверки сквозного сценария Koswork: зависимый расчёт,
конечный документ и аварийные условия (пауза, перезапуск, частичный результат,
повторная дата). Создан по заданию владельца от 20 ноября 2026 (блок B).

## Набор данных

- **Бриф**: подготовить короткий отчёт о бюджете лунной станции.
- **Источник 1** (`source-a.txt`): `19 700 ₽`, артикул `00123`, дата `07.11.2026`.
- **Источник 2** (`source-b.txt`): `4 300 ₽`, артикул `00456`, дата `08.11.2026`.
- **Ожидаемое**: сумма `24 000 ₽`, оба артикула сохранены, дата повтора не
  меняет исходные значения `[expected.json]`.

## Сценарии

| Имя              | Что проверяется                                                     |
| ---------------- | ------------------------------------------------------------------- |
| `normal`         | 材料一→材料二→зависимый расчёт→конечный DOCX; все эталоны совпадают |
| `paused_resumed` | пауза после первого шага, продолжение без повторного вызова модели  |
| `restarted`      | перезапуск координатора, завершённые шаги не повторяются            |
| `partial`        | частичный результат: один файл + отчёт с `"complete": false`        |
| `retry_new_date` | повтор с новой датой: сумма и артикулы прежние, дата обновлена      |

## Первый отчёт DeepSeek

`reports/deepseek-first-run.json` — ожидаемая форма отчёта исполнителя. При
получении реального первого прогона DeepSeek замените этот файл фактическим
отчётом и запустите `verify.mjs`: он покажет расхождения по эталонам.

Уже исправленные неоднозначности (до первой передачи):

1. Дата повтора не должна изменять исходные суммы/артикулы — явно зафиксировано
   в `expected.json.retry_new_date.invariant`.
2. Частичный результат не должен встречаться за полный: `complete:false` и
   `completed_steps < total_steps` проверяются отдельно.

## Запуск

```bash
node verify.mjs                 # сверить встроенные эталоны и целостность пакета
node verify.mjs --report FILE   # сверить фактический отчёт с эталонами
```

Проверка без аргументов гарантирует, что эталоны самосогласованы и SHA-256
файлов совпадают с `SHA256SUMS`. С аргументом — сравнивает фактический отчёт
с ожидаемыми значениями по каждому сценарию.
