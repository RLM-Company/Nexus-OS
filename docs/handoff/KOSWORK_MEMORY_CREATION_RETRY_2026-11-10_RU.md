# Koswork: повтор создания памяти после потери ответа

Память проекта раньше создавала новую запись на каждый POST. Если сервер уже
сохранил запись, а ответ потерялся, ручной повтор создавал дубликат.

## Поведение

Добавлен необязательный `client_creation_id` только для создания записи.
Сервер сохраняет ключ и SHA-256 канонического набора полей. Повтор в той же
области владельца/проекта возвращает исходную запись без новой вставки, в том
числе после обновления экземпляра хранилища и при заполненном лимите записей.
Порядок JSON-свойств не является частью содержимого. Изменение любого поля
с тем же ключом возвращает `MEMORY_CREATION_CONFLICT` (409).

Редактирование записи не откатывается повтором её первоначального создания:
возвращается текущая версия исходной записи. «Забыть» сохраняет непрозрачный ключ
в существующей строке-tombstone, очищает прежний fingerprint вместе с содержимым
и источником. Старый запрос возвращает `MEMORY_CREATION_FORGOTTEN` (409), а не
восстанавливает забытое. Явное новое создание с новым ключом допускается.

Проверка и вставка выполняются в savepoint; уникальный индекс ограничен проектом,
владельцем и ключом. Savepoint не коммитит внешнюю транзакцию. Проектные проверки
доступа, состояние проекта, источники и лимит 200 записей сохраняются. Новых
таблиц или независимого журнала данных нет. Ключ и fingerprint не выдаются
в публичном объекте памяти. Старые клиенты без ключа сохраняют прежнюю семантику.

Форма держит ключ неизменённой попытки в памяти до успешного подтверждения.
Повтор отправляет тот же ключ и содержимое. Следующее создание после успеха
получает новый ключ; изменённый черновик — другую попытку. Выбор редактирования
или смена проекта сбрасывают ожидающее создание. Автоматических POST нет.
Переживание перезапуска формы/страницы не заявляется.

## Проверки

- Регрессионный тест до исправления создавал два разных ID для одного ключа.
- База: повторы, изменение каждого поля, owner/project scope, редактирование,
  запрет воскрешения после forget и очистка digest, лимит/старые клиенты,
  вложенная транзакция.
- Миграция с версии 63: сохранены старые ID, версия, текст `19 700 ₽, кроме доставки`,
  pin; новые колонки NULL, повтор миграции безопасен, SQLite integrity_check.
- API: 201 с прежним ID, 409 при конфликте/forget, 400 для недопустимых ключей,
  совместимость старого POST без ключа.
- Браузер: первый POST реально принят локальным API/SQLite, но ответ подменён
  на 503; ручной повтор возвращает тот же ID, в истории одна запись. Следующее
  явное создание получает новый ключ и отдельную запись.

Используются сценарная модель и синтетические данные. Стили, компоновка и
навигация не меняются. Платные запросы, VPS и живая приёмка на ПК не используются.

## Порядок выпуска

Миграция `0064_project_memory_creation` добавляет nullable-колонки и уникальный
частичный индекс, существующее содержимое не переписывается. Сначала обновляется
API со схемой, затем web. Защита не заявляется для новой формы со старым API,
который ещё не поддерживает поле. Серверная выкладка в этот блок не входит.
