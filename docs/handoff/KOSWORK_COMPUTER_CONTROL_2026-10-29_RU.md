# Koswork: управление Windows-компьютером, первый кандидат

29 октября 2026, Europe/Moscow. База `8938ed4cae46ce96f79d85f2eb4e7794bb123c12`.
Ветка `codex/koswork-computer-control-20261029`.

Владелец выбрал подключение и управление реальным ПК: сайты/вкладки, приложения,
документы, ввод текста и взаимодействие с программами. Это реализация первого
Windows-адаптера в существующем клиенте, а не объявление готовности всего Koswork.
Облачный компьютер, внутренняя изолированная среда и отдельный браузер остаются
другими блоками. Дизайн чата, сайдбар и логотип сохранены.

## Что добавлено

- Нативная консоль задачи: проект, цель, отдельное разрешение, журнал шагов,
  остановка и глобальная клавиша Ctrl+Alt+Shift+K. В существующей панели Work —
  только кнопка открытия этой консоли с целью/проектом.
- Поиск приложений по системному каталогу, запуск найденного приложения,
  открытие сайтов браузером по умолчанию и документов их обычными приложениями.
- Наблюдение основного монитора и ограниченное дерево доступности, переключение
  окон, клик, прокрутка, Unicode-ввод и сочетания клавиш. Исполнитель Windows
  работает отдельным скрытым процессом с фиксированным протоколом, а не строками
  shell от модели.
- Серверный цикл «экран → одно действие → новое наблюдение» на существующем
  ModelGateway. Vision обязателен; автоматических повторов платного запроса нет.
  Токены и неопределённые расходы используют существующий учёт владельца/проекта.
- Сеанс связан с владельцем, сервером, проектом и целью; на каждое действие
  запрашивается одноразовая авторизация его точного хеша. Политика проекта,
  аварийная остановка и privacy fence проверяются до выдачи действия.
- Смена владельца/сервера, выход, остановка, срок и перезапуск не возобновляют
  управление. Поздний ответ модели не может восстановить остановленную сессию.
  Смена окна или ввода после снимка запрещает действие по старому состоянию.
- Изображения обрабатываются в памяти; временная текстовая история подключена
  к экспорту/удалению данных владельца. Авторизация/учёт расходов не удаляются.

`COMPUTER_FOCUS_REJECTED`: Windows может отказать в активации окна; такой сеанс

Полные снимки рабочего стола в репозиторий не добавлены. Во время разработки
обнаружены и исправлены несовместимый с PowerShell 5 тип `ushort`, несовпадение

Ранние отказы фокуса/нестабильные снимки не объявлялись успехом; финальные три прогона
выполнены после исправлений, с проверкой времени последнего ввода.

## Ограничения и приёмка

Основной монитор; 30 шагов задачи в консоли и протоколе; 30 минут
разрешения. Нет гарантии управления любой программой, повышенными окнами,
экраном блокировки, UAC или CAPTCHA. Классификация последствий по смыслу поручена
модели: флаг подтверждения не заменяет доказанную защиту от всех опасных GUI-действий.
Выполнять задачу одновременно с ручной работой мышью/клавиатурой нельзя считать
надёжным сценарием.

Тест Блокнота не доказывает совместимость со всеми редакторами и приложениями.
Нужны живой оплаченный vision-маршрут и целевой сценарий от владельца,
проверка packaged/installed клиента с API и обычная Windows-приёмка. Сервер не обновлён,
установщик на ноутбуке не запускался, платных запросов в этом блоке не было.
Предыдущие отложенные проверки первого этапа этим кандидатом не закрываются.

## Как подключать после приёмки

1. Совместимые API/web и Windows-клиент 0.12.0. Миграций БД этот блок не добавляет.
2. Обычный вход владельца; подготовленный/активный проект с разрешёнными
   `integration.private.use` и `workspace.write`. Создание пустого проекта не
   запускает модель; запуск авторизованной задачи активирует его.
3. Доступный действующий vision-маршрут для роли analyst / `manager_work_draft`.
   Существующие ключи и выбор провайдера автоматически не заменяются.
4. Koswork → «Выполнить на компьютере» либо нативное меню Koswork; цель,
   проверка раскрытия экрана и разрешение на задачу. Закрытие консоли прекращает её.

Автообновление клиента по-прежнему выключено без ключа публикации. Этот кандидат
не является подписанным Windows-релизом и не выкладывался на VPS.

## Подготовка настоящего запуска после разбора теста

Владелец отдельно уточнил: Word и Telegram должна выполнить сама Kosmora.
Ранние движения на ноутбуке выполнялись разработчиком через детерминированные
сценарии, не живой моделью. Исторические JSON/хеши в evidence относятся к исходнику
`9d4a353e`; после этого уточнения эти сценарии на ноутбуке повторно не запускались.

Добавлены:

- Неплатная проверка vision-маршрута до активации проекта. Это проверка локальной
  конфигурации, а не гарантия доступности внешней модели.
- Обязательное объявление провайдерного планировщика при создании сеанса и
  проверяемые клиентом метаданные источника каждого шага. Нативный рабочий клиент
  отказывается от mock/test, старого API без метаданных и чужого session/step.
  Метаданные формирует API по завершённому Gateway run; модель не может добавить
  их своим JSON. Это сведения доверенного сервера, не независимая аттестация.
- Явные состояния «ещё не запускалась», «ожидание команды», «пауза», «завершён»
  и журнал идентификаторов запросов. Проверка исполнительного механизма не
  показывается как запуск живой модели.
- Пауза `ask_user` с кнопкой локального продолжения. Сеанс и история сохраняются
  в прежнем ограничении 30 минут/30 шагов; во время ожидания нет снимков, действий
  и вызовов модели. Продолжение не переносит пароль/код в модель. Истечение гранта,
  смена владельца и остановка запрещают продолжение перед новым снимком.
- Настоящий путь рабочего стола из Windows Known Folders, включая перенесённый
  Desktop/OneDrive. Содержимое папки автоматически не перечисляется.

Проверено без движения мыши/клавиатуры владельца: 19 тестов computer-control API,
9 тестов HTTP identity boundary, 200 контрактных тестов и 87 Node-тестов Windows;
typecheck/lint API и контрактов, сборка API/контрактов. PowerShell-helper скомпилирован
с закрытым stdin без обращения к рабочему столу. Проверки подтверждают протокол,
ожидание/продолжение и запреты; это по-прежнему не живой сквозной тест модели.

Для предыдущего коммита `9d4a353e` завершились Windows build/lifecycle, Browser
acceptance, Verify monorepo и API identity. OCI сначала упёрся в холодный запуск
