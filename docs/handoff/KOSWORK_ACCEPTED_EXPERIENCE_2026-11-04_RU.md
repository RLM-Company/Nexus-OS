# Koswork: выбранные примеры принятых задач

## Назначение

Продолжение согласованного Ruflo/Gemini плана: использовать подтверждённый опыт
в новом рабочем задании. Основа — существующая зашифрованная локальная история,
план, критерии, состояния инструментов и явная отметка владельца «Результат проверен
мной». Новая база памяти, автономный learner и SQL-миграции не добавляются.

В существующей истории окна Koswork у подходящей задачи появилась команда
«Использовать как пример». Она выбирает один пример для следующего запуска,
сохраняет уже написанную новую цель, позволяет снять выбор. Выбор сбрасывается
после запуска, смены проекта и получения новой задачи из приложения. Чат, sidebar,
логотип, компоновка и стили не меняются. Это добавление функции в существующий
локальный элемент, а не переделка оформления.

## Сравнение с повторно использованной основой

Проверены закреплённые Ruflo 3.71.0 / commit
5f3dacc54b7279e39b172d6027d7989791448e2e:

- [ReasoningBank adapter](https://github.com/ruvnet/ruflo/blob/5f3dacc54b7279e39b172d6027d7989791448e2e/v3/@claude-flow/browser/src/infrastructure/reasoningbank-adapter.ts):
  превращает успешные trajectories в patterns, содержит selector/value поля.
- [Signed trajectory service](https://github.com/ruvnet/ruflo/blob/5f3dacc54b7279e39b172d6027d7989791448e2e/v3/@claude-flow/browser/src/application/signed-trajectory-service.ts):
  связывает источник, метаданные и изменение процедуры. Подпись/хеш содержимого
  сами по себе не доказывают правильность результата.

Адаптирована идея происхождения и повторного использования процедуры. Код upstream
не копировался. Наши существующие Work workflow/Skills уже покрывают декларативные
шаблоны; они сохраняются. Здесь закрывается другой путь: явный выбор локального
принятого примера при новом задании управляемого Work-агента. Selector/value replay,
снимки экрана, пароли, coordinates и перенос прежних разрешений не добавлены.
Автоматическая выдача произвольного remedialResolution за системное правило исключена.

## Пригодность примера и значение результата

Источник должен находиться в текущей истории того же owner/server/project, иметь
executionMode=work, status=completed, явный acceptedAt и полный проверенный план.
Все состояния плана checked, неопределённые dispatching/requested отсутствуют.
Строки с секретами и незавершённые/непринятые задачи не предлагаются.

Модели передаются только выдержка цели до 500 UTF-16 units (без обрыва символа),
план с критериями без старых checked-состояний, source ID/project/acceptedAt,
revision и компактные счётчики наблюдений инструментов. Общий JSON до 14 000
UTF-8 байт. Сокращение цели и сводки инструментов явно помечено. Счётчики observed
означают наличие следующего наблюдения; они не доказывают желаемый внешний эффект.
Метод не даёт автоматического утверждения достоверности всех исходных фактов.

acceptedAt — локальная отметка владельца, не серверная аттестация. Revision — хеш
исходной записи для определения изменений, не подпись, модельный score или оценка
качества. Статус completed одной модели без отметки владельца недостаточен.

## Новый запуск

- Команда выбора не начинает модель или выполнение. Нативное подтверждение новой
  задачи показывает, какой пример выбран и какие данные будут переданы модели.
- План новой задачи пуст; составляется заново под текущую цель. Старые approvals,
  refs, адресаты, координаты, paths и права инструментов не восстанавливаются.
- API принимает пример как отдельное UNTRUSTED REFERENCE DATA внутри user JSON.
  Системное правило фиксировано и не содержит текста источника. Текущая цель,
  policy/grants, фактические файлы и свежие наблюдения остаются определяющими.
- Сервер ограничивает пример тем же project и режимом work, фиксирует его digest
  на первом шаге и отклоняет смену/удаление примера в продолжающемся сеансе до
  нового model dispatch. Размер проверяется до запроса провайдеру.
- Локальный исполнитель перечитывает запись до/после model request и перед
  действиями через assertLive. Удаление, истечение, изменение или смена owner/origin
  прекращают использование; поздний результат не получает разрешение на ввод.
- При заполнении истории выбранный источник защищён от eviction в момент создания
  нового задания. Новая запись сохраняет только ID/revision происхождения. При
  восстановлении сверяются тот же источник и версия, права запрашиваются заново.

## Приватность, совместимость и стоимость

Никакого фонового просмотра других чатов или автоматического включения памяти нет.
Пример выбирается явно для одной задачи. Действующие encryption, logout/account
cleanup, 20-record/30-day retention и privacy fences локальной истории сохраняются.
Отдельной копии траектории или новых постоянных серверных таблиц нет. Удаление
истории не обещает удалить уже созданные пользователем результаты или прошедшие
провайдеру запросы; действуют существующие механизмы удаления соответствующих данных.

API объявляет supports_work_reference только для Work. Без согласования старый
сервер не получает новый payload; выбранная reference-задача останавливается до
planner step с понятной причиной, обычные задания продолжают прежний протокол.
Клиент 0.20.0 включает модуль в NSIS. Для живого использования нужны совместимые
API и установленный клиент; серверная выкладка и ноутбук владельца этим пакетом
не обновляются. Никакого fine-tuning, изменения весов или доказанного роста
бенчмарков нет. Пример добавляет входные токены к обычному запросу; отдельного
платного вызова на дистилляцию/обучение не выполняется. Старые бюджеты сохраняются.

## Приёмка

- AES-GCM history: accepted/unaccepted/failed/unfinished/secret/uncertain sources,
  project/owner/origin, revision, expiry, clear, Unicode, retention pin и lineage.
- Настоящие Work driver/ComputerSession/workspace: выбранный пример поступает в
  планирование; новый план пуст, затем создаётся и читается новый реальный файл,
  проверяются текущие критерии и отдельное подтверждение записи. Старые grants
  не применяются. Model planner — сценарная фикстура.
- Удаление истории во время model await: authorization=0, файл не создаётся.
- Legacy API: planner steps=0, пример не передаётся.
- API: выбранный пример только в user data, текущая цель сохранена; подмена,
  удаление, чужой project/режим и чрезмерный размер отклоняются до dispatch.
- Настоящий Chromium: выбор/снятие и сброс примера, сохранение новой цели,
  передача выбранной ссылки при start, переключение проекта и literal untrusted
  labels. Разметка источника не исполняется.

CI и точная ревизия фиксируются в PR. Живая модель, основной рабочий стол, личные
файлы и VPS в тестах не участвуют. Успешный тест передачи контекста не доказывает
улучшение качества произвольных рабочих задач.
