# Контекст Kosmora: убрать искусственный порог 32K

Прямое поручение владельца от 31 октября 2026 года: провести проверку CheapVibeCode
gpt-6.1-sol и отключить ограничение Kosmora на 32 тысячи. Визуал не меняется.

## Изменение кода

В production runtime ChatService и ManagerService получают окно выбранной модели
из Model Registry, включая выбор mock по alias. Сборщик переписки и упаковка
дополнительной памяти используют один и тот же вычисленный бюджет. Старый предел
28000 больше не применяется к рабочему runtime с найденным маршрутом.

Из окна вычитаются настроенный выходной бюджет и резерв для часов/профиля/Relay:
до 4096 единиц (10% для маленьких окон). Для Sol 1050000 и вывода 1200 это 1044704.
Это консервативная верхняя оценка входа по UTF-8/изображениям, не точный токенизатор
и не обещание вместить 1050000 реальных токенов произвольного текста.
Реальный предел модели и запрет молча обрезать текущий вопрос сохраняются.
Standalone-конструкторы без явно переданного окна сохраняют прежний fallback,
чтобы не угадывать характеристики неизвестного маршрута.

Финансовые квоты, размер одного вложения, ручные параметры задач и выходной бюджет
не отключаются этим изменением. Оно относится к сборке контекста.

## Профиль Sol

`config/model-registry.cheapvibecode.sol.v1.json` — отдельный opt-in профиль.
Авторизованный GET https://ru.cheapvibecode.ru/v1/models подтвердил наличие Sol
и объявления context_window=1050000, max_output_tokens=128000. Это согласуется
с https://developers.openai.com/api/docs/models/gpt-6.1-sol, но не удостоверяет
происхождение модели и не доказывает использование полного контекста на практике.

Профиль использует прежний транспорт openai-compatible. Tool calling и strict
structured output не объявлены поддержанными этим Chat Completions адаптером.
Конфиденциальность неизвестна, денежные цены null. Eligibility roles/task_types=[]
позволяет общей модели обслуживать существующие задачи; права инструментов остаются
в отдельных policy/consent checks. Этот новый профиль сам по себе не активируется.
Не заменять им существующий живой профиль без проверки требуемых задач/правил.
Свидетельство discovery ограничено сроком, указанным в JSON.

Предыдущие исторические профили gpt-5.5 и другого провайдера не переписаны.

## Активация на VPS

При подготовке HTTPS 13.141.51.16 не ответил в заданный connect timeout.
Выкладки или изменения службы не было. Не утверждать, что лимит уже снят на сайте.

Когда сервер восстановлен:

1. Сохранить текущие API-образ, model.env и фактически выбранный registry с хешами.
2. Собрать API с обновлёнными packages/core и apps/api. Миграции этому изменению не нужны.
3. В существующем активном Sol registry заменить только context_window_tokens
   на 1050000 после свежей проверки каталога. Сохранить model_id, aliases, roles,
   task_types, capabilities, privacy, цены и действующее обслуживание. Новый opt-in
   профиль — альтернатива, не повод расширять существующий allowlist автоматически.
4. Перезапустить API, проверить здоровье и реально используемые registry/model.
5. Проверить запрос/историю больше 32K и честный отказ на превышение окна модели.
   Контрольный синтетический вопрос должен содержать случайный факт из начала истории.
6. При ошибке вернуть сохранённые образ и registry. Данные и web не заменять.

Локальные проверки: крупная история, текущий вопрос на кириллице, обязательная
память, окно маленькой модели, резерв вывода, история проекта и wiring runtime.
Все проверки используют fixtures, не подтверждают качество провайдера.

Дополнительная живая проверка исправленного кода: buildApp → HTTP injection →
GeneralChatRoutes → ChatService → ModelGateway → настоящий CheapVibeCode streaming
Chat Completions. Использована только временная in-memory база с синтетической
перепиской, без слушающего сервера, VPS и пользовательских данных. Один модельный
вызов завершён успешно: верхняя оценка входа 127133, провайдер сообщил 63234
входных токена. Два случайных значения из начала/конца истории возвращены точно.
Контроль старого упаковщика уже не содержал раннего значения; исправленный
запрос содержал оба. Это не активация исправления на размещённом сайте.
