# Koswork: контрольные точки, отмена и подтверждения

Шесть последовательных блоков поверх исправления поздних результатов в PR #451.
Это укрепление действующего исполнителя Kosmora/Koswork в согласованном объёме
восстановления, privacy lifecycle и управления правами.

## Что изменилось

| Блок                   | До изменения                                                                                                                         | Теперь                                                                                                                                             |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| Контрольная точка Work | Фильтр подписей плана пропускал PIN, одноразовые коды и некоторые credential-формы, уже исключённые из цели задачи                   | Общая проверка целей и подписей. Чувствительный план становится `null` при записи и при чтении старой записи                                       |
| Нативный API           | Переданный AbortSignal мог игнорироваться транспортом; поздний ответ всё равно принимался. Повреждённый UTF-8 заменялся символом `�` | Проверки отмены перед fetch, после identity/fetch/чтения потока и перед возвратом. Некорректные UTF-8/JSON отклоняются с ограниченным кодом ошибки |
| Смена плана            | Даже `browser_read`/`browser_tabs` выставляли признак совершённых изменений и вызывали лишнее подтверждение                          | Только явные операции наблюдения исключены из этого признака. Подтверждения записи и смены плана после эффектов сохранены                          |
| Остановка сред Work    | Ошибка `browser.stop` пропускала `computer.stop`; неудачный begin мог оставить старый контекст                                       | Обе очистки предпринимаются независимо. Контекст и права сбрасываются до запуска очистки; ошибка блокирует выполнение                              |
| Очистка браузера       | Ошибка отмены первой загрузки мешала отменить остальные и завершить dispose                                                          | Предпринимается отмена каждого transfer. Dispose всё равно снимает listener, очищает таймер и пытается закрыть все view, затем сообщает об ошибке  |
| Остановка сессии       | Ошибка `workspace.cancel` пропускала остановку нативного драйвера                                                                    | Обе очистки вызываются независимо; при ошибке контроллер требует перезапуска и не допускает новую задачу                                           |

Чтение старой чувствительной записи скрывает её план; это не заявление о физическом
удалении прежнего зашифрованного файла. Следующая запись сохраняет очищенное
представление, штатная очистка истории по-прежнему удаляет его целиком.

Наблюдения, не требующие подтверждения смены плана: `observe`, `wait`, `list_apps`,
`find_apps`, `browser_read`, `browser_tabs`, `browser_screenshot`. Это не отменяет
первичное согласование среды, проверки владельца, шага и текущего observation.
Ввод, навигация, загрузки, неизвестные действия и запись сохраняют консервативную
обработку. Неудача отмены не объявляет transfer отменённым и не доказывает откат
внешнего эффекта.

## Проверяемые сценарии

- Регрессионные проверки каждого блока падали на прежнем поведении.
- История: PIN/код/passwd/token в планах и чтение старой зашифрованной записи;
  обычные условия `19 700 ₽, кроме доставки` сохраняются.
- API: отмена до/во время identity, fetch, body и последней проверки identity;
  русская цитата/эмодзи в побайтовом потоке, повреждённые UTF-8 и JSON.
- Реальный `ComputerSession` + `WorkCycleDriver`: чтение браузера, смена плана,
  подтверждённая запись отчёта, новая смена плана с подтверждением и чтение файла
  обратно. Один лишний диалог исключён; два необходимых подтверждения сохранены.
- Ошибки очистки обеих сред, трёх параллельных transfer и workspace/driver.
  Проверяются все попытки очистки, отзыв прав, закрытие view и запрет повторного
  использования повреждённого контроллера.

Нативные исполнители в fault-сценариях сценарные; файлы и шифрованная история
настоящие, во временных папках. Платные модели не вызываются.

## Верификация

- `npm run check --prefix desktop/windows`: синтаксические проверки и 302 tests;
  **301 passed, 0 failed, 1 штатный Windows-only skip**.
- Профильные наборы для шести блоков прошли без ошибок.
- Prettier, проверка секретов и `git diff --check`.
- Новый общий модуль включён в NSIS inputs и обязательную проверку комплекта.
  После штатной подготовки 216 PDF/OCR-ресурсов `verify-unsigned-policy` прошёл:
  кандидат 0.19.0, unsigned NSIS x64, автообновления выключены.

Это не Authenticode-проверка, установка на ноутбуке владельца, серверная выкладка
или живая приёмка модели. Устройства, дизайн, Jarvis и Multi-Agent не расширены.
