## Пользовательский путь

Открыть `/code-agent`, выбрать проект и разрешённую базовую ветку, сформулировать небольшую правку, нажать «Предложить исправление». Сверить diff, сохранить подходящие файлы для проверки и разрешить её запуск. После обновления страницы остаются та же задача, diff и результат проверки. Для публикации нужно отдельное подтверждение точной версии проверенного предложения.

После обрыва ответа на публикацию интерфейс запрашивает состояние той же задачи. Если Draft PR уже записан, появляется исходная ссылка. Если GitHub ещё не подтвердил исход, доступна явная сверка. Повтор с тем же токеном и хешем проверки ожидает начатую операцию или возвращает подтверждённый результат. При неопределённом ответе GitHub повтор выполняет только сверку. Изменённые токен и хеш не дают повторно опубликовать устаревшее предложение.

Браузерный стенд проходит выбор проекта и ветки, diff из ответа фикстуры модели без ручной правки, проверку, перезагрузку, двойной клик и потерю ответа уже после сохранения ссылки. Сценарии того же набора проверяют смену двух задач, поздний чужой ответ и прямую ссылку на недоступный проект.

```sh
pnpm --filter @cosmora/api exec vitest run test/code-agent.test.ts test/code-agent-github-tree.test.ts test/github-integration.test.ts --maxWorkers=1
pnpm --filter @cosmora/web exec playwright test --config playwright.code-agent.config.ts
CODE_AGENT_TEST_IMAGE="$(docker image inspect node:24-bookworm-slim --format '{{.Id}}')" \
CODE_AGENT_REPAIR_REPORT_DIR=/tmp/koscode-624-fixture-proof \
pnpm --filter @cosmora/api exec vitest run test/code-agent.test.ts -t 'real OCI API repair' --maxWorkers=1
```

В локальном API-прогоне прошли 138 тестов, один OCI-сценарий условно пропущен. Типизация API и браузерного набора, целевые линт и форматирование прошли. При отдельном локальном OCI-запуске Docker вернул ошибку нехватки места при создании слоя контейнера. Первый локальный прогон Chromium был прерван после ошибок запуска смежных страниц в Next dev с вынесенным кэшем. Целевой прогон Chromium сообщил об успехе всех шести сценариев, а внешняя команда завершилась с кодом 1 после отчёта Playwright. Изолированный раннер и штатный браузерный gate проверяются на GitHub Actions.

Содержимое фикстуры OCI, исходный SHA, точный diff, результат проверок и число GitHub-записей сохраняются артефактом CI `coscode-final-workflow-proof`. Маршрут использует HTTP-адаптер исполнителя и временный Git-репозиторий. GitHub и модель в этом сценарии заменены фикстурами.

## Живой прогон

Открыты вызов модели и запись одного Draft PR в назначенном тестовом репозитории. Для этого прохода репозиторий и действующее разрешение на вызов модели и запись не предоставлены. Скрипт `test/code-agent-live-github.acceptance.ts` из #609 проверяет GitHub с синтетическим diff и не вызывает модель.

На разрешённом стенде используйте тот же пользовательский путь с отдельной тестовой веткой. Зафиксируйте исходный SHA, точный diff, вывод проверки, URL задачи, ссылку Draft PR и количество PR для созданной ветки. Проверка потери ответа должна сверять исход через интерфейс или чтение GitHub. Схема БД и зависимости поставки прежние. Откат через revert коммита поставки.
