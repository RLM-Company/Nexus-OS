# Koswork: восстановление чтения памяти проекта

Панель памяти проекта использовала одно состояние для ошибок чтения и изменения
записей. Последующее успешное чтение не очищало сетевое предупреждение. При этом
безусловная очистка общего состояния скрыла бы отказ сохранения.

Сетевое предупреждение отделено от ошибки команды. Только принятый актуальный
снимок очищает предупреждение чтения; проверяются abort, epoch и блокировка
изменения. Ошибка команды сохраняет приоритет в существующем блоке сообщения.
Поздний отказ чтения, начатого до изменения, не записывается поверх нового состояния.
При смене проекта сбрасываются оба состояния ошибок.

## Проверка

Браузерный сценарий с локальным API/SQLite:

1. Вернуть HTTP 503 при обновлении памяти — появляется сетевое предупреждение.
2. Восстановить HTTP 200 и явно обновить — предупреждение исчезает.
3. Отклонить сохранение HTTP 409 — видна ошибка изменения.
4. Успешное чтение, новый HTTP 503 и восстановление не скрывают ошибку изменения.

Тест использует настоящие чтения памяти, управляемые сетевые отказы и отклонённый
запрос записи. Модель синтетическая, платных вызовов нет. Другие сценарии Work,
планов, памяти и файлов входят в `playwright.work-progress.config.ts`.
До исправления новый сценарий воспроизводил предупреждение, оставшееся видимым
после успешного обновления. После исправления целевой сценарий проходит.

API и права не меняются. Записи не сохраняются и не повторяются автоматически.
Используются прежние кнопки, разметка и стили. Скрытая сквозная память и её отдельные
настройки этим исправлением не перерабатываются. Выкладка на VPS и живая приёмка
на ПК владельца остаются отдельными работами.
