# Koswork: чтение списков только в видимой вкладке

Списки работ с метаданными модели и списки планов больше не продолжают постоянный
опрос, пока документ скрыт. В видимой вкладке сохранены прежние интервалы:
750 мс для работ/модели и 1000 мс для планов. Возвращение вкладки, фокус и online
запрашивают свежий снимок сразу, не создавая параллельных циклов чтения.

Общий `startVisibleReadPolling` управляет только GET-чтениями этих панелей.
Выполнение агента, права, бюджет и управляющие команды не затрагиваются.
Начатое до скрытия чтение может завершиться. При завершении цикла отменяются
оставшиеся дочерние чтения, в том числе после раннего отказа `Promise.all`.
При смене проекта/выбранной работы и размонтировании отменяется запрос,
удаляются обработчики и таймеры; поздняя ошибка не попадает в новую панель.

Прежние проверки версии, epoch и блокировки пользовательских изменений сохранены
в обоих компонентах. Ошибки чтения показывают прежние сообщения. JSX, стили,
частота активной работы и серверное выполнение не меняются. Остальные запросы
приложения не объявляются остановленными; экономия токенов модели не заявляется.

## Проверки

- Четыре теста таймеров/событий: частота, скрытие/возврат, отсутствие пересечения,
  отказ чтения, отмена оставшегося транспорта, очистка и поздняя ошибка.
- Chromium с настоящими UI и HTTP/SQLite: прекращение чтений работ, модели,
  планов и runtime после скрытия; работа меняется и новый план создаётся на сервере;
  после возвращения интерфейс получает оба изменения.
- Сохраняются пять сценариев прогресса: стабильный снимок, временная ошибка,
  новая версия, возврат вкладки и объединение wake-событий.

Visibility и часы моделируются тестом; это не проверка скрытия нативного окна
Windows и не общий бенчмарк сервера. Реальная модель, VPS и устройство владельца
в этой поставке не используются.
