# Чтение локального хранилища агентом Koswork

Следующий согласованный блок после локальной папки PR #420: поиск и чтение
источников самим агентом, с отдельным нативным разрешением. Сервер и установка
на ноутбук владельца остаются отложенными. Multi-Agent не меняется.

## Рабочий сценарий

В окне общей задачи Koswork сначала подключить рабочую папку для результатов,
если нужна запись, затем нажать «Читать локальное хранилище». В нативном диалоге
подтверждается передача найденных имён/текстовых фрагментов серверу и модели для
задачи. Это дополнительное разрешение, выбранная ранее папка хранилища сама по
себе его не даёт. Начало задачи по-прежнему требует обычного подтверждения цели.

У общей файловой области появляется виртуальная папка `.kosmora-vault`, только
для чтения. Обычная рабочая папка остаётся доступной для отчётов и результатов.
Применяются уже существующие workspace_list / workspace_find / workspace_read,
без новых сетевых или произвольных файловых RPC. Перед каждым исполнением остаётся
серверная авторизация конкретного действия. Модель получает инструкции о чтении
по точным ссылкам и границах доверия только в режиме work.

Список источников содержит непрозрачный путь `.kosmora-vault/<SHA256>/<offset>`.
Поиск имени не раскрывает текст. Поиск содержимого возвращает ограниченные
выдержки и ссылку на близкий фрагмент. Чтение возвращает точный текст, имя и хеш,
UTF-16 начало/конец, полный размер в символах, excerpt_only и next_path.
Модель может прочитать следующую часть большого документа, вместо отправки всего
архива. Неполный JSON-фрагмент не считается целой разобранной записью памяти.
Цитата — недоверенные данные, а не системные инструкции или разрешения.

Никакого редактирования, восстановления, запуска или загрузки источника из этой
виртуальной области на сайт нет. Для вывода используются файлы обычной выбранной
рабочей папки. Название реального дискового каталога хранилища модели не передаётся.
В обычном режиме браузера/управления ПК кнопка не показывается и команда отвергается.

Обычные файловые инструменты также не открывают служебный каталог хранилища
через выбранную родительскую папку. Его нельзя подключить напрямую как рабочую
папку; каталог исключён из обхода и поиска, а доступ к его файлам по физическому
пути блокируется. Проверяется и канонический путь каталога.

## Срок действия и отзыв

Разрешение живёт только в памяти процесса, до окончания/ошибки/остановки задачи,
отзыва кнопкой или 30 минут от выдачи — что раньше. Оно не восстанавливается из
журнала или после перезапуска. Смена аккаунта/сервера и изменение подключения папки
прерывают доступ. Переподключение той же папки тоже меняет её revision.
Запоздавшее подтверждение после остановки не создаёт разрешение повторно.

Даже ошибка очистки драйвера не пропускает отзыв. Рабочая папка сохраняет своё
обычное разрешение; завершается только доступ к локальному хранилищу.
Восстановление прежней задачи, чья workspaceId включала такой временный доступ,
не поддерживает автоматическое переиспользование старого ID: требуется новая
задача с новым разрешением и повторной проверкой источников.

Файлы проверяются по хешу при чтении; повреждение/удаление не возвращает старый
кэшированный текст. Уже отправленные серверу/модели фрагменты отзыв обратно не
удаляет. Хранилище остаётся без шифрования оригиналов, как описано в PR #420.

## Пределы

Сохраняются ограничения исходного хранилища: до 500 файлов, 10 МиБ оригинал,
поиск текста до 1 МиБ на файл и 4 МиБ за проход. Тексты должны быть корректным
UTF-8 без NUL; бинарные оригиналы не распознаются. Список — 10 файлов на страницу;
поиск — до 8 результатов, запрос до 160 символов; ограниченность обозначается.
Фрагмент — до 6000 UTF-16 единиц с дополнительным пределом сериализованного ответа.
Суррогатные пары не разделяются. Слишком большой объединённый результат даёт
явную ошибку, без обрезания JSON. Доступен и поиск непосредственно по виртуальной
папке, если обычная рабочая папка даёт слишком много результатов.

Выбор папки обычных файлов после выдачи доступа к хранилищу отзывает это временное
разрешение; порядок подключения указан в диалоге. `.kosmora-vault` зарезервировано
в виртуальном файловом интерфейсе. Самостоятельная синхронизация с серверной
памятью, Google Drive и семантический поиск не входят в этот блок.

## Проверки

Реальные временные папки: исходные числа/исключения, одновременная запись отдельного
отчёта, запрет записи/загрузки хранилища, отзыв и срок, поздние диалоги, смена папки,
чужой аккаунт, удаление/бинарный источник и traversal. Большой текст с emoji
собирается из последовательных фрагментов в исходные байты текста без потерь.

Тестовый ComputerSession с настоящими файловыми адаптерами проходит план → поиск
→ чтение → создание отчёта → контрольное чтение → проверку критерия. Ни экран,
ни браузерная среда для такого сценария не запрашиваются. Планировщик — fixture;
это не оценка качества живой модели. Нативное окно отдельно проверяет границу
главного фрейма и отсутствие команды в обычном браузерном режиме.

Chromium/CDP smoke проверяет кнопки выдачи/отзыва и прежние функции браузера.
Локально прошли 196 тестов Windows-клиента и сборка API. Целевые 42 проверки
computer-control и проверка типов API также пройдены без живых запросов модели.
Windows CI предыдущего PR #420 собрал NSIS, но упал позже в packaged GUI fixture
на отсутствии result.txt при сценарии загрузки. Это пока не доказанное исправление
установщика: добавлены отдельные стадии диагностики verify-download/unified-work,
чтобы следующая проверка указала точное место. Не скрываем сбой ретраями или
ослаблением проверки фактических байтов. Живая приёмка на ПК владельца отложена.
