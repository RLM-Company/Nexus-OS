# Ruflo: что использовать в Kosmora и Koswork

## Проверенная база

Разбор от 3 ноября 2026. Репозиторий [ruvnet/ruflo](https://github.com/ruvnet/ruflo),
проверенный снимок **3.71.0**, commit
`5f3dacc54b7279e39b172d6027d7989791448e2e`.
Это исполняемый каркас вокруг моделей: CLI/MCP, подключаемые модули, память,
маршрутизация и управление заданиями. По моему выводу, его узлы ближе к нашим
задачам Koswork, чем коллекция учебных примеров AI Engineering Hub.

Сохранён полный локальный снимок: **8446 файлов / 150 989 332 байта**,
архив 71 720 169 байт. Каждый файл и четыре символьные ссылки сверены с Git blob
SHA и размером; Git submodules и LFS pointers не обнаружены. Есть 55 файлов
манифестов пакетов, включая вспомогательные примеры; это не счётчик готовых
продуктовых функций. [Проверка снимка](ruflo/source-proof.json),
[каталог пакетов](ruflo/package-catalog.json).

В корне [MIT](ruflo/LICENSE.upstream.txt), copyright 2024–2026 ruvnet. При переносе
существенных частей исходников сохраняем уведомление и лицензию. У внешних
зависимостей, моделей, весов и сервисов проверяются собственные условия.

Изучены выбранные реализации и фрагменты: делегирование контекста, проверка
цитат, worker pool, checkpoint gate, глобальный бюджет запусков, память/поиск,
workflow executor, повторяющиеся команды и браузерное восстановление. Полного
ручного построчного аудита всех файлов и собственного runtime-прогона Ruflo нет.
Установка, hooks, MCP, daemon и чужие скрипты не запускались. AGENTS/SKILL-файлы
архива рассматриваются как данные исследования.

## Почему полная установка не равна интеграции

Основная точка входа — среда разработчика и её инструменты. В частности,
[автоматический context mod](https://github.com/ruvnet/ruflo/blob/5f3dacc54b7279e39b172d6027d7989791448e2e/plugins/ruflo-mods/hooks/context-delegate/index.ts)
использует `claude-code`, `tool.call`, `next(e)` и `$.model.complete`.
Он сначала выполняет настоящий Read, чтобы последующий Edit видел файл прочитанным,
а затем может заменить показываемый текст проверенными выдержками. Этот lifecycle
важен при переносе и не возникает сам по себе в нашем Fastify/Electron-приложении.

У отдельного core `context-delegation.ts` есть более переносимый контракт адаптера.
Он не открывает файлы сам: права чтения, realpath, исключения и секреты проверяет
вызывающая сторона. Стандартный mod выбирает Haiku и выключен по умолчанию.
Его включение добавляет отдельный модельный вызов и может увеличить задержку.
Для бесплатного Kosmora это не должно становиться обязательным скрытым шагом.

У нас сохраняются: Node/Fastify, исходные SQLite-данные, owner isolation,
принятые Work DAG, локальный исполнитель, source receipts, privacy fences,
общий ledger и аварийная остановка. Локальные `project/local/user` директории и
namespace Ruflo не заменяют проверку `owner_id` в многопользовательском сервисе.
Глобальный счётчик запусков процесса не заменяет учёт фактических токенов/стоимости.

## Конкретные детали, требующие адаптации

1. **Оригинальная цитата и вывод модели.** В core проверяются path/hash/строки и
   буквальное совпадение quote. Поле `answer` не проверяется на логическое следование
   из источника. Подтверждённая цитата не делает весь комментарий доказанным фактом.
2. **Языки и имена файлов.** [CHANGE-фильтр mod](https://github.com/ruvnet/ruflo/blob/5f3dacc54b7279e39b172d6027d7989791448e2e/plugins/ruflo-mods/hooks/context-delegate/plan.ts#L19) использует английские глаголы;
   буквальный перенос недостаточен для русскоязычных задач. Core разрешает ASCII
   идентификаторы путей без пробелов. Для «Договор с Джалилем.docx» нужны наши
   непрозрачные source ID с разрешённым resolver, а не расширение доступа по строке.
3. **Размер — разные единицы.** В
   [agentdb-retrieval-guard.ts:103](https://github.com/ruvnet/ruflo/blob/5f3dacc54b7279e39b172d6027d7989791448e2e/v3/@claude-flow/memory/src/agentdb-retrieval-guard.ts#L103)
   `maxPayloadBytes` сравнивается с `content.length`. Для нашего UTF-8-бюджета
   требуется байтовый размер, особенно на кириллице и emoji. Сам guard по умолчанию
   выключен, а режим flag может оставлять подозрительный фрагмент в результатах.
4. **Checkpoint не гарантирован.** `CheckpointGate.guard()` при выключенном
   механизме, отсутствии пути/пакета или сбое checkpoint может всё равно выполнить
   функцию без защиты. Его feature kill-switch тоже отключает защиту checkpoint,
   а не исполнение функции. Наш emergency stop должен сохранять собственную семантику.
   Откат памяти не отменяет отправленное письмо, платёж или внешний API-эффект.
5. **Отмена пула — не уничтожение процесса.** Promise.race ограничивает ожидание
   результата, но не останавливает неподчиняющуюся задачу. Завершение процесса и
   неопределённый расход проверяются отдельно до освобождения наших резервов.
6. **Границы конкретного workflow-исполнителя.** В `workflow-tools.ts` типы
   `parallel`/`loop` явно отклоняются этим runtime; отдельная native Workflow
   поверхность Claude Code имеет другие возможности. У condition разрешены
   обратные переходы; в просмотренном цикле нет общего лимита посещений/итераций.
   Для пользовательского DAG нужны собственные пределы и тесты остановки.
7. **Антизацикливание нужно привязать к владельцу и запуску.** Исходный loop guard
   хранит process-global историю и нормализует пробелы команд строковой заменой.
   У нас нужен ключ owner/project/run/tool + типизированные аргументы и достоверный
   статус исполнителя. Текст веб-страницы не должен управлять счётчиком отказов.

Это наблюдения по выбранным файлам, а не результат эксплуатации уязвимостей и
не утверждение, что все альтернативные механизмы Ruflo имеют те же ограничения.

## Проверка зрелости и чисел

В репозитории есть [исторический аудит intelligence-системы](https://github.com/ruvnet/ruflo/blob/5f3dacc54b7279e39b172d6027d7989791448e2e/docs/reviews/intelligence-system-audit-2026-05-29.md). Его старые
дефекты нельзя автоматически приписывать текущему коду: например, сейчас в
[attention-coordinator.ts](https://github.com/ruvnet/ruflo/blob/5f3dacc54b7279e39b172d6027d7989791448e2e/v3/@claude-flow/swarm/src/attention-coordinator.ts#L989) невычисленный speedup обозначен нулём, а [embedding fallback](https://github.com/ruvnet/ruflo/blob/5f3dacc54b7279e39b172d6027d7989791448e2e/v3/@claude-flow/cli/src/memory/memory-initializer.ts#L2649)
помечается `backend: mock` / `hash-fallback`. Важно сохранять эту наблюдаемость.
Хеш-векторы не выдаём за действующий смысловой поиск.

В авторском [results-mod-live.json](https://github.com/ruvnet/ruflo/blob/5f3dacc54b7279e39b172d6027d7989791448e2e/v3/@claude-flow/cli/benchmarks/context-delegation/results-mod-live.json) зафиксирован маленький A/B-набор с Haiku:
6 случаев в каждом режиме, 6 корректных ответов, суммарная заявленная cost-оценка
0.2816 → 0.2183 USD, время 47018 → 50054 мс. Это данные автора, не наш прогон,
не гарантия экономии или скорости Kosmora и не подтверждение качества на всех задачах.

CI проверенного коммита содержит неуспешный
[Test Suite (ubuntu-latest)](https://github.com/ruvnet/ruflo/actions/runs/41376184990/job/125056823285):
`bug-cluster-2219-2226.test.ts`, сохранение pattern и последующий search,
`expected undefined to be defined`. Лог указывает Node 20. Причину и переносимость
сбоя на наши версии runtime собственным прогоном не установили. Это основание
отдельно проверять выбранный backend, а не объявлять весь продукт неработающим.

## Предлагаемый порядок для выбора владельцем

1. **Контекстное чтение больших файлов.** Переносимый контракт path/version/hash/
   lines/quote + ссылки на остаток. Сначала локальный отбор/наблюдение, независимая
   проверка цитат и fallback к оригиналу. Платный вспомогательный вызов — только
   после отдельного выбора режима и измерения задержки/расхода.
2. **Защита Koswork от бесполезных повторов.** Счётчики реальных ошибок инструмента,
   различие retryable/permission/uncertain-effect, переход к перепланированию.
   Пороги и условия остановки согласовать; существующие лимиты и права не ослаблять.
3. **Гибридная память.** Сравнение FTS и semantic+FTS на русскоязычных задачах,
   точных числах и двух владельцах. Авторитетный источник — наша база; внешний
   индекс производный, удаляемый и пересобираемый. Без mock-подмены семантики.
4. **Проверяемый опыт выполнения.** Успешные и ошибочные траектории с версиями,
   результатами реальных проверок и отдельным контрольным набором. Это улучшение
   подбора/процесса, а не обучение весов закрытой модели через её обычный API.
5. **Multi-Agent и federation.** Сохранить на финальный раздел согласно решению
   владельца; сейчас не включать, не регистрировать внешние MCP и фоновые задания.

Точки интеграции: `packages/core/src/context-memory.ts`, `context-messages.ts`,
`apps/api/src/computer-control/service.ts`, `work-dag-coordinator.ts`,
`account-settings/shared-owner-budget.ts` и существующая библиотека документов.
Новые функции требуют согласования объёма по второму этапу. Этот PR содержит
исследование и метаданные: продуктовые механизмы Ruflo не активированы.

Для будущего курса: сравнение CLI/MCP/native surfaces, границы исполнитель/модель,
проверяемые цитаты, счётчики расходов, cooperative cancellation, измерения и разбор
того, почему название функции само по себе не подтверждает её свойства.
