# Локальный semantic encoder: выбор и проверка

Дата: 3 ноября 2026. Объём согласован в плане Ruflo/Gemini: настоящий encoder,
гибридный поиск и проверка на наших сценариях. Интерфейс и права не расширяются.

## Использованная основа

- [Multilingual E5 small, исходная карточка](https://huggingface.co/intfloat/multilingual-e5-small/blob/614241f622f53c4eeff9890bdc4f31cfecc418b3/README.md).
  Авторы: Liang Wang, Nan Yang, Xiaolong Huang, Linjun Yang, Rangan Majumder,
  Furu Wei; Microsoft. Карточка декларирует MIT. В отдельный репозиторий
  Kosmora веса не копируются. Сохраняем ссылку и атрибуцию исходного материала.
- [ONNX-конверсия Xenova](https://huggingface.co/Xenova/multilingual-e5-small/tree/761b726dd34fb83930e26aab4e9ac3899aa1fa78).
  Зафиксированы revision и SHA256 всех четырёх используемых файлов, включая
  tokenizer и q8 ONNX. Манифест — в API. Основная модель: 118 308 185 байт;
  весь необходимый комплект: 135 392 016 байт. Скачивание — отдельная явная
  команда оператора; API никогда не догружает модель во время запроса.
- [Transformers.js](https://github.com/huggingface/transformers.js), пакет
  `@huggingface/transformers` **4.3.2**, Apache-2.0; transitive runtime/версии
  сохранены в lockfile. Пакеты сохраняют собственные LICENSE/notice.
  [Официальное локальное использование](https://huggingface.co/docs/transformers.js/custom_usage).

Из исходной карточки применяется рецепт query/passages с английскими префиксами
`query: ` и `passage: `, даже для русского текста; masked mean pooling,
L2-нормализация и cosine, 384 измерения, максимум 512 токенов модели.
Wrapper, ограничение конкурентности, проверка источников и интеграция — наш код.
Это обученная модель, а не хеширование слов. Hash остаётся идентификатором
версии/байтов и не заменяет embedding.

E5 small выбран для первого CPU-пути без GPU и удалённой передачи текста.
Более крупные модели, reranker, HNSW и постоянный vector index не добавлены:
сначала проверяем пользу в действующем scoped recall. Проектные механизмы
Ruflo и архивные pseudo-semantic модули не подключаются параллельно.

## Замороженный набор

16 независимых синтетических источников, 22 RU/EN-запроса: перефразирование,
запросы на другом языке, числа, исключения и 6 буквальных контрольных запросов.
Набор зафиксирован коммитом `7ccdffa3` до первого измерения. Форматирование
после этого меняло только whitespace. SHA256 канонического JSON:
`446192b2b1a6d58e82bd70d142d4bd79e4ac0afd0a87474a4d51788433821249`.
Коэффициенты RRF/пороги не подгонялись под результаты.

Первый измеренный прогон с реальными q8-весами, Windows, Node 26.13.0:

| Метрика                           | Только lexical | Гибрид |
| --------------------------------- | -------------: | -----: |
| Нужный источник первым            |           6/22 |  17/22 |
| Нужный источник среди первых трёх |           6/22 |  20/22 |
| MRR                               |         0.2727 | 0.8447 |

Медиана semantic recall — 86.8 мс, p95 — 119.6 мс; загрузка encoder около 4.0 с.
Снимок RSS процесса после прогона — 323.2 MiB. Это не пик потребления и не
скорость всей модели/чата. Небольшой набор не измеряет качество всех сценариев
и не доказывает превосходства над другими сервисами. Сырые результаты:
[JSON](semantic-memory-evaluation-20261103.json).

Два промаха в top-3 сохранены: доступ сотрудников к пилоту и работа без мыши
при английском вопросе к русскому источнику. Нет заявления «помнит всё».

Отдельный прогон **скомпилированного worker** с 96 фрагментами по 600 UTF-16
единиц: 3 302 мс, снимок RSS 463.7 MiB. Второй одновременный запрос отклонён
для lexical fallback. Это один замер на ноутбуке, не SLA и не нагрузочный тест
нескольких пользователей. Ограничение V8 256 MiB не ограничивает native память
ONNX; настройки потоков — не квота ресурсов ОС.

Воспроизведение без платной модели:

```sh
node scripts/install-semantic-memory-model.mjs /absolute/path/to/model
pnpm --filter @cosmora/api exec node --import tsx --conditions=development ../../scripts/bench-semantic-memory.mjs /absolute/path/to/model /absolute/path/to/result.json
```

Структурные/permission-тесты используют явно обозначенные fixture scores.
Они не подменяют этот прогон настоящего encoder и не считаются тестом интеллекта.
