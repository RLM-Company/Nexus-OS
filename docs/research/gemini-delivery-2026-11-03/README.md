# Проверка поставки Gemini за 1–3 ноября 2026

## Получено и сохранено

Проверены доступные на Google Диске документы с 1 ноября по московскому времени.
Первоначально найдены восемь отчётов за 2–3 ноября; после уточнения владелец передал
[единый ZIP](https://drive.google.com/file/d/1eg3BqZacKW2erWc_whqB4rUXyj6LFDEe/view).

Архив `kosmora-complete-3days-all-in-one-package.zip`: **1 173 642 байта**, SHA256
`13f533f3c1edc75517d4bb110cd7515e953a98aecbb215e9f9e1470051aa3859`.
Внутри 235 файлов, 3 714 154 распакованных байта. Все 202 позиции авторского
манифеста совпали по размеру и объявленному префиксу SHA256. Пути проверены до
распаковки; выходы из каталога, коллизии имён и симлинки не обнаружены.

Полное исходное содержимое сохранено в
[reference/gemini-complete-20261103](https://github.com/RLM-Company/Nexus-OS/tree/reference/gemini-complete-20261103).
Исходный снимок: `3d73ccb1822fbb14566804cf0d2584b539e37ce1`; SHA256 содержимого
**всех 235 Git-blobs** совпал с ZIP. Снимок включает авторские push-скрипты как
материал поставки; эти скрипты не запускались. Его нельзя сливать поверх продукта
как полный репозиторий: 24 файла пересекаются с актуальной базой `1443d644`.

Восемь Google Docs сохранены в `source-reports/*.txt` с нормализацией CRLF → LF;
контрольные суммы и время источников — в `manifest.json`. Это исходные заявления
автора, включая заявления о готовности, а не результаты нашей приёмки.

## Проверки

- TypeScript разобрал синтаксис 170 JS/TS-файлов без ошибок. Это не typecheck
  всей поставки и не доказательство подключения функций к продукту.
- Проверки известных форматов ключей не дали совпадений, включая шесть
  декодированных payload из shell-скриптов. Это не гарантия отсутствия любого
  возможного секрета или полный аудит безопасности.
- В отдельно распакованном архиве прошли 19/25 компонентных запусков. Шесть
  требовали базовые файлы проекта, которых нет в патч-поставке.
- После дополнения базой `1443d644` **все 25 поставленных компонентных запусков
  прошли**. Один первоначально заблокировало ограничение тестового окружения на
  запуск Git; повтор прошёл с разрешёнными read-only командами. Сеть и платные
  модели при проверке не использовались. Рабочий репозиторий не заменялся этим
  реконструированным деревом.
- Приёмка адаптации отдельно: **225 desktop-тестов и 56 API-тестов**, сборка
  contracts, API typecheck и ESLint. Три формата прочитаны независимыми
  python-docx, openpyxl и python-pptx; дополнительно проверены ZIP CRC, XML,
  внутренние связи, текст, числовые ячейки и типы формул.

Компонентные тесты поставки транспилируют выбранные файлы и используют фикстуры.
Их успешность не означает завершённую миграцию, живое управление ПК, реальные
провайдерные benchmarks или готовность каждого заявленного раздела.

## Встроенный блок

В текущий локальный исполнитель подключены `workspace_create_docx`,
`workspace_create_xlsx` и `workspace_create_pptx`. За основу взяты генераторы
OpenXML из поставки; код переработан под действующие контракты и выбранную папку.

- Создаётся настоящий бинарный документ без Word/Excel/PowerPoint и shell.
- Запись проходит существующие owner/folder/cancellation проверки, нативное
  подтверждение, exclusive create и проверку хеша записанного файла.
- Существующий файл не перезаписывается; неизвестный результат записи не
  повторяется автоматически. Vault остаётся пространством чтения.
- Модель и клиент согласуют поддержку; старый клиент/API сохраняет прежний
  формат обмена. Новые инструкции не добавляются без этой возможности.
- XML-данные экранируются, некорректные символы отклоняются. Ввод документа
  ограничен 24 000 сериализованных UTF-8 байт. Бюджет вывода native-запроса при
  объявленной поддержке документов — не более 6000 токенов и не выше профиля;
  для старого режима остаётся 2000. Общие бюджеты и учёт расхода сохранены.
- Строки Excel с `=` остаются текстом. Формулы задаются отдельным объектом;
  поддержаны только SUM/AVERAGE/MIN/MAX/COUNT по локальным ячейкам и диапазонам.
  Внешних ссылок, DDE, макросов и автоматически загружаемых объектов нет.
- В PowerPoint добавлены размеры и позиции текста, layout/master/theme-связи
  и автоуменьшение текста. В исходнике пустой `spPr` не задавал размер текста.

Нет скрытого утверждения о проверке содержимого в настоящем Microsoft Office:
проверены независимые читатели и реальные временные файлы с тестовым планировщиком.
Живая Windows-приёмка на устройстве владельца остаётся отложенной.

### Два подтверждённых ограничения исходников

`dense-vector-semantic-search.ts` строит вектор хешированием n-грамм,
псевдослучайной проекцией и восемью ручными группами синонимов. Это лексическая
аппроксимация, без обученного multilingual encoder. Его скорость не доказывает
скорость или качество нейросетевой семантической памяти.

`ast-code-sandbox-verifier.ts` проверяет regex, затем запускает выражение в
`node:vm`. Он не реализует AST security boundary. Node прямо исключает применение
этого модуля как механизма безопасности для недоверенного кода.
[Официальная документация Node.js](https://nodejs.org/api/vm.html#vm-executing-javascript).
Действующая изоляция Code сохранена.

Все исходники поставки доступны для дальнейших адаптаций. Статус reference
означает сохранение и проверку кандидата, а не готовую функцию в активном сервисе.
На VPS этот пакет не выкладывался; рабочие службы и Windows-бинарник не заменялись.
