# Семантическая оценка содержимого (фикстура v2, must_keep_semantics)

**Статус**: measurement-only прогон №3 по этой фикстуре выполнен 2026-11-11
(REPORT: `experience-llm-distill-semantics-2026-11-10-report.json`); решение о
внедрении — за владельцем.

## Что это

`packages/db/test/fixtures/semantic-experience-distill-semantics-evaluation.json`
— 4 кейса к занятию «Опыт выполнения» (Ruflo adoption), в которых семантически
критичны условия, отрицания и причинные правила, а не только имена файлов:

- `conditional-anchors-all-safe` — операционные условия («только по активным
  договорам», «не раньше 09:00») должны пережить краткую переформулировку;
- `negation-must-not-flip` — запрет «блокируются до проверки юристом»;
  ловушка-«перевёртыш» `после проверки юристом` внесена в `forbidden_literals`;
- `stale-plus-causal-core` — три устаревших шага (путь, координаты, почта)
  должнывыпадать, а причинное правило («только при двойном клике / одиночный
  клик безопасен») — выжить;
- `long-condition-declared-lost` — длинное числовое условие объявлено
  «вероятно-потерянным» (`relevant_literals_declared_lost`), измеряется его
  дословное восстановление.

## Контракт

- Схема и метрики — как у v1 (`scripts/bench-experience-llm-distill.mjs`);
  новый код измерения не нужен, нужен только выбор фикстуры.
- Отличие от v1, зафиксированное в `purpose` фикстуры: ловушки-«перевёртыши»
  намеренно НЕ входят в исходный пример. Их появление в ответе означает, что
  модель сама инвертировала смысл (в v1 `forbidden_literals` всегда лежали
  внутри исходника как устаревшие улики).
- Нюанс, унаследованный от v1: литералы с обратными слешами проверяются по
  первичному тексту escaped-JSON; основные семантические якоря v2 — текстовые
  фразы без слешей, на них нюанс не влияет.

## Как измерять (после завершения прогона №2)

1. Добавить флаг `--fixture <путь>` (переопределение `REPORT_HELPERS.fixturePath`,
   по умолчанию v1) отдельным сводным коммитом на desc-ветке — bench меняется
   только когда прогон №2 завершён.
2. Прогон №3: как обычный полный прогон (лить модель, манифест дайджестов,
   отдельный отчёт `docs/research/experience-llm-distill-semantics-2026-11-10-report.json`),
   RESUME-чекпойнты работают без изменений.
3. Сравнение с прогоном №1 — только по общим метрикам (`relevant_carried_strong`,
   `forbidden_carried`, `stale_step_leak`, `reduction`, `parse_ok`,
   `deterministic_pairs`). Это НЕ воспроизведение прогона №1: другая фикстура,
   другой `fixture_sha256`; база по семантическим якорям создаётся самим
   прогоном №3.
4. Границы прежние: весов в репозитории нет, сети нет (worker), bench вне CI,
   отчёты коммитятся только с реальными числами, merge/внедрение — решение
   владельца.
