# B0.2 review: runtime routing and atomic Usage Ledger

**Date:** 2026-08-25
**Status:** CANDIDATE / CI PENDING

## Scope

- extend `ModelRequest` with explicit feature, confidentiality, context-estimate, budget, and
  optimization constraints;
- resolve every runtime provider attempt through the versioned Model Registry;
- bind adapter provider/model identity exactly to the selected route;
- validate completion identity and non-negative token counters before accounting;
- allow fallback only through another registry-approved route and only before provider text;
- reject malformed provider event sequences;
- persist each selected route as a Usage Ledger attempt;
- atomically commit resolved model, actual token usage, currency, and calculated cost with the
  successful run;
- terminally mark failed, cancelled, and restart-interrupted attempts;
- expose the secret-free registry version in model runtime status.

## Safety properties

1. A configured external provider absent from the registry prevents API startup.
2. A registry model without a matching adapter cannot execute.
3. Unknown privacy metadata cannot serve confidential requests.
4. Unknown pricing cannot serve hard-budget requests.
5. No provider detail is imported by the web application.
6. Credentials remain outside registry, ledger, API responses, and logs.
7. A run cannot report success if its final ledger reservation cannot commit atomically.
8. Provider-reported identity or usage that contradicts the selected route fails closed.
