# Kosmora Pay — собственный биллинг Kosmora, этап 1

Задача: принимать **подписки Kosmora**, не создавать платёжную организацию для сторонних продавцов.

## Реализовано

- SQLite-модели заказов и append-only журнал событий платежа.
- Все суммы в **целых копейках**; RUB. Идемпотентность внутри Kosmora по ключу заказчика + отдельный стабильный UUID заказа для ЮKassa.
- `YooKassaGateway` — реальный HTTP Basic Auth, Redirect Checkout, проверка платежа серверным GET. Ключи не хранятся в базе.
- Серверный каталог тарифов. Клиент не выбирает произвольную сумму.
- Защищённые маршруты текущего owner API: создание заказа, просмотр заказов, просмотр подтверждённой валовой выручки, запрос актуального статуса в ЮKassa.
- Заказ не получает статус `succeeded` по ответу браузера: только после серверной проверки совпадения идентификатора, суммы, валюты и признака paid.
- Если платёжный провайдер не настроен, **никаких списаний нет**, API возвращает 503.
- Ошибки проверяются; в логи не пишем тело ответа банка или секреты.

## API

`GET /api/v1/pay/summary` — сводка **подтверждённых оплат** (не прибыль и не баланс банка!).

`GET /api/v1/pay/orders?limit=50` — заказы текущего владельца.

`POST /api/v1/pay/checkout` с заголовком `Idempotency-Key: <12-64 chars>`:

```json
{ "customer_ref": "internal-user-001", "plan_code": "pro" }
```

Возвращает заказ `pending` и ссылку `confirmation_url` от ЮKassa.

`POST /api/v1/pay/orders/:orderId/verify` — проверяет оплату повторным запросом к ЮKassa.

**Важно:** сейчас эти маршруты доступны только верифицированному владельцу через общий owner API. Публичный пользовательский checkout пока не подключён — нужен отдельный пользовательский auth, защита от спама и управление возвратами. Не рекламировать как полностью запущенную оплату подписок.

## Конфигурация

Не добавляйте секреты в GitHub. Для реального включения нужны секреты и договор эквайринга:

```ini
KOSMORA_PAY_ENABLED=true
YOOKASSA_SHOP_ID=<merchant-shop-id>
YOOKASSA_SECRET_KEY=<secret-from-merchant-cabinet>
KOSMORA_PAY_RETURN_URL=https://your-owned-domain.example/pay/return
KOSMORA_PAY_PLANS_JSON={"pro":99000}
```

99000 коп. = 990 руб. — **только пример формата**, не утверждённая стоимость тарифа. Не включайте `KOSMORA_PAY_ENABLED` без оформления получателя платежей и способа исполнения 54-ФЗ (онлайн-чеки).

## Что ещё не реализовано

- Подписки с периодическим списанием и полноценные права доступа после оплаты (entitlements).
- Пользовательские аккаунты, пользовательский checkout, callback/webhook и периодический worker сверки.
- Возвраты, отмены, споры, комиссия эквайринга, банковские выписки, проверка поступлений на расчётный счёт, налоговая отчётность.
- Фискализация по 54-ФЗ: её необходимо согласовать с конкретным провайдером и юридическим получателем платежей до продаж.
- `succeeded_gross_minor` — валовая сумма **без вычета возвратов**, **не показатель поступления на расчётный счёт**. Для финансовой защиты сооснователей обязательны отдельные договорённости о доступе к выпискам и праве на отчётность.

Это реальный компонент, но **не завершённый production платёжный сервис**. Никаких скрытых финансовых блокировок, перехвата средств и прав на чужие счета нет.
