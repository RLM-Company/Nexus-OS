Конкретные задачи для разных бизнесов добавлены в
[бизнес-каталог из 72 сценариев](KOSWORK_BUSINESS_FUNCTIONS_BACKLOG_RU.md).

## Решение владельца и границы

Владелец запросил нишевые специализации, воспроизведение речевого стиля и поведения,
сохранение стиля и широкий набор полезных функций для разных профессиональных задач.
Это согласованное направление продукта, а не свидетельство готовности перечисленных
функций. Первый набор, сценарии и существенные продуктовые решения согласовываем
с владельцем перед реализацией. Multi-Agent остаётся последним; специализации могут
работать в рамках одного агента. Изменений UI, runtime и платных запросов этот документ
не выполняет и не подразумевает.

## Предлагаемая структура специализации

Каждая специализация задаёт:

1. Конкретную задачу и границы компетенции.
2. Необходимые исходные материалы и уточнения.
3. Рабочую процедуру, инструменты и допустимые действия.
4. Формат результата: файл, правку, расчёт или действие в подключённой системе.
5. Критерии проверки, обработку неполных данных и ошибок.
6. Примеры и повторяемые задания для приёмки.

Общими остаются модель, локальный исполнитель, доступы, память, версии и учёт расхода.
Отдельная специализация не требует отдельной модели или параллельного агента.
Расширение каталога строится на этих механизмах; одного названия роли в промпте
недостаточно для заявления о рабочей профессиональной функции.

## Персональный стиль: кандидаты функций

| Функция                  | Ожидаемое поведение                                                                                                  |
| ------------------------ | -------------------------------------------------------------------------------------------------------------------- |
| Профиль по образцам      | Из выбранных пользователем текстов извлекаются тон, лексика, длина фраз, структура, пунктуация и характерные обороты |
| Разные стили             | Личный, деловой, публичный и отдельные профили проектов/клиентов выбираются независимо                               |
| Сохранение голоса        | При редактировании исправляются запрошенные проблемы с сохранением характерной манеры и смысла                       |
| Настройка силы адаптации | Можно сохранить лишь тон либо приблизить структуру и лексику к образцам; точную форму управления согласовать         |
| Рабочие привычки         | Предпочтения по подробности, формату результата, порядку работы и промежуточным отчётам                              |
| Обратная связь           | Исправления пользователя помогают уточнять профиль; сохраняемые правила видимы и управляемы                          |
| Стиль проекта/бренда     | Терминология, правила оформления, примеры и словарь применяются в выбранном проекте                                  |
| Проверка соответствия    | Итог проверяется по конкретным правилам профиля, а не получает выдуманный процент сходства                           |

Стилевой профиль — настройки и выбранные примеры в контексте, не автоматическое
дообучение весов модели. Он не разрешает выдумывать факты, цитаты, обещания или личный
опыт пользователя. Адаптация поведения означает рабочие предпочтения, а не скрытые
психологические выводы. Она не меняет права доступа и не увеличивает автономность.

Пользователь может просмотреть, исправить, отключить и удалить профиль вместе с
сохранёнными образцами. Материалы разных владельцев, клиентов и проектов не смешиваются
без явного выбора. Применение профиля прозрачно; сроки хранения и точную механику
обучения на исправлениях согласовать при разборе блока.

## Кандидаты нишевых пакетов

Это предложения каталога, не обещание одинаковой готовности во всех нишах.

| Направление                            | Пример полезного результата                                                         |
| -------------------------------------- | ----------------------------------------------------------------------------------- |
| Автор и редактор                       | Текст в выбранном стиле, правки с сохранением смысла, последовательная терминология |
| Маркетинг и контент                    | Материалы по брифу и правилам бренда, контент-план с готовыми черновиками           |
| Продажи и поддержка                    | Подготовленные ответы по базе продукта и истории обращения, без выдуманных условий  |
| Аналитика и таблицы                    | Проверяемые расчёты, формулы, отчёт с источниками и обозначенными допущениями       |
| Исследования                           | Сопоставление источников, ссылки, даты, противоречия и границы покрытия             |
| Учёба                                  | Объяснения по уровню, задания, проверка ответов и план повторения                   |
| Перевод и локализация                  | Перевод с терминологией проекта и сохранением структуры документа                   |
| Операционная работа                    | Обработка разрешённых файлов, сводки встреч, задачи и календарные действия          |
| Предприниматель и руководитель проекта | Планы, сравнение вариантов, реестр решений и обновляемые рабочие документы          |

Работу с репозиториями развиваем в Coscode по отдельному разбору раздела. Космора может
использовать согласованный лёгкий набор персонализации; доступность специализаций в
бесплатном режиме и их лимиты пока не определены.

## Предлагаемые критерии приёмки

- Для каждого пакета есть обычные, неполные и ошибочные входные данные.
- Проверяется фактическая корректность результата и сохранение требований пользователя.
- Для стиля используются также тексты, не входившие в образцы; сходство оценивается
  отдельно от правильности фактов и сохранения смысла.
- Проверяются выбор, отключение, изменение и удаление профиля, разделение проектов.
- Измеряются время, расход модели и объём необходимых ручных исправлений.
- Пакет считается рабочим после проверки законченных сценариев; количество пунктов
  каталога само по себе не является показателем готовности.

Предлагаемый первый сквозной сценарий: получить образцы пользователя и бриф, создать
редактируемый профиль, подготовить новый документ, принять правки и сохранить только
выбранные стилевые правила. Выбор этого сценария для реализации остаётся за владельцем.
