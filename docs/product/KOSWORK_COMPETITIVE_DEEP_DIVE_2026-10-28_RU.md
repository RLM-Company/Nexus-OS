# Koswork: подробная карта ChatGPT Work, Claude Cowork и Gemini Tasks

Проверено 28 октября 2026, Europe/Moscow. Документ для совместной продуктовой
проработки с владельцем. Он расширяет предыдущую укрупнённую таблицу, а не
утверждает весь перечисленный объём к реализации.

## 1. Метод и границы доказательств

Основание — 38 официальных страниц, каталог ссылок в конце. Часть официальных
OpenAI-страниц дополнительно сохранена в локальный исследовательский каталог
с датой и SHA-256. Публичные markdown-версии читались напрямую, поскольку
веб-инструмент не принимает их MIME. Недоступные адреса не считаются источниками.

Это документарная проверка. Платные задачи, испытания в аккаунтах конкурентов,
замеры скорости/стоимости и практическая проверка действий не выполнялись.
Доступность меняется по тарифу, платформе, региону, настройкам организации и rollout.
«Описано» не означает доступность в любом аккаунте; «не установлено» не означает
отсутствие функции. Внутренние закрытые алгоритмы провайдеров не реконструировались.

Сравниваем именно рабочие продукты. Возможность в API не переносится автоматически
в пользовательский интерфейс; функция Claude Code или Codex не приписывается
Cowork/Work без подтверждения. Смежные инструменты обозначены отдельно.
Multi-Agent исследован как факт рынка, но его реализация остаётся последней.

Уточнения, влияющие на архитектуру Koswork:

- Встроенный браузер Claude — самостоятельный профиль внутри desktop, а не
  универсальный облачный браузер, работающий независимо от компьютера пользователя.
  В нём сохраняются входы; есть выборочный импорт cookies с ограничениями по ОС/браузеру. [C2]
- У Gemini документированы локальный Chrome и удалённый браузер. Обычный просмотр
  страницы, действия через Chrome и доступ к папкам Mac — разные полномочия. [G1,G2,G12]
- На Windows локальный Computer Use ChatGPT занимает активный рабочий стол.
  Для независимой фоновой работы требуется другая среда; облачный браузер уже
  отделён от личного устройства. [O3,O4]
- У Work доступность cloud/local sync задаёт границы продолжения. Синхронизация
  беседы не равна загрузке всего диска, а переключение среды не гарантируется
  посреди текущего выполнения. [O1,O6]

Для обсуждения: Koswork нужны отдельные понятия «облачный компьютер», «браузер
агента», «разрешённый браузер пользователя» и «локальные приложения». Выбор одного
не должен незаметно давать остальные доступы.

Транзакционное восстановление и надёжность на конкретных сайтах требуют испытаний.

Предметный каталог Koswork предстоит согласовать по операциям:

- Почта: найти письмо, прочитать тред, подготовить черновик, отправить согласованное,
  работать с вложениями и метками.
- Календарь: прочитать события, проверить занятость, создать/изменить встречу и обработать ответ.
- Облачные файлы: найти, прочитать, создать, изменить, экспортировать, управлять доступом.
- Документы: редактировать конкретный раздел и комментарии; таблицы — диапазоны,
  формулы и графики; презентации — отдельные слайды.
- Рабочие системы: сообщения/треды, задачи, записи CRM, базы знаний.
- GitHub: доступ к выбранному репозиторию, issues, файлам, diff и проверкам;
  граница разработки с Coscode согласуется отдельно.

Google отдельно описывает действия с Gmail, Calendar, Docs, Sheets, Slides,
Drive, Keep и Tasks. [G1] Для остальных продуктов возможности конкретного сервиса
нельзя выводить только из факта наличия MCP. В матрице нашей интеграции должны
быть чтение/запись, права, тип аккаунта, платформы, подтверждения и ограничения.

Удалённый MCP, локальный MCP, расширение браузера и обычное подключение папки —
разные механизмы. У справок Claude есть отличающиеся описания локальных MCP
в разных поверхностях: поддержку нужно фиксировать для конкретного механизма,
а не обещать любой локальный сервер во всех режимах. [C4,C6]

## 5. Что реально означает «повышенный интеллект»

| Слой                      | Документированное наблюдение                                                                | Требование для обсуждения Koswork                                                     |
| ------------------------- | ------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| Выбор модели              | У всех трёх есть модели разной специализации/доступности [O2,C8,G3]                         | Выбирать реально подходящее ядро, проверяя доступность у провайдера                   |
| Глубина рассуждения       | Work: reasoning effort, в том числе Max [O2]                                                | Передавать поддерживаемый параметр, показывать влияние на задержку/расход             |
| Thinking и effort         | Claude описывает их отдельно; поведение зависит от модели [C8]                              | Не считать один ползунок универсальным API для всех моделей                           |
| Автоматический выбор      | Google описывает подбор модели и уровни thinking [G3]                                       | Автовыбор с понятной причиной, возможность зафиксировать профиль                      |
| Самая глубокая обработка  | Google сообщает о замене Deep Think на Argon [G4]                                           | Не закреплять в продукте устаревший набор режимов как вечный стандарт                 |
| Исследовательский процесс | Research использует последовательные поиски и источники [C10,G6]                            | Разделять глубокое исследование и просто длинный ответ                                |
| Планирование действий     | Рабочие продукты строят многократный процесс с инструментами [O1,C1,G1]                     | Учитывать наблюдения и ошибки при выборе следующего действия                          |
| Контекст и память         | Проекты/материалы/память — отдельные источники контекста [O6,C7,G10,G11]                    | Сохранять принятые решения, извлекать релевантное, отмечать потерю охвата             |
| Внешняя проверка          | Инструменты позволяют проверять расчёты и файлы; универсальная гарантия качества не описана | Для чисел — расчёт, для фактов — источник, для файла — проверка структуры/содержимого |
| Параллельные агенты       | Work Ultra связан с субагентами; у Cowork они также описаны [O2,C1]                         | Учесть в исследовании, реализацию отложить по решению владельца                       |

Рассуждение, самостоятельность, объём контекста, разрешения и число агентов —
разные измерения. Большая самостоятельность не доказывает больший интеллект.
Более высокий effort может помочь сложной задаче, но не гарантирует правильность
и обычно повышает время и расход. Рекламные оценки Google о превосходстве Argon
не считаются нашим независимым измерением.

Рекомендуемая схема одного агента для обсуждения: понять цель → извлечь материалы
и правила → построить план → выбрать инструмент → получить наблюдение → проверить
результат → скорректировать следующий шаг → завершить по критериям. Повторная
проверка может выполняться тем же агентом и не требует запуска Multi-Agent.
Показываем план, действия, доказательства и краткие пояснения; не обещаем раскрытие
всего внутреннего рассуждения модели.

## 9. Долгая работа и управление

Предметные функции для каталога Koswork:

1. Старт задачи с явными критериями результата.
2. Просмотр плана и результатов отдельных шагов.
3. Добавление указания во время выполнения.
4. Запрос недостающих данных без потери прогресса.
5. Передача управления браузером человеку и обратно.
6. Остановка текущего исполнения.
7. Пауза и последующее продолжение — семантика требует отдельной проверки.
8. Возврат к задаче на другом устройстве при поддерживаемом режиме.
9. Уведомление о результате или необходимом участии человека.
10. Сохранение файлов и выбор следующего уточнения.
11. Перенос выполнения между локальной и облачной средой — только по явным
    поддерживаемым правилам, с проверкой доступности ресурсов.
12. Работа с отказом инструмента, изменением страницы, истечением входа и расходом.

Наблюдения по конкурентам: steering/продолжение [O12,C1,G1]; управление с телефона
и голосом [O11,G2]; ограничения среды [O1,C2,G12]. Документация не доказывает
универсальный «точный рестарт после любого сбоя без повторной оплаты».
Наши checkpoints/бюджет из первого этапа нужно проверить на новых маршрутах.

Голосовая диктовка, озвучка ответа и голосовое управление работающим агентом —
три разные функции. Work Voice описывает запуск и корректировку задач; у Gemini
Mac remote есть голосовые команды. [O11,G2] Полный новый голосовой ассистент
и Jarvis остаются отдельной отложенной темой.

## 11. Доступы, контроль и ограничения

Это часть функционала агента, а не отдельная формальная анкета:

- Какие папки, сайты и аккаунты доступны именно этой задаче.
- Разница между чтением, черновиком, изменением, публикацией и удалением.
- Когда действует прежнее согласование пользователя, а когда требуется новое.
- Как отозвать конкретное подключение и очистить сессии.
- Как сайт/файл отделяется от инструкций пользователя: внешние данные не дают полномочий.
- Где находятся облачные и локальные копии, что остаётся после удаления задачи.
- Что пользователь может проверить до внешнего действия и как остановить исполнение.
- Как инструменты учитывают чужие права в исходном сервисе и организационные настройки.

Основания: [O3,O5,C4,C13,G8]. Общие ограничения подтверждены; эффективность защит
от prompt injection и надёжность конкретных реализаций в этой работе не тестировались.
Не обещать отмену необратимого действия, бесконечную автономность или доступ к
заблокированному сайту. Условия конкурентов не переносятся автоматически на Koswork.

## 12. Предлагаемая структура Koswork для обсуждения

Дополнительный организационный слой тоже входит в карту возможностей, хотя
не обязан становиться первой версией личного Koswork:

| Функция                        | Документированный пример                                                     |
| ------------------------------ | ---------------------------------------------------------------------------- |
| Совместные проекты             | Cowork Team/Enterprise: права просмотра/редактирования проекта [C7]          |
| Совместные результаты          | Артефакты с отдельным просмотром, редактированием, ссылкой и экспортом [C11] |
| Каталог команды                | Личные и организационные плагины/процедуры [O5,C5]                           |
| Управление доступными моделями | Организационные ограничения выбора модели/effort [C8]                        |
| Управление инструментами       | Разрешение/запрет подключения и отдельных возможностей [O5,C13]              |
| Задачи организации             | Team Tasks, служебные подключения и отдельные условия запуска [O8]           |

Из этого не следует автоматическое право публиковать командные данные или
раздавать доступ. Должны различаться личный аккаунт, проект, внешний сервис и
видимость результата. Наличие ссылки на файл не означает наличие совместного
редактирования и не заменяет проверку прав.

| Область               | Реальный результат для пользователя                                       |
| --------------------- | ------------------------------------------------------------------------- |
| Интеллект             | Выбор модели/глубины и подхода, сложные задачи с проверкой                |
| Контекст              | Проект, материалы, решения, поиск и управляемая память                    |
| Исполнение            | Изолированный компьютер, код и инструменты                                |
| Веб                   | Браузер агента, выбранные сайты, сессии и передача управления             |
| Локальное подключение | Разрешённые папки/приложения устройства, отдельные условия Windows/macOS  |
| Интеграции            | Конкретные операции в почте, документах, календаре и рабочих сервисах     |
| Результаты            | Готовые проверяемые файлы, native-изменения и интерактивные материалы     |
| Управление            | План, уточнения, прогресс, отмена, продолжение и история                  |
| Повторяемость         | Инструкции процедур, шаблоны, ручные/временные/событийные запуски         |
| Учёт                  | Фактические токены/суммы, неопределённый расход, бюджет и доступный объём |

Это функциональная группировка. Ни новые вкладки, ни переделка оболочки этим не
утверждаются. Текущие API, хранилища и исполнители сначала проверяются на повторное
использование. Kosmora остаётся самостоятельным экономичным бесплатным чатом;
доступность инструментов и конкретные квоты обсуждаются с владельцем.

## 13. Где искать собственное преимущество

Браузер, компьютер, MCP, память, skills, планирование, документы и расписания уже
есть на рынке. Точечная правка, интерактивные артефакты и проектная память также
не являются новой категорией функций. [O7,C7,C11,G5]

Гипотезы для Koswork, а не доказанное превосходство:

1. Согласованный режим работы: глубина, лимит, доступы и критерии результата
   сохраняются вместе с задачей и не требуют повторного объяснения на каждом шаге.
2. Память решений с происхождением: видно, какое требование утвердил человек,
   какие факты подтверждены источником, а что агент пока предполагает.
3. Понятный охват: какие страницы, файлы и строки действительно обработаны,
   что исключено, устарело или не удалось прочитать.
4. Связанные результаты: после изменения входа обновляются затронутые расчёты
   и разделы; зависимости и затраты на обновление можно проверить.
5. Восстановление с контролем расхода и внешних действий: сначала установить
   состояние уже отправленного запроса, затем предлагать продолжение. Если
   состояние выяснить невозможно, сохранить неизвестный исход и не повторять
   платное или внешнее действие автоматически.
6. Контекстный переход Kosmora → Koswork → Coscode/Studio по выбранной задаче,
   с передачей материалов и результатов вместо повторного объяснения.
7. Сопоставимые варианты выполнения с приблизительным расходом и ограничениями,
   а после работы — фактический результат и отчёт.

Нельзя утверждать, что ни один конкурент этого не делает. Проверять нужно удобство,
надёжность и совместную работу механизмов на одинаковых пользовательских задачах.

## 14. Что ещё требует практической проверки

| Проверка             | Что измерять                                                                                          |
| -------------------- | ----------------------------------------------------------------------------------------------------- |
| Сложное рассуждение  | Выполнение ограничений и правильность на проверяемых задачах при разных моделях/effort                |
| Длинные материалы    | Охват источников, точность ссылок, потеря решений и работа с противоречиями                           |
| Документы и таблицы  | Формулы, числа, формат, возможность редактирования и качество экспорта                                |
| Браузер              | Успешность реальных шагов, вход, ручная передача, загрузки, динамические страницы                     |
| Компьютер            | Работа на поддерживаемой ОС; точность действий, блокировка пользовательского ввода и доступность фона |
| Интеграции           | Реальный набор read/write операций, права, отказы и идемпотентность                                   |
| Долгая задача        | Уточнение в процессе, отмена, восстановление, вход с другого устройства                               |
| Автоматизация        | Точное поведение времени/события, отключённого компьютера и недоступного источника                    |
| Экономика и скорость | Время до полезного и окончательного результата, реальные токены и суммы, участие человека             |

Каждый прогон требует одинакового входа, доступа и критериев. Рекламная оценка
«самый умный» и скорость появления первого текста не заменяют приёмку результата.
Нужны и успешные, и ошибочные сценарии. Живые сравнения и реализация согласуются
отдельно; этот документ не запускает платные запросы или действия в аккаунтах.
