**Статус**: план без кода, подготовлен для решения владельца по очереди после
merge #532 (2026-11-11). Реализация любого варианта — только после явного
выбора владельцем; приёмка и merge — владелец. Все измерения уже в main
(measurement-only, прогон №1 + REPRODUCED №2, semantics №3).

## Факты: что уже в main

### Shipped-поток (продукт, не менялся measurement-линией)

- `buildWorkReference` (desktop/windows/work-experience.cjs) строит
  `koswork.accepted-example.v1` из локальной завершённой записи: excerpt цели
  ≤500 байт (+флаг `goal_excerpt_only`), полный checked-план (title+criteria),
  `tool_observations` (kinds+counts, ≤16), provenance, revision — sha256
  ИСХОДНОЙ записи (не зависит от обрезок вывода), весь артефакт ≤14 000 байт.
- Reference строится на лету в `history.reference()` на **каждый** запрос
  planner'а сессии (computer-session.cjs) — API (service.ts) фиксирует hash и
  требует тот же reference на всех следующих шагах (`COMPUTER_REFERENCE_CONFLICT`).
- Схема строгая (packages/contracts/src/computer-control.ts):
  `additionalProperties: false`, план `minItems: 1, maxItems: 8`, ≤14 000 байт,
  тот же project; маркера «частичного плана» в формате нет.
- Рамка промпта `WORK_REFERENCE_RULES` (service.ts): reference — недоверенные
  справочные данные; не наследовать checked-состояния, пути, получателей,
  реквизиты, координаты, старые ссылки и апрувы; текущая цель и гранты
  приоритетны. Защита от наследования «грязных» данных сегодня — **только
  промпт-рамка**, слой данных ничего не скрабит.

### Measurement (bench, вне CI, не продукт)

- **Детерминированный кандидат** `extractive-drop-candidate-v1` (в
  `scripts/bench-semantic-experience-distill.mjs`, прогон №1 на панели 13
  кейсов / 53 шага, REPRODUCED true бит-в-бит): скетч
  `koswork.example-sketch.v1` — префикс цели до устаревшей фразы (лимит 480),
  шаги целиком, kinds без counts, provenance; 7 запрещённых классов (пути/UNC,
  письма/@-хэндлы, реквизиты, координаты, даты/старые ссылки, апрувы) → шаг
  дропается целиком; бюджет скетча 5 000, упаковка останавливается. Медиана
  отношения скетч/вход 0,7935; запрещённых фрагментов перенесено **0/32**;
  переиспользуемые литералы 26/26; честные потери: co-location (шаг с чистым
  текстом + путь → дропается вместе с чистым) и хвост бюджета.
- **LLM-кандидат** `llm-drop-candidate-v1` (Qwen2.5-0.5B q4, весов в репо нет,
  сеть выключена в worker, greedy): прогон №2 REPRODUCED true (13/13);
  прогон №3 (semantics-панель 4 кейса): честные числа — parse_ok 3/4,
  детерминизм 4/4, запрещённых перенесено **2** (даты «01.11»/«08.11» в одном
  кейсе), relevant 11/14, восстановлено declared-lost 2/3, выдуманных
  файл-токенов 0, stale-leak 4, сокращение **1** (не сжимает: 1 130–1 228 байт
  на кейс), ~9–14 мин/кейс на CPU (win32, transformers.js 4.3.2, RSS ~71 MiB).

## Ключевой вывод измерений

Детерминированный кандидат готов как механизм «предотвращения загрязнения с
ограниченным скетчем»: переносит всё переиспользуемое буквально-байтно и ни
одного запрещённого фрагмента, ценой co-location дропов и хвоста бюджета.
LLM-кандидат как продукт **не готов**: не сжимает (сокращение 1), один раз
перенёс запрещённые литералы, один раз не спарсил JSON, дорог на CPU; его
единственное уникальное умение — переписывание (восстановление со-локализованного
чистого текста). Продукт-ценность дистилляции существует в двух местах: то,
что видит модель (reference ходит в каждом запросе сессии), и хранимый
компактный след (фундамент будущих память/история-функций). Оба лежат за
пределами «чистого» desktop/windows-среза — выбор варианта за владельцем.

## Варианты

### A. Скраб внутри текущего формата (только desktop/windows)

`buildWorkReference` применяет дроп-логику кандидата к выдаваемому reference:
префикс цели до устаревшей фразы (кап 500 сохраняется, флаг excerpt — как
сейчас), план без шагов, содержащих любой из 7 запрещённых классов.
`tool_observations` не трогаем (counts остаются; рамка уже фиксирует их
семантику). Формат, revision (хэш исходной записи), схема и API — без
изменений: план ≥1 шага остаётся валидным; если запрещённые классы есть во
всех шагах — честный отказ (`COMPUTER_REFERENCE_UNAVAILABLE`), владелец видит
его при выборе примера.

- Плюсы: ни одного изменения за пределами desktop/windows (схема strict, но
  полный план не обязателен — `minItems: 1`); слой данных перестаёт носить то,
  что рамка запрещает наследовать (defense-in-depth поверх промпта); байты ↓ в
  каждом запросе сессии.
- Минусы/честно: (1) частичность плана немаркирована — strict schema не пустит
  новый флаг без изменения contracts, поэтому владелец принимает семантику
  «пример без молчаливых шагов» без маркера в артефакте; (2) co-location
  потери чистого текста — поведение кандидата, не баг; (3) сокращение будет
  отличаться от bench-медианы 0,7935 (counts сохранены) — переизмеряется на
  реализации отдельным замером, не обещание; (4) desktop-тесты
  (work-experience.test.cjs: deepEqual полного плана) обновляются в срезе.
- До реализации проверить: нет ли в API/тестах фиксации ПОЛНОГО равенства
  плана reference с записью (на уровне контракта известна только схема).

### B. Скетч как отдельный формат reference (`koswork.example-sketch.v1`)

Полный контракт кандидата: kinds без counts, бюджет 5 000, упаковка,
маркированные потери. Максимум ценности (байты + скраб слоя данных + честный
формат), но требует изменений в packages/contracts и apps/api/computer-control
(сфера Codex): схема, WORK_REFERENCE_RULES, conformance-панель. Кросс-пакетная
договорённость до кода; два формата живут параллельно (правило выбора —
решение владельца). Ядро кода то же, что в A, поэтому A не выбрасывается.

### C. Отложить внедрение

Measurement-only остаётся (данные и bench уже в main, ничего не теряется);
вернуться при накоплении реальных примеров или при запросе память/история
функций. Обоснование: ценность вариантов A/B сегодня — defense-in-depth и
байты; острота вырастет вместе с объёмом реального принятого опыта.

### LLM-поворот — не вариант на сейчас

Числа прогонов №2/№3 против внедрения (см. вывод выше). Возвращаться только
по явному запросу владельца на переписывание (восстановление со-локализованного
текста), с новой панелью и отдельным решением.

## Что не меняется при любом варианте

Веса, fine-tuning и сеть исключены; новые журналы денег и управляющие движки
не создаются; автоматическая выдача remedialResolution исключена; bench/фикстуры
не редактируются и вне CI; права устройств и гранты не расширяются; UI приёмки
не меняется (видимые изменения — только через VISUAL_WAITLIST и решение
владельца); Multi-Agent — последний раздел; live-приёмка — прежняя отложенная
граница.

## Рекомендация

Вариант **A** как первый шаг (локальный срез, без кросс-пакетных зависимостей,
непосредственная defense-in-depth ценность), вариант **B** — отдельным срезом
после кросс-пакетной договорённости с Codex и только если после A остаточная
ценность скетч-формата подтверждена замером; **C** — честная альтернатива,
если владелец считает остроту недостаточной; **LLM** — measurement-only.
