# Решения владельца по Stars

25 ноября 2026 года. Продуктовый бриф по результатам обсуждения с владельцем.

Stars выбран флагманским направлением Kosmora. Рабочие режимы получают общую платформу компьютера, браузера, голоса, памяти и инструментов. Обычная Kosmora остаётся повседневным чатом. Эти решения задают направление и согласованные свойства. Состав первого выпуска владелец определит позже.

## Решения владельца

| Область              | Согласованное поведение                                                                                                                                                               |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Создание и настройка | Человек или уполномоченный менеджер создаёт, настраивает и удаляет агентов. Менеджеры могут образовывать несколько уровней.                                                           |
| Замена агента        | Незавершённые задачи передаются заменяющему. Контекст и результаты должны сохранять возможность продолжения.                                                                          |
| Контекст             | У каждого агента свой рабочий контекст и доступ к общему контексту команды.                                                                                                           |
| Постановка поручения | Готовое ТЗ, совместная проработка через вопросы и анкетирование либо самостоятельная проработка агентом в пределах разрешений.                                                        |
| Приоритеты           | Изменение приоритета и цели определяется настройками полномочий.                                                                                                                      |
| Люди и агенты        | Человек может иметь своего агента. Общие проекты допускают несколько аккаунтов и несколько персональных агентов.                                                                      |
| Среды                | Базовые подписки используют устройство пользователя для исполнения. Верхние подписки предоставляют облачное исполнение Stars. Предусмотреть перенос задачи между средами.             |
| Совместная работа    | Перед началом распределяются задачи. Агенты учитывают действия и результаты друг друга.                                                                                               |
| Разрешения           | Действия зависят от профиля, заданного владельцем.                                                                                                                                    |
| Приёмка              | При наличии старшего агента он проверяет подчинённых. В совместной работе каждый человек принимает работу своего персонального агента. Детальные случаи будут разобраны с владельцем. |
| Фоновые задачи       | События, время, дата и ожидание условия могут запускать работу. Агент в ожидании работает с минимальным расходом.                                                                     |
| Инициатива           | Приветствуются предложения, конструктивные переговоры и честная критика. Агент может первым написать, напомнить или начать обсуждение. Настройка позволяет отключить инициативу.      |
| Созвоны              | Агент может участвовать на протяжении всего созвона. Главный или доверенный участник разрешает подключение. Полномочия задаются заранее и меняются во время встречи.                  |
| API                  | Коммерческий API для встраивания в другие приложения.                                                                                                                                 |
| Первый выпуск        | Объём выпуска, расходы, квоты и тарифы определяются позднее.                                                                                                                          |

Внутренний контекст агента и общая память требуют сохранения между запусками. Технический способ хранения и отбора материалов остаётся архитектурным решением. Фраза «как у других ИИ» по памяти требует дальнейшей детализации сценариев.

## Связь с разрешениями

Основа — [утверждённая схема A0–A6](../constitution/specifications/autonomy-schema-v1.1.md). В ней отдельно заданы управление агентами, временные и постоянные инструкции, изменение стратегии, доступ к проектам, коммуникации, публикации и другие способности. Схема имеет статус спецификации. Для реализации сверяем поддерживаемые действия с существующим policy-engine.

Уровень менеджера задаёт место в иерархии. Выполнение конкретного действия проверяется по профилю полномочий и разрешённым ресурсам. Профили могут содержать overrides отдельных способностей.

## Предложения по совместной работе

Следующие правила предложены Codex по поручению владельца продумать иерархию. Их требуется согласовать при разборе сценариев.

1. Владелец пространства назначает главного менеджера. В каждом бизнесе или проекте могут быть управляющие, руководители групп и исполнители. Структура сохраняется между поручениями.
2. У задачи один ответственный менеджер. Персональные агенты участников могут участвовать в ней, сохраняя авторство поручений и границы доступа.
3. Делегированное поручение сохраняет автора, ответственного, цель, входные версии и критерии результата. Исполнитель возвращает результат ответственному.
4. Если два участника дают несовместимые указания, агент фиксирует конфликт и запрашивает решение ответственного. Отмена, запрет доступа и аварийная остановка применяются сразу в своей области.
5. Старший агент выполняет техническую проверку. Принятие человеком фиксируется отдельно согласно распределению ответственности. Для общей задачи участники заранее назначают человека, принимающего общий итог.
6. Передача задачи включает материалы, решения, готовые части, незавершённые операции и разрешённую точку продолжения. На новой среде повторно проверяются доступы и состояние внешних действий.
7. Общий контекст предоставляется по разрешённой области команды, бизнеса или проекта. Полезные выдержки подбираются к шагу, а точные исходники сохраняются отдельно.
8. Для фона используем события, таймеры и лёгкие проверки условий. Модель вызывается при необходимости анализа или действия. Частота проверок и объём наблюдения настраиваются.
9. Инициативность, уведомления и самостоятельные внешние действия имеют отдельные настройки. Для критики агент объясняет основания, отмечает неопределённость и предлагает улучшение.
10. Для встреч отдельно задаются прослушивание, запись, расшифровка, возможность говорить, доступные материалы и последующие действия. Учитываются правила площадки и согласия участников.

## Последующие решения

Нужно согласовать перенос личной памяти при замене агента, приёмку общего результата несколькими людьми, правила смены ответственного, интервалы фоновых проверок и конкретный состав API.

Предлагаемые группы API — сообщения и потоковые ответы, агенты и команды, асинхронные задачи, файлы, события и webhooks, подтверждения и отмена. Это предложение технического состава.

Звёзды поверх рабочего экрана остаются вариантом отображения. Для основного пространства обсуждена карта команд с панелью общения с агентом.
