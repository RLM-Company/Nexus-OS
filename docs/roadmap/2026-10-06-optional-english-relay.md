# Опциональный English Relay для экономии токенов

Статус: идея зафиксирована, реализация не включена.

## Цель

Добавить в настройки чата и в раздел функций переключатель `English Relay` / «Авторетранслятор». При включении пользовательский запрос перед отправкой модели переводится на английский, модель работает с английской версией, а ответ переводится обратно на язык интерфейса или исходного запроса.

Функция выключена по умолчанию и должна включаться явно. Предположение о снижении расхода токенов, включая возможную экономию более 100% относительно некоторых языков, считать гипотезой до измерений на реальных запросах и конкретных моделях.

## Поведение

- Переключатель доступен в настройках текущего чата и в общем разделе функций.
- Состояние должно быть явно видно рядом с полем ввода; выключение немедленно возвращает обычную отправку.
- В истории сохраняются исходный запрос пользователя и ответ на языке чата; английский промежуточный текст не должен подменять пользовательский текст.
- При включённом режиме модель получает английский текст, но системные инструкции, structured output, tool calls, имена файлов, пути, URL, идентификаторы, JSON, команды и содержимое code fence сохраняются без перевода.
- Для вложений переводится только извлечённый естественный текст, если это явно разрешено типом файла; бинарные данные, таблицы с идентификаторами и код не переводятся автоматически.
- Ответ модели переводится обратно перед показом пользователю. Код, команды, JSON, URL и технические идентификаторы в ответе должны сохраняться дословно.
- Если переводчик недоступен или перевод неоднозначен, отправка не должна молча переходить на исходный язык: показать понятную ошибку и дать отдельный выбор «повторить с English Relay» или «отправить без него».

## Ограничения и безопасность

- Не передавать ключи, секреты и скрытые системные данные в отдельный переводчик.
- Не менять язык GitHub API, имена веток, путей и параметров инструментов.
- Не переводить содержимое, для которого важна побайтовая точность.
- Ограничить размер промежуточного текста и добавить защиту от повторного перевода уже английского запроса.
- Зафиксировать, что токены переводчика тоже входят в стоимость/лимит; для коротких сообщений relay может быть отключён пользователем без потери исходного запроса.

## Критерии приёмки для будущей реализации

1. По умолчанию relay выключен после нового чата, reload и восстановления сессии.
2. При включении исходный и промежуточный тексты разделены, а повторная отправка не создаёт двойной перевод.
3. Code fence, JSON, URL, команды, имена файлов и tool-call аргументы проходят без изменений.
4. Ошибка переводчика видна пользователю и не приводит к незаметной отправке другого текста.
5. Есть сравнительный benchmark: одинаковый набор запросов без relay и с relay, отдельно для входных и выходных токенов, задержки и качества; решение о включении по умолчанию принимается только после измерений.

## Открытые решения

- Локальный переводчик или отдельный провайдерский маршрут.
- Переводить ли ответы всегда или дать отдельный переключатель «показывать исходный ответ».
- Нужен ли порог длины, ниже которого relay автоматически не предлагается.
- Как явно показывать пользователю язык, который получил провайдер, не перегружая чат.
