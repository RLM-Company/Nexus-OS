# Связанный контекст проекта и инициативный Work

**Дата идеи:** 2026-10-28

**Статус:** `IDEA`

**Этап:** кандидат для второго этапа; приоритеты требуют отдельного включения в roadmap.

## Контекст

Владелец попросил сохранить идеи после разбора продукта 365 и его канала.
Адаптируем общие продуктовые приёмы к задачам Kosmora: работа с информацией,
проектами и готовыми результатами. Источник вдохновения —
[канал 365](https://t.me/daysystem365) и [публичный лендинг](https://365app.online/).
Это собственная будущая реализация; наличие функции в чужом продукте не предполагается
доказанным одним рекламным описанием.

## Идеи

| Идея                      | Будущий пользовательский результат                                                                                     |
| ------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| Общий рабочий контекст    | Цели, задачи, файлы, решения и результаты проекта доступны ассистенту с понятными источниками и актуальностью          |
| План дня и недели         | Собрать задачи собственных выбранных проектов, учесть сроки, длительность и зависимости, предложить порядок выполнения |
| Оценка нагрузки           | Обнаружить перегрузку или конфликт сроков, объяснить причину и предложить конкретный перенос                           |
| Задача → Work → результат | Запустить выполнение из задачи, связать с ней Work и прикрепить проверенный результат обратно к проекту                |
| Инициатива ассистента     | Предложить следующий шаг при приближении срока, незавершённой работе или появлении важного нового материала            |
| Обзор проекта             | Показать цели, текущие задачи, последние результаты, препятствия и решения, ожидающие владельца                        |

## Рекомендуемая первая связка

`Проект → задача → Work → проверка → готовый результат в проекте`.

Начать с одного завершённого сценария: пользователь выбирает задачу, явно запускает
Work, видит его состояние и получает связанный с задачей файл. Повторное открытие
сохраняет связь и результат, а повтор запроса не запускает вторую платную работу.
Далее можно добавить планирование дня/недели и инициативные предложения.

В Kosmora уже есть материалы проекта, Work, планы с зависимостями и результаты.
Эта идея объединяет их в пользовательский сценарий; она не означает, что все
опорные механизмы требуется создавать заново. Перед реализацией нужно сверить
существующие API и поведение.

## Управление пользователем

- Инициативные предложения — отдельная включаемая функция, по умолчанию выключена.
- Предложение объясняет использованные задачи, сроки и материалы. Неизвестная
  длительность или неполный контекст явно отмечаются.
- Перенос сроков, изменение задач и запуск оплачиваемого Work требуют явного
  действия пользователя в рамках этой идеи. Она сама не расширяет текущую автономность.
- Выбор проектов ограничивает охват контекста; изменения материалов и удалённые
  данные учитываются по действующим правилам актуальности и доступа.
- Пользователь может отклонить предложение, отключить инициативу и управлять её частотой.

## Возможная интеграция с 365

Статус направления: `DISCOVERY`, необязательное дополнение.

Исследовать наличие публичного API или экспорта задач/проектов. Если официальный
способ существует и владелец выберет подключение, отдельно определить состав
данных, направление импорта/синхронизации и разрешения. Сейчас наличие API не
проверено; интеграция, передача данных и доступ к аккаунту 365 не активированы.

## Границы записи

Это сохранённые идеи, а не объявление готовых функций или изменение требований
первого релиза. Финансы, здоровье и семейный планировщик не добавляются в текущий
объём проекта этой записью. Визуальные решения рассматриваются позднее в
[листе ожидания визуала](../design/VISUAL_WAITLIST.md).
