# Kosmora media 14–16 — durable lifecycle & owner accounting (v2)

**Exact base:** tracked source archive `b15912d23ab15a99e38370e22e472faf28c99961` **PLUS** the previously accepted `kosmora-media-14-16-complete.patch` (SHA-256 `b92d322dcc5d843d1a734165c547f5ed4d32d53a0b273d7598097d56dd60c9ef`). ## What v2 adds

- One durable single-API-process store for **image, speech and transcription** jobs. JSON checkpoints and completed PNG/MP3 binaries live on persistent private disk. Transcription **recording bytes are never stored**; only owner-visible text is saved. State machine: `queued → running → done|failed|cancelled`. No automatic paid replay on restart; interrupted entries become `failed/INTERRUPTED`. User can explicitly start a new job. Startup cleans only recognized temporary files and orphaned PNG/MP3. Content checksum validated before authenticated download.
- Explicit per-owner cancellation fences: abort controller, state transition, and guards immediately before any commit. `DELETE /api/v1/media/jobs/:id` **cancels** but retains history. `DELETE /api/v1/media/assets/:id` **deletes** that owner's metadata/result. A late result cannot recreate deleted/cancelled jobs. One process only; no distributed workers.
- All three server media operations require `OwnerMediaBudget` **and** an enabled capability, paid permission and user consent. No `ownerBudget` ⇒ `BUDGET_UNAVAILABLE`/HTTP 503, **no provider dispatch**. Idempotency key for the canonical ledger is `operationId === job.id`. `reserve` is awaited before provider dispatch. `reconcile` accepts only validated, provider-returned token counters; never synthesize costs from byte counts. When absent, cancelled, interrupted or uncertain: `uncertain` keeps a hold. Failure of budget reconciliation fails the job, retaining the reservation until the account store reconciles it. The provided baseline does **not** contain the shared AccountStore ownerBudget, therefore no fake local budget or silent paid billing fallback was introduced.
- Privacy adapter `createMediaPrivacyAdapter(service)` exports `name`, `required`, `quiesce(ownerId)`, `export(ownerId)`, `delete(ownerId)`, `resume(ownerId)`. Quiesce aborts owned work and fences future writes. Export includes jobs and **same-origin authenticated owner-only download links**, byte sizes, SHA-256 (for v2 assets) and MIME types. Delete removes owned media only, **never billing records / uncertain holds**. Integrator must register this adapter in the global privacy coordinator; do not claim complete export/delete if registration is missing. `resume` should be invoked by coordinator **only** after a non-destructive export has finished.
- Russian monochrome controls: status/history after reload, explicit cancel, retry by a **new click** (not automatic), authenticated download and deletion. Browser speech APIs start **only after a user click**. A server recording stops by 60 seconds or 1.5 MB, whichever comes first; server also validates 1.5 MB max. Speech-to-text now replies with **HTTP 202 job metadata**, polled via `GET /jobs/:id`, not an immediate `{text}` response. The text is editable and never automatically sent.

## Integrator instructions

1. Apply `kosmora-media-14-16-v2-modules.patch`, then `kosmora-media-14-16-v2-integration.patch`, onto the exact base above. Or apply `kosmora-media-14-16-v2-complete.patch` once. Main integration is **server.ts only**: production storage defaults to `/var/lib/cosmora/media`, with `KOSMORA_MEDIA_DIR` override. app.ts, shared nav, db schema, journal, Model Registry and text provider remain unchanged.
2. In the *integrated checkout* supply `ownerBudget` on `MediaService` using the already-existing AccountStore interface. Its implementation must reserve canonically and idempotently on job.id, record canonical usage, preserve uncertain holds and retain billing records after owner privacy deletion. Do not enable paid media without this. Existing `KOSMORA_MEDIA_PAID_ENABLED` remains `false`. There are no new keys, real payments or paid calls in this patch.
3. Register `createMediaPrivacyAdapter(mediaService)` in the actual privacy coordinator, preserving `quiesce → export/delete → resume-on-export-only`. A coordinator that lacks this required adapter must fail closed. This source archive lacks that newer coordinator API, so **the registration remains INTEGRATOR ACTION**.
4. No SQLite migration required: already durable JSON jobs, with no runtime DDL. Slot `0029` / `idx29` / `when1791580800004` left untouched and available if the integration owner chooses to move jobs to SQLite. Do not invent a migration or reorder journals 25–28.
5. Run `pnpm --filter @cosmora/model-gateway typecheck`, `pnpm --filter @cosmora/api typecheck`, `pnpm --filter @cosmora/web typecheck` and `pnpm --filter @cosmora/api test`, then manual user-flow checks `generate/record → cancel → retry → reload → download/delete`, and a two-owner privacy isolation test. Check host volume persistence and file permissions in container; no VPS changes from this branch.
