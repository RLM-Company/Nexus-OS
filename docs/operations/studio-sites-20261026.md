# Studio: static website creation

The Sites surface now creates a real self-contained HTML/CSS file through the existing durable Work pipeline instead of preparing a prompt for the main chat. The owner selects an existing project and explicitly starts generation. Work preserves project material/privacy fences, the shared owner ledger, approval by complexity, cancellation and its limit of two to three model calls. The website output contract requires one complete `index.html` under 64 KiB. Invalid output fails without publishing files or retrying the paid generation.

Completed results open in the existing owner-scoped Canvas editor. Saving, revisions, conflict handling, local draft recovery, copying and HTML download use the same Canvas implementation. Opening another result is an explicit action. Background polling does not replace the current editor. Site and ordinary Canvas data remain private to their existing owner/project; no new database table or migration is introduced. Publication to hosting and backend application generation are separate work.

Only the Sites editor opts into static visual HTML preview. Ordinary Canvas continues showing HTML as text. The preview parses in an inert HTML template, retains an allowlist of static HTML and attributes, removes scripts, navigation, forms, foreign namespaces and nested frames, and restricts images to embedded PNG/JPEG/WebP. The serialized output receives a restrictive CSP and is displayed with an empty iframe sandbox and no referrer. CSS can render; script execution and external resource loading are disabled. Original source bytes are preserved for editing/download; preview filtering never rewrites the saved file. The desktop/tablet/phone controls change the actual preview viewport.

Isolation follows the [HTML iframe sandbox](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/iframe) and [CSP](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/CSP) contracts. The iframe sandbox is an attribute, not a CSP meta directive. Static preview does not claim that JavaScript or form integrations were tested.

Browser regression coverage exercises creation through the real local API/coordinator with a deterministic provider fixture, visual HTML rendering, viewport resizing, exact download bytes, revision reload, external-resource blocking, active-markup removal and recovery of a lost creation response without a duplicate task. Paid/live provider acceptance is recorded separately after activation.
