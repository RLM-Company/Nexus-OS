# Studio Games: data-driven playable prototypes

Games now creates a real playable prototype instead of forwarding an idea to the ordinary chat. The owner chooses an existing project and one of three supported mechanics: collecting items while avoiding obstacles, matching pairs, or answering a quiz. Work produces exactly one `game.json`. Themes, labels, difficulty and questions are model-generated data; execution uses a fixed application runtime. This is not arbitrary game-code execution, a general-purpose engine, hosting or multiplayer.

The bounded `kosmora.game.v1` contract rejects unknown fields, duplicate memory labels, invalid quiz answers and mismatched mechanics. The ordinary Work pipeline retains project/owner scope, shared usage accounting, cancellation, approval and optional Critic gates. Invalid output is not published or automatically regenerated. The Work creation route now uses the TypeBox compiler: the default mutating validator could strip `genre` while trying other branches of the output-contract union. Real HTTP regressions cover all game discriminators.

Completed results open in Canvas with an independent new-draft key, JSON download, revisions, conflict handling and local draft recovery. The Games editor exposes explicit Play, Restart, Stop and standalone HTML download. Editing JSON removes the current frame and requires another explicit launch. Playing and restarting perform no model calls. Ordinary Canvas and the static Sites preview keep their existing behavior.

The exported HTML contains escaped JSON and a fixed trusted runtime. Model strings only enter text nodes. No model-supplied script or HTML is executed. The embedded frame permits scripts but omits same-origin, navigation, forms, popups and download permissions. A nonce permits only the fixed runtime; the frame's CSP denies network, nested frames and objects. A saved standalone file works without the Kosmora server or external assets. [Iframe sandbox rules](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/iframe) explain why `allow-same-origin` is omitted.

Arcade uses actual pointer/keyboard input and animation frames. Its time and pause controls use `performance.now()`, and hidden documents pause automatically. Memory includes matching, mismatch reset and a clean restart; quiz includes answer feedback, scoring and completion. [Animation frame behavior](https://developer.mozilla.org/en-US/docs/Web/API/Window/requestAnimationFrame) and [monotonic browser time](https://developer.mozilla.org/en-US/docs/Web/API/Performance/now) inform these controls.

Browser acceptance covers all three mechanics, pause/restart/stop, version reload, literal hostile labels, parent-origin isolation, invalid-edit shutdown and offline HTML playback. Shared Sites flows are rerun. Chromium can report resource attempts before marking them blocked by CSP; resource-isolation checks require every observed attempt to fail specifically with CSP, never merely a DNS/proxy failure or an actual response. Live model generation is recorded separately after activation. No database migration is required.
