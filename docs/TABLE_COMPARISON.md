# Сравнение сохранённых версий таблицы

`POST /api/v1/projects/:projectId/tables/:id/compare` сравнивает две неизменяемые
ревизии одной собственной таблицы. Расчёт не вызывает модель и не меняет таблицу,
настройки, историю либо материалы проекта. Интерфейс остаётся прежним.

```json
{
  "before_version": 1,
  "after_version": 2,
  "alignment": { "kind": "key", "before_columns": [1], "after_columns": [1] },
  "offset": 0,
  "limit": 50,
  "include_values": false
}
```

Режим сопоставления обязателен:

- `position` сопоставляет первую строку с первой, вторую со второй и так далее.
  Вставка в середину может выглядеть как много изменений: этот режим не ищет
  соответствия и не притворяется, что восстановил их.
- `key` использует явно выбранные исходные столбцы (1-based, до трёх компонентов).
  Ключи сравниваются как точные строки без нормализации: `001`, `1`, `A` и `A `
  различаются. Составной ключ кодируется как JSON-массив, без коллизий разделителей.
  В каждой версии ключ должен быть уникальным и иметь все непустые компоненты.
  При неоднозначности возвращается 422 с кодом, стороной и номером строки, без
  публикации самого ключа в ошибке. Автоматического перехода на другой режим нет.

Сопоставление столбцов значений — по исходной позиции, а не по похожему названию.
Изменения названия, типа, добавление и удаление столбца перечислены в `schema_changes`.
Одинаковые названия не затирают друг друга. Перенос столбцов не угадывается: при
необходимости перестановка отражается в структуре и точных значениях ячеек.

Все исходные строки участвуют в расчёте; сохранённые фильтры и сортировка Studio
не скрывают изменения. Ячейки сравниваются как точные строки, без исполнения формул
и числового приведения (`1` и `1.0` различаются).

Ответ `kosmora.table-comparison.v1` содержит:

- `source` с ID таблицы, версиями и SHA-256 обеих ревизий;
- `summary` со всеми добавленными, удалёнными, изменёнными, неизменёнными и
  сопоставленными строками. `moved_rows` — сопоставленные по ключу строки с другим
  порядковым номером; они могут одновременно быть изменёнными. `changed_cells`
  относится только к сопоставленным строкам, включая добавленный/удалённый столбец;
- `schema_changes` независимо от изменений данных. Нулевое `changed_rows` не означает
  отсутствия изменений структуры;
- `changes` — ограниченную страницу добавлений, удалений и изменений с исходными
  номерами строк (1-based, без заголовка) и номерами изменённых столбцов;
- `detail` с полным числом изменений, следующей позицией и явным признаком полноты.

Сначала перечисляются удаления и изменения в порядке исходной версии, затем
добавления в порядке новой. При `include_values:true` страница включает точные массивы
ячеек до/после; по умолчанию значения не добавляются. Итоговые счётчики всегда
охватывают все строки, независимо от размера страницы.

`limit` — от 0 до 200; 0 возвращает только счётчики и структуру. Большой ответ
ограничен 1 МБ и отклоняется с 413 без молчаливого обрезания. Уменьшите страницу,
выключите значения или запросите сводку с `limit:0`. Исходные лимиты хранилища
таблиц сохраняются. Миграции и новые зависимости не нужны.

Обычная сессия обязательна. Чужой проект, другой тип артефакта или отсутствующая
ревизия дают 404. SHA-256 обеих версий проверяется до расчёта; повреждение даёт 409
без выдачи содержимого. Ответы приватные, с `no-store`; лишние поля отклоняются.
