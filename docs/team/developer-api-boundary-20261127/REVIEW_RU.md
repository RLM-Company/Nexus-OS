# Приёмка границ публичного API

Дата: 27 ноября 2026. База — PR #694, точный SHA
`48862d7809e306ada8ac40776c53be02cf434a3c`.
Исправления подготовлены отдельно от ветки исполнителя; main и VPS не изменялись.

## Что исправлено

1. **Клиентский ключ получал доступ к внутренним маршрутам владельца.**
   Воспроизведение через `buildApp` и настоящий HTTP-маршрут:
   `GET /api/v1/navigation-context` с ключом только `chat.read` возвращал
   `200 {"owner_id":"owner-a"}`, хотя ожидается 401. Проверка нового теста
   на исходном resolver воспроизвела именно этот ответ.
   Теперь клиентские ключи разрешены только для явно перечисленных зарегистрированных
   маршрутов внешнего API. Query string, похожий префикс, неправильный формат ключа
   и административные маршруты не обходят границу. Сессионный доступ сохранён.
2. **Активные потоки имели общий ID без владельца/ключа.**
   Ключ другого приложения мог отменить чужой поток по совпавшему request ID.
   Отдельный HTTP-тест на исходном коде получил 200 вместо ожидаемого 404.
   Теперь внутренние ID генерации и отмена привязаны к владельцу, ключу и клиентскому
   ID. Одновременный повтор активного ID тем же ключом возвращает 409 без перезаписи
   контроллера. Клиентский ID в публичном ответе сохранён.
3. **Поток не очищался при исключении провайдера.**
   Завершение и освобождение ID выполняются в finally; отмена отслеживает соединение
   ответа. Клиент получает безопасное событие ошибки без внутренних диагностик.
   После ошибки тот же ID можно использовать повторно.
4. **Администрирование ключей ошибочно требовало actor_id = owner_id.**
   У легитимной сессии владельца эти идентификаторы могут различаться.
   Проверяется роль владельца, клиентские учётные данные запрещены.
5. Ошибки входной схемы теперь возвращаются как 400, а не INTERNAL/500.

## Условия сведения

- Включать исправление вместе с PR #694, не выпускать исходный resolver отдельно.
- Миграция `0078_developer_api` из исходной поставки пересекается по номеру с
  миграциями новых поставок Stars и совместных проектов. Интегратор должен назначить
  уникальные номера и возрастающие timestamps, проверить обновление базы main и
  повтор миграции. Этот патч схему базы не меняет.
- Нельзя считать весь публичный API и ускорение принятыми по этому исправлению.
  Например, `runParallelRoute` в исходной поставке вызывает части последовательно,
  а HTTP-обвязка использует один request/idempotency ID для всех частей и не передаёт
  дочерний AbortSignal. Это отдельный следующий блок исправлений; доказанного
  ускорения живой модели пока нет. Новые таски API пока являются очередью хранения,
  подключение полноценного исполнителя проверяется отдельно.
- Основная ветка на момент проверки: `3af92583ccc8ceb49f44c0b8633955f40feaf59f`.
  Ни новая поставка #694, ни это исправление на сервер не выкладывались.
