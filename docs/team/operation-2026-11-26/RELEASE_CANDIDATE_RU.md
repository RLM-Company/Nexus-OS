## Воспроизведение

- SQLite и области проекта — `pnpm --filter @cosmora/db exec vitest run test/project-intake-upgrade.test.ts test/project-correction-rules.test.ts test/project-sources-store.test.ts`.
- HTTP и источники — `pnpm --filter @cosmora/api exec vitest run test/project-membership.test.ts test/drive-connector-lifecycle.test.ts test/project-sources.test.ts test/research-receipts-user-run.test.ts test/supplier-work-handoff.test.ts`. Материал проходит существующие endpoints и проверяется по байтам. Research запускается с контролируемыми ответами сети и модели.
- Stars — `pnpm --filter @cosmora/api exec vitest run test/work-dag.test.ts -t 'binds a Stars mission'`. Подтверждённая тройка → два исполнителя → ошибка одного → замена экземпляра по той же версии blueprint → отдельное подтверждение повтора → менеджер с двумя проверенными байтовыми входами и обязательной рецензией → три файла с SHA-256 и ZIP. Вторая миссия отменяется после постановки дочерних Work в очередь. Повтор и чтение чужой миссии проверены. Путь в интерфейсе — Stars, проект, миссия, команда Agent Studio, ссылка на план Koswork. Платный запуск остаётся отдельным действием в плане.
- Desktop — `node --test desktop/windows/test/{browser,browser-shell,browser-tab-ownership,computer-recovery-events}.test.cjs`. Ручное действие до ввода отменяет ожидающий и отложенный шаг. Системный сценарий `browser-dom-smoke.cjs` использует Chromium, Windows/Electron проверяйте отдельно.
- Приёмка в браузере — `KOSMORA_E2E_PRODUCTION=1 pnpm --filter @cosmora/web exec playwright test e2e/supplier-work-handoff.spec.ts e2e/research-canvas.spec.ts e2e/game-development.spec.ts e2e/sites-workbench.spec.ts e2e/koscode-navigation.spec.ts e2e/skills-library.spec.ts`. Для стандартного CI используется Playwright Chromium. Games запускает только поддерживаемые варианты, OBJ-lite обрабатывает вершины и треугольники; glTF и сторонние движки не подключены.
- Медиа и Koscode — `pnpm --filter @cosmora/api exec vitest run test/media-api.test.ts test/media-acceptance-integration.test.ts test/media-durable-lifecycle.test.ts test/code-agent.test.ts`. Текущие возможности и провайдер — существующие конфигурации. Образ контейнера для отдельного OCI-сценария поднимается в GitHub CI.

## Живые проверки и решение

- **Интегратор и владелец назначенного GitHub стенда.** Живой Koscode Draft PR в тестовом репозитории ещё не опубликован. Для воспроизведения выбрать согласованный репозиторий в Koscode, подготовить небольшую правку, исправить неудачную проверку, подтвердить Draft PR, повторить подтверждение после потери ответа и сверить один PR в GitHub. Фикстуры проверяют этот контракт отдельно от реальной публикации.
- **OpenCode.** Проверить Windows/Electron на отдельном стенде. Сценарий — начать работу с вкладкой, вернуть управление пользователю во время ожидания, затем проверить активное окно и отсутствие позднего ввода. Локальный CDP smoke на системном Chromium остановился на `BROWSER_STALE` при открытии страницы поиска. На движке от `main` с тем же браузером повторяется там же.
- **Drive / владельцы аккаунтов.** Пройти реальный OAuth, импорт разрешённого файла, отзыв и повторный доступ. Проверена управляемая фикстура OAuth; данные Google не использовались. Совместный проект уже доступен участнику по ссылке, основной список проектов пока показывает собственные проекты.
- **Gemini / владелец провайдера.** Передать читаемый патч или точный Git ref и перечень возможностей подключённого провайдера. Нужна живая проверка реальной генерации и совместимых операций, включая историю версий, видео и отказ при неподдерживаемой операции. URL-only изображения в текущем runtime отклоняются и CDN не загружаются.
- **Stars / интегратор.** Замена сохраняет ту же версию роли, ограничения проекта и незавершённый шаг. Отдельный выбор другой модели, перенос на другую версию blueprint и живой многомодельный прогон остаются открыты.
- **Отдельный PR #687.** Кнопка нового чата из сообщения ведётся отдельно. Первая широкая браузерная проверка этого PR дала повторившийся после повтора сценарий черновиков чата. Перенос в общий кандидат требует проверки чистого результата.
