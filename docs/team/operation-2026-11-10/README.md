# Операция Kosmora: автономные сферы разработки

Старт учёта: **10 ноября 2026, Europe/Moscow**. Владелец передаёт отдельные файлы
внешним исполнителям. Создание этих файлов не означает отправку или запуск чатов.

Цель: большие законченные пользовательские возможности и выпускаемый совместимый
продукт. Рабочая петля выбирает следующий пробел своей сферы без нового промпта
после каждой функции. Количество токенов/строк/модулей не является результатом.

## Согласованные границы

Владелец явно поручил подготовить широкие петли по разным сферам вместо выдачи
мелких отдельных задач. Это новое распределение заменяет назначения пакета
7 ноября. Не является разрешением на новый дизайн, внешние публикации, платные
операции или управление устройством. Multi-Agent остаётся последним; Jarvis,
облачный ПК и обучение весов не запускаются. Обучение через обратную связь — Claude,
факты/источники/контекст — DeepSeek, будущий курс по ИИ остаётся отдельным проектом.

Общие API-контракты/DB/entrypoints согласует Codex. Browser core — Gemini,
Windows host — OpenCode, память — DeepSeek, skills — Claude, code-agent — разработчик.
Документы/Office/Drive и основная Work-цепь — Codex. Общие hooks сдавать отдельным
integration commit: не блокировать весь модуль, но и не считать его подключённым
только по наличию локального standalone-примера.

## Как ведём операцию

- Общая [доска](BOARD.md) и [журнал](JOURNAL.md) обновляются Codex по полученным
  веткам/PR/исходникам и результатам. Отчёт без кода не повышает статус.
- После каждого законченного среза исполнитель отдаёт PR и checkpoint, затем
  продолжает свою очередь. Если предыдущая поставка не принята, следующую строит
  поверх неё в той же цепочке и явно указывает зависимость; не создаёт лавину PR.
- На следующем сеансе начинает с checkpoint и актуального main. Обычный чат
  не превращается от текста инструкции в бесконечный фоновый процесс.
- Codex проверяет совместимость и необходимые CI перед включением в выпуск.
  Серверная выкладка/реальная модель/owner-PC отмечаются отдельно, не по фикстурам.
- Обязательные цифры: принятые пользовательские сценарии, готовые к интеграции
  срезы, критические открытые дефекты, блокировки и реальные live-проверки.
  Время/стоимость измеряются только фактически, не предполагаются.

## Что означает первый дроп

Не «все мыслимые функции окончены». Выпускается зафиксированный набор реально
проверенных режимов с перечисленными ограничениями. Остальные сферы продолжают
независимые петли. Для каждого кандидата нужны совместимый комплект версий,
upgrade/rollback, реальные критерии результата и отсутствие известных критических
дефектов. Автоматические проверки не заменяют первую пользовательскую приёмку.
