# 04_DEEPSEEK: Память, контекст и качество извлечения

Исполнитель: **DeepSeek Harness**. Ветка: `ops/deepseek-memory`. ID отчётов: `04_DEEPSEEK`.

## Твоя масштабная цель

Довести память Kosmora/Koswork до полезной системы: помнить подтверждённое,
находить нужное в разрешённых чатах/проектах, экономить контекст и честно
отказываться от вывода, если подтверждения нет. Не обещать буквальное «помнит всё».

## Очередь больших результатов

1. Найди активные memory/index/ranker/packing entrypoints. Отдели prototypes и
   measurement-only модели от реально используемых. Не включай их по одному названию.
2. Доведи запись/исправление/забывание фактов: источник, версия, противоречие,
   подтверждение пользователя, expiry, удаление из индекса и export. Не путай
   последнее сообщение с истинным фактом и не воскрешай забытое из старого summary.
3. Доведи сквозное извлечение: разрешённые чаты и scope проекта/владельца,
   правильный источник и цитата, защита от ложного recall и absent-fact. Данные
   другой задачи/аккаунта не должны попадать в контекст при async-смене владельца.
4. Доведи эффективное сжатие: обязательные ограничения/активные цели/решения/
   непрочитанные результаты не теряются; повторы удаляются; source refs остаются.
   При потере информации раскрывай ограничение и дочитывай оригинал по запросу.
5. Доведи ранжирование и укладку под реальный бюджет. Измеряй recall/precision,
   неподтверждённые ответы, размер контекста и задержку на фиксированной панели.
   Сравни с текущим baseline; экономия без сохранения полезности не считается успехом.
6. Улучши управление памятью в её существующих настройках и диагностику причин
   выбора источника. Повышать автономно тариф/модель/права или включать memory OFF нельзя.

## Границы

Твои: context-memory/evidence-selection и активные memory modules в core,
apps/api semantic-memory и memory routes/store/index, scoped memory controls/tests.
Граф изменяй только в части памяти без перестройки его UI. Drive importer остаётся
Codex: потребляй канонический source API, не подключай второй OAuth/Drive crawler.
Skills/стиль — Claude, runtime задачи — Codex. Общие schemas/DB — integration commit.

## Критерий завершения

На фиксированной панели есть корректный recall, отсутствующие/противоречивые факты,
длинные задачи, forget/revoke/restart и cross-owner isolation. Показатели baseline
и новой версии опубликованы с ограничениями; реальные данные владельца не нужны.

### Петля — выполняй её, а не только описывай

1. Найди действующий entrypoint своей сферы, проверь пользовательский путь.
   Составь BACKLOG.md: уже работает / сломано / отсутствует / требуется решение.
   Наличие файла, mock или отчёта не означает функцию. Не строй второй runtime.

   сначала потеря данных/изоляция, затем блокеры результата, затем полезные улучшения.
   Разбей большой сценарий на поставляемые части; не жди завершения всей сферы.
3. Реализуй настоящий вертикальный срез: пользовательское действие → текущий
   контракт → runtime → сохранённый/видимый результат. Анализ и тесты сопровождают
   реализацию, но не заменяют её. Повтори существующее сильное поведение, если
   отсутствующего механизма не нужно. Перед крупным механизмом изучи готовые решения,
   проверь лицензию и версию; адаптируй совместимое, не накладывай чужой репозиторий.
4. Проверь успех, отказ, отмену, повтор и восстановление там, где они применимы.
   Запускай содержательные проверки изменённой области, типы/линт и требуемые gates.
   Внешние недоступные зависимости заменяй только в тестах, явно отделяя live-статус.
5. Сделай commit и обнови DELIVERY.md + CHECKPOINT.md. Открой/обнови PR в main;
   не сливай и не выкатывай самостоятельно. Сдай рабочую часть сразу, продолжая
   следующий непересекающийся срез. Не накапливай сотни файлов без интеграции.
6. Снова возьми следующий приоритетный пробел. Не спрашивай «продолжать?» после
   каждой функции. При блокировке конкретной части зафиксируй её и продолжи
   независимую работу своей сферы. Не обходи недостающие разрешения.

В конце доступного сеанса сохрани точную точку продолжения. При следующем запуске
прочти её и продолжай. Инструкция не создаёт фонового процесса и не отменяет лимиты
платформы: не обещай работу после завершения сеанса и не имитируй бесконечный цикл.
Если все критерии сферы выполнены — проведи итоговую приёмку и остановись с отчётом;
не изобретай новый продукт ради продолжения. Не повторяй неизменившийся сбой
бесконечно: после двух одинаковых неудачных попыток пересмотри причину/подход;
если независимого пути нет, передай конкретную блокировку.

  новые общие контракты, а не разрешай конфликты автоматическим выбором своей версии.
- Chat/sidebar/logo/global CSS не переделывать. Минимальные элементы согласованной
  функции — в существующем разделе по его правилам; изменение компоновки/дизайна
  записывать в VISUAL_WAITLIST.md и не выполнять попутно. Читай bundled Next docs

- Не меняй ключи/провайдера/тарифы. Эта петля не разрешает расход реального API,
