# DeepSeek Harness 1 — Stars от команды до исполнителей

Прочитай `00_COMMON_RU.md` в ветке `team/local-completion-20261128`. Ветка: `completion/stars-20261128`. ID: `08_HARNESS`.

Ты единственный владелец Stars этой волны: иерархия, делегирование, реальное взаимодействие, затем удалённое исполнение. В main есть versioned org, missions, WorkDAG delegation и карта/панели. stars-runner-adapter — изолированный тестовый исполнитель, не готовое облако.

## Очередь A — работающая команда

1. Главный менеджер, два управляющих, исполнители для двух проектов. Роли, ответственный, критерии и разрешённые ресурсы сохраняются.
2. Настоящие модельные агенты получают независимые и зависимые поручения через WorkDAG, читают разрешённые результаты и возвращают общий проверенный артефакт.
3. Доведи уточнения, сообщения агенту/между агентами, арбитраж несовместимых указаний и приёмку старшим. Технический PASS и принятие человеком различаются.
4. Замена/удаление исполнителя сохраняет сделанное и переносит незавершённое. Restart не требует ручного completed. Поздний результат не оживляет отменённую задачу.
5. Карта отражает настоящих агентов, связи и состояния, позволяет общение и управление; без выдуманного прогресса.

## Очередь B — среда исполнения

Доведи авторизованный remote protocol, leases/heartbeat, checkpoint, отмену и перенос задачи local↔remote. Проверяй на отдельных локальных процессах/изолированных workers, затем подготовь развёртывание. Только реальный удалённый запуск позволяет назвать облачный сценарий принятым. Устройства/секреты не переносятся вместе с checkpoint автоматически.

Используй scheduler OC1, память Harness 2, membership и desktop OC3. Один физический курсор нельзя дать нескольким агентам одновременно. Фоновое ожидание не должно постоянно генерировать токены. Общий developer API — Codex; hooks встреч — Harness 3. Не создавай параллельные stores/права/очереди.

## Приёмка

Два проекта и команда выполняют поручение; один исполнитель падает и заменяется, возникает конфликт, человек разрешает его, задача переживает restart, выдаёт проверенный общий файл. Затем перенос между двумя изолированными исполнителями с отсутствием дублей и утечек. Проверь revoke, отмену и чужого участника.

Продолжай петлю до реальной команды; временный runner и fixtures называй явно. Поставка — PR/SHA, trace, артефакт и точные подтверждённые среды исполнения.
