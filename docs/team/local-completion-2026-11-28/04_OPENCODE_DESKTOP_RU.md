# OpenCode 3 — ПК, браузер и Windows-приложение

Прочитай `00_COMMON_RU.md` в ветке `team/local-completion-20261128`. Ветка: `completion/desktop-browser-20261128`. ID: `04_OPENCODE`.

Твой результат — Kosmora сама выполняет разрешённую работу на ПК, а клиент сохраняет и восстанавливает этот процесс. Действия разработчика через собственные инструменты не считаются действиями Kosmora.

## Очередь

1. Сначала доведи существующие computer session/workspace/driver, browser engine, recovery, device leases и executor-target. В main исправлена утечка native lease при устаревшем queued observation; не потеряй эту защиту.
2. Пройди приложение → документ → сохранение → независимый readback → результат Koswork. Потом браузер → страница/тестовая форма → upload/download → проверенный файл → возврат агенту.
3. Проверь несколько окон, смену фокуса, системный диалог, закрытый процесс, свежесть наблюдения и подтверждение результата после действия. Не заменяй ошибки слепыми кликами по старым координатам.
4. Human takeover/stop/revoke обязаны прекращать поздний ввод. Два агента делят нативный фокус по очереди; независимые DOM-контексты не получают скрытого доступа к основному ПК.
5. Затем закончи Windows lifecycle: вход/сохранение сессии, смена origin/аккаунта, DPAPI-черновики, reconnect, restart, центр результатов и совместимость установки/обновления.
6. Подготовь typed мосты для голосового агента, Games и Stars через действующий runtime. Их бизнес-логику здесь не дублируй.

Зона: desktop/windows и computer-control/browser мост. Code-agent workspace в packages/tool-runtime принадлежит OC4; общие изменения согласуй. Не управляй реальным пользовательским аккаунтом/приложением без назначенного теста; основа — выделенный каталог, тестовый профиль и локальная форма. Не удаляй рабочую установку и не меняй подпись/updater ради проверки.

## Приёмка

Настоящий установленный клиент с моделью делает документную и браузерную задачи. На середине пользователь перехватывает управление, затем разрешает продолжение. После обрыва и restart нет потери черновика, дубля результата или чужого сеанса. Проверки mock, disposable Electron и ноутбука владельца отмечай раздельно.

Продолжай исправлять разрывы до полного цикла; затем бери следующий пункт внутри этого направления. Сдай код, runnable acceptance, PR/SHA и отчёт.
