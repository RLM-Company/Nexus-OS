# Codex — публичный API и интеграция

Владелец назначил Codex исполнителем API и интегратором этой волны. Действуют 00_COMMON_RU.md и отдельные worktree. Реализация API — `completion/developer-api-20261128`; общая приёмка — отдельный кандидат. ID: `11_CODEX`.

## API: исправить подтверждённые разрывы

1. В routes.ts POST /tasks сохраняет queued через createTask; настоящего consumer, завершающего задачу, при аудите не найдено. Подключить durable dispatch к действующему Work/Stars runtime, не дублируя его и не смешивая ключ клиента с owner identity.
2. Задача проходит claim → исполнение → сохранённый результат → скачивание. Добавить lease/restart/cancel, проверку scopes/owner, correlation ids и идемпотентность. Повтор acknowledgement не создаёт новую работу, поздний результат после отмены не публикуется.
3. Есть подписки и приём подписанных событий. Довести настоящую исходящую доставку: durable outbox, подпись фактических байтов, event/delivery IDs, bounded backoff, дедупликация, отзыв, журнал и неизвестный исход. Проверять адрес, DNS и редиректы; не допускать SSRF или раскрытия секретов.
4. Связать developer usage с каноническим model usage ledger, включая параллельные дочерние вызовы, review/repair и ошибки. Не начислять один расход дважды. Тарифы/размеры квот не назначать.
5. Довести внешний CLI/SDK пример: ключ → stream → задача → результат → события → revoke. Клиентский ключ не может читать внутренние owner API, чужие задачи или администрировать ключи.

## Интеграция команды

Принимать точный SHA, дифф и фактические доказательства. Сверять, что уже включено. Исходные ветки сохранять, общие изменения принимать последовательно, после каждого — целевая проверка. Затем полный CI общего SHA, проверка итогового main и дерево для живой приёмки. Не выдавать тестовый сервис/runner за production.

Отдельно держать локальные фикстуры, настоящую модель, реальный локальный UI/ПК, внешние сервисы, VPS и первую группу. Новые внешние действия не возникают из разрешения на сведение.

На локальной базе 132e609d прошли один настоящий чат и один маленький файловый цикл Koswork. Это полезный baseline, не доказательство готовности всех режимов. Проверять совместные проекты/роли на общих стыках. Существенный незавершённый блок совместной работы передавать освободившемуся исполнителю, не прятать в статусе «приёмка».

## Следующая очередь Codex

После API — скорость: baseline/fast/parallel на одинаковых задачах с TTFT, total, usage и качеством; исправления буферизации/подготовки, частичный retry, контроль контекста и кеша. Подключать только полезный измеренный механизм. Не обещать изменение физического TPS чужого провайдера. Совмещать это с интеграцией, не назначая себе заранее все чужие незавершённые функции.

Поставка: работающий внешний клиент, проверенный артефакт, квитанция события, сверенный ledger, PR/SHA, общий статус и открытые блокеры с владельцами.
