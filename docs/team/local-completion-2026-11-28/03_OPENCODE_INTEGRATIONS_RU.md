# OpenCode 2 — реальные интеграции

Прочитай `00_COMMON_RU.md` в ветке `team/local-completion-20261128`. Ветка: `completion/integrations-20261128`. ID: `03_OPENCODE`. Владеешь подключениями внешних сервисов и пользовательским HTTP/MCP-коннектором.

Calendar/Mail в main — только фикстуры, исключённые из production-каталога. Не выдавай их за работающую почту или календарь. Drive/GitHub/HTTP/MCP-фундамент уже существует.

## Последовательная петля

1. Сверь реестр коннекторов, секреты, capabilities, OAuth и действующие production transports. Выбери поддержанную пару почта/календарь, закрепив официальные API и необходимые scopes.
2. Реализуй полный lifecycle первого сервиса: подключение → минимальный доступ → чтение → подготовка изменения → подтверждение → реальная операция → журнал → отзыв.
3. Доведи обновление/истечение токена, отмену, потерянный ответ, версию объекта и защиту от повторной отправки. Секреты не попадают в descriptor, журнал, браузерный ответ или чужую область.
4. Пройди тот же цикл для второго сервиса. События передавай в существующий automation inbox OC1, не создавая второй event store.
5. Доведи пользовательские HTTP/MCP-подключения: capability discovery, проверка адреса/редиректов, безопасные credentials, диагностируемые ошибки и revoke. «Совместимое API» не означает поддержку абсолютно любого сервиса.
6. После двух полных lifecycle доведи Drive reconnect/revoke и следующие приоритетные коннекторы из имеющегося плана, если доступны реальные интерфейсы. Количество карточек не является целью.

Зона: connector catalog/registry/transports, cloud-storage auth/transport, MCP и их панели. Не меняй membership-логику, Stars, память или execution API Codex. Общие registration/exports — отдельным небольшим коммитом.

## Приёмка

Два аккаунта, отказ чужому владельцу, истёкший доступ, отзыв во время операции. Для письма — черновик и подтверждённая отправка только назначенному тестовому адресату; для календаря — тестовое событие с readback и последующей корректировкой. При отсутствии OAuth-настроек закончи код и независимые сценарии, явно перечисли недостающие параметры; не подменяй live фикстурой.

Повторяй реализация → wiring → реальный пользовательский цикл → исправление. Сдай PR/SHA, отчёты и точный список действительно работающих сервисов.
