# OpenCode 4 — Koscode до реальной разработки

Прочитай `00_COMMON_RU.md` в ветке `team/local-completion-20261128`. Ветка: `completion/koscode-20261128`. ID: `05_OPENCODE`.

Ты владеешь code-agent service/executor/workspace, patch/editor, проверками и GitHub-путём Koscode. Отдельная навигация уже внедрена #704. Не возвращай старую оболочку и не переделывай обычный чат.

## Полная рабочая петля

1. Сверь текущий путь repository → revision → context → model proposal → checked diff → execution → acceptance → Draft PR. Последняя поставка не прошла внешний живой Draft PR; fixture не закрывает этот пункт.
2. Доведи получение актуального дерева/файлов, небольшую правку настоящей моделью и проверяемый patch. Сохраняй исходный SHA и показывай точные изменения.
3. Исполни допустимые проверки в действующей изоляции. Ошибка проверки должна возвращаться модели для адресного исправления, а не превращаться в формальный PASS.
4. Сохрани редакторские изменения и guard при переходах, reload и приходе устаревшего ответа. Большой diff/повреждённый patch/чужой путь не должен применяться частично.
5. После явного подтверждения пользователя создаётся ровно один Draft PR. Проверяй branch/SHA drift, потерянный ответ GitHub, идемпотентность, revoke и отмену до внешнего действия.
6. Доведи retry/restart/cancel, повторное открытие задачи и повторное редактирование результата. История и артефакты должны оставаться связаны с задачей.

Не выдавай фикстурный OCI прогон за написанный моделью код или реальный GitHub PR. Не публикуй без подтверждения. Для live используй выделенный тестовый репозиторий/ветку, назначенные владельцем; если их нет, подготовь сценарий и продолжай независимые части. Не обходи этот блокер публикацией в рабочий репозиторий.

Зависимости: native/desktop OC3, GitHub OAuth/transport OC2, общий developer API Codex. Не переписывай их реализации. Общие registration/contract изменения выделяй отдельно.

## Финальная приёмка

Модель получает маленький дефект, сама меняет код, запускает проверку, исправляет обнаруженное и показывает diff. После подтверждения появляется один Draft PR; повтор запроса не создаёт второй. Сдай PR/SHA, входной и выходной SHA тестового репозитория, реальные логи исполнения и точные ограничения.
