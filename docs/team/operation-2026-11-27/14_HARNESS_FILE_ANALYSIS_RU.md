## Цель

Раздел анализа файлов работает с большими документами и пакетами, сохраняет
покрытие и точные источники, выдаёт полезный результат без молчаливых пропусков.
Не требуется обещание «ИИ ничего никогда не пропускает» — требуется отчёт,
по которому видно обработанное, ошибку и оставшийся объём.

## Владение

document-answer-service/routes/store, document-library и профильный ingestion
в существующей архитектуре, UI анализа и покрытие. Форматное редактирование
Office — OC4; память/Skills — Harness 2; поиск веба — Harness 4.
Если нужен desktop reader, согласуй узкий адаптер с OC1/OC4.

## Полная петля

1. Инвентаризируй готовые ZIP/PDF/OCR/страничные проверки. Не повторяй
   уже слитую retry-связь, coverage и распаковку как новые функции.
2. Доведи ограниченную по памяти потоковую/пакетную обработку и план работы.
   Нестандартный/повреждённый файл и вложенный архив дают явный статус.
3. Подробный режим распределяет независимые части через существующий
   исполнитель и сохраняет результаты, версии и provenance.
4. Проверь ссылки на страницу/файл/фрагмент и сведение нескольких документов.
   Отчёт не закрывает пропуски несуществующим summary.
5. Добавь полезные извлечения/сравнение/реестр с пересчитываемыми итогами.
   Используй Skills Harness 2 вместо копирования бизнес-правил.
6. Доведи pause/cancel/retry и продолжение после перезапуска без повторной
   полной загрузки и потери завершённых частей.
7. Проверь большие синтетические пакеты, Unicode/таблицы/сканы,
   ошибки OCR, лимиты ресурсов, архивные пути и изоляцию владельцев.

Обязательный итог — большой набор разных документов → разбиение →
подробный отчёт и артефакт с источниками → сбой одной части → продолжение →
повторное открытие и честное покрытие. Размеры и число реально обработанных
страниц фиксируй, не называя маленькую фикстуру испытанием тысяч страниц.
