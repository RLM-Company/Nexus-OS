## Продуктовая цель

Studio выдаёт настоящие медиафайлы. Пользователь задаёт параметры/референсы,
получает результат, редактирует поддерживаемым способом, возвращается
к истории и скачивает. Те же операции доступны по явному запросу в чате.

#688 уже адаптировал твой предыдущий пакет. Прочитай
GEMINI_STUDIO_INTEGRATION_RU.md. Не возвращай отвергнутый отдельный Studio-стек,
SVG-имитации правки, тон вместо речи и отправку ключа на произвольный URL.

## Циклы провайдеров и изображений

1. Инвентаризируй подключённые маршруты. Изучи актуальные официальные
   API и возможности допустимых провайдеров. При выборе учитывай стоимость
   и качество конкретной операции; низкая цена без поддержки не подходит.
2. Подключи совместимые адаптеры через существующий registry/runtime.
   Не зашивай ключи, фиктивные endpoint и неподтверждённые capabilities.
3. Доведи image generation и edit с точным исходным артефактом, референсами,
   параметрами, историей и сравнением версий. Маски/локальная правка
   доступны только при настоящей поддержке и проверке.
4. Проверь явную генерацию из обычного чата и из Studio. Сохрани
   разрешённый запуск и отсутствие фонового платного дублирования.

## Циклы видео, Sound и Music

1. Реализуй настоящие video generation и получение проверенного клипа.
   Текстовая раскадровка остаётся отдельным полезным инструментом.
2. Поддержи сценовый workflow в объёме возможностей сервиса: создание,
   принятие, изменение/перегенерация выбранной сцены, сборка/экспорт.
   Если сервис умеет только целый клип, честно реализуй именно это.
3. Подключи настоящие SFX и Music, а не универсальный тон.
   Параметры темпа/длительности/описания/вокала передаются только когда
   поддерживаются. Речь использует рабочий TTS, сохраняя voice/speed/format.
4. Результат можно просмотреть/прослушать, остановить, скачать и открыть
   после перезапуска. Range и streaming должны работать фактически.
5. Отмена, timeout провайдера, late result и неизвестный исход не приводят
   к повторному списанию/созданию задания автоматически.

## Циклы презентаций

Проверь настоящую генерацию редактируемого PPTX по поручению пользователя.
Доведи изменение одного слайда, изображения/таблицы, заметки и повторный экспорт.
Неизменённые слайды сохраняются. Проверяй не только ZIP-сигнатуру,
но содержимое и визуальный результат на типовых примерах.

## Границы

Результат принадлежит аккаунту/разрешённому проекту. Применяй актуальные
правила Harness 3. Артефакты остаются в существующем файловом хранилище,
история хранит версии и provenance. Не наращивай SQLite гигабайтами base64.

Сохраняй origin/redirect/SSRF protections. Подписанная CDN-ссылка не должна
получать provider Bearer. Формат, размер и содержимое результата проверяются.
Нет API — нет статуса «генератор работает». Сам adapter и live-проверка
помечаются отдельно. Не заменяй production API собственным createStudioHttp.

## Приёмка

Пройди image+edit, video, речь, SFX, Music и PPTX через существующий интерфейс.
Для каждого — создать → проверить содержимое → изменить, если поддерживается →
сохранить исходную версию → скачать → перезапустить → открыть историю.
Также чужой аккаунт, повтор request id, поздний ответ и отмена.

Сначала реальные production routes с управляемым transport, затем доступный
живой провайдер в рамках разрешений. Сохрани небольшие проверенные результаты
или доступные ссылки без личных данных.

Если push недоступен — полный raw patch/архив от точной базы.
Никаких пакетов только из отчётов, невидимых веток и удалённых исходников.
Продолжай по петле до конца медиа-направления.
