## Цель

Пользователь работает над настоящим репозиторием в Koscode: понимает проект,
даёт задачу, видит точный diff, проверки и результат. После подтверждения
создаётся один Draft PR. Ошибочный код исправляется повторным циклом.

## Владение

apps/api/src/code-agent/, apps/web/src/app/code-agent/, их тесты и собственные
контракты. GitHub connector/auth принадлежит Harness 3, device driver — OC1,
developer API — OC3, Games — OC2. Существующий pipeline подтверждений сохраняется.

## Полная петля

1. Проверь существующий executor, snapshot, diff и восстановление публикации.
2. Доведи работу с деревом и контекстом проекта: релевантный поиск файлов,
   версия базы, несколько изменяемых файлов, ограничения ресурсов и инструкций.
3. Сделай рабочий путь задача → план → изменения → проверки → исправление →
   повторная проверка. Статус PASS основан на текущем точном diff и SHA.
4. Улучши навигацию, просмотр файла/diff, выбор изменений и понятные ошибки.
   Не меняй глобальный sidebar или обычный чат.
5. Сохраняй сессию, историю попыток, ссылки на файлы и проверенные результаты.
   Отмена и смена базы не должны оставлять действующее устаревшее разрешение.
6. Свяжи подтверждённую публикацию с актуальной основной веткой.
   Обрыв/повтор подтверждения восстанавливает один созданный PR.
7. Исправь failing test, stale diff, base changed, ошибку executor,
   отсутствие сети и чужой репозиторий.

Обязательный результат — законченная небольшая функция в тестовом репозитории,
с тестом, исправлением воспроизведённого дефекта и точным diff.
Живой внешний Draft PR выполняется в назначенном пользователем репозитории.
Если доступа нет, закончи остальное и сохрани runnable live acceptance.
Продолжай после первого PR-патча к устойчивому пользовательскому workflow.
