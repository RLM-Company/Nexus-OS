# 12 сценариев Harness 2 — запускаемый бизнес-процедурный раннер

Ветка `feature/ds2-memory-skills-business-20261127`. Документ описывает **фактически реализованный** срез: детерминированный, без модели, сети и доступа к хосту.

## Вход и выход

- `POST /api/v1/business-scenarios/run`, тело `{ scenario_id, input }`.
- Контракты: `packages/contracts/src/business-scenarios.ts` (TypeBox, аддитивно; существующие DTO не изменены).
- Чистая точка входа: `runBusinessScenario(id, input)` из `packages/core/src/business-scenarios.ts`.
- Ответ: `{ format: "kosmora.business-scenario-run.v1", scenario_id, artifact, checks[], gaps[], needs_answer }`.
- `needs_answer = true` ровно тогда, когда есть `gaps`; пропущенные поля **не заполняются выдуманными значениями**.

Артефакт всегда содержит `kind` и поля, необходимые для процедуры: `text`, `table`, `register`, `calculation`, `checklist` или `gaps`. Это полезный результат (CSV/Markdown/реестр/расчёт/чек-лист), а не только статус.

## Переиспользование, а не новая разработка

- BIZ-013 и BIZ-040 **не являются новыми реализациями**: вызываются существующие проверенные чистые функции `packages/core/src/supplier-offer-comparison.ts` и `packages/core/src/biz040-field-register.ts`. Повторная верификация зафиксирована в тестах и в поле `artifact.reused`.
- BIZ-038 и BIZ-046 используют существующие `applyProjectRules`/`evaluateSkillResult` через импорт/вызов там, где применимо; BIZ-046 — прямой вызов `evaluateSkillResult`.
- Раннер не содержит сетевых, модельных, файловых или хост-вызовов.

## Проверки и ограничения

- Тесты `packages/core/test/business-scenarios.test.ts`: 12 сценариев, gap/needs_answer, повторное применение к изменённым входам, детерминизм.
- Тест API `apps/api/test/business-scenario-routes.test.ts` использует Fastify `inject`, как `supplier-work-handoff.test.ts`.
- Ограничение: сценарии работают только с предоставленными входами и не выполняют внешние действия (отправка запросов, подача тендера, финансовые операции).
