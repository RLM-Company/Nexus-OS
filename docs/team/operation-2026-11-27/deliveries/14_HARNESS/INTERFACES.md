# Интерфейсы анализа больших пакетов

База `3af92583ccc8ceb49f44c0b8633955f40feaf59f`. Существующий подробный анализ принимает вопрос и ID готовых файлов проекта. Новый checkpoint содержит ID попытки, порядковый номер партии, SHA-256 вопроса и точных фрагментов, ссылки на страницы и строки, проверенные заметки или код отказа. Партия и покрытие фиксируются одной транзакцией. Вопрос, тексты и реестр остаются в пределах аккаунта и проекта.

`POST /api/v1/projects/:projectId/document-library/answers/:id/pause` останавливает исполнение, сохраняя части. Для совместимости старая модель статусов передаёт паузу как `cancelled` с причиной `PAUSED`. Новый запуск после `/retry` создаёт связанную попытку. Совпавшие по SHA-256 проверенные партии используются повторно; повторные запросы с прежним ID возвращают ту же попытку. Частичный готовый ответ с ошибками тоже можно продолжить.

`GET /api/v1/projects/:projectId/document-library/answers/:id/analysis.ndjson` скачивает построчный реестр покрытия, прошедших и ошибочных частей. Отдельные строки содержат адреса файлов, страниц, фрагментов и найденные цитаты. Интерпретации модели автоматически по смыслу не проверяются. Отчёт с обобщением и обычные выгрузки DOCX/PDF/CSV/ZIP используют прежние маршруты и формат.

Адрес `/:fileId/fragments/:chunkId` внутри `document-library` возвращает текущий индексированный фрагмент с номером страницы и диапазоном строк при действующем доступе. NDJSON содержит ссылки на оригинал и этот адрес. Сохранённые заметки в реестре остаются снимками источников на момент анализа.
