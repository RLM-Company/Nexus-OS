# BUG-01: восстановление запроса поверх нового черновика

**Владелец:** 01_CODEX (чат и composer).
**Оригинальная поставка:** [REQUEST_RECOVERY_2026_11_13_RU.md](../../../operation-2026-11-10/deliveries/02_DEVELOPER/REQUEST_RECOVERY_2026_11_13_RU.md).

## Минимальные данные

[input.json](input.json) — исходный текст, исходный файл, новый ожидающий файл,
статусы `failed`/`cancelled`, история только с пользовательским сообщением.

## Шаги

1. Отправить `source_text` с `source_files`; дождаться терминального статуса
   `failed` или `cancelled` из `status_fixtures`.
2. Не трогая историю, ввести новый текст и добавить `new_pending_file`.
3. Нажать «Вернуть запрос в редактор».
4. Проверить редактор: текст, вложения, отсутствие повторной отправки.
5. Перезагрузить страницу и повторить проверку.
6. Повторить для второго статуса из `status_fixtures`.

Живая модель не нужна: провайдер — `fixture`.
