## Сценарий (один набор материалов, зависимые шаги)

Добавлен тест `apps/api/test/work-dag.test.ts` →
`koswork lifecycle: materials -> plan -> approval -> dependent steps -> verified
download, including pause/restart/lost start response`.

Входные материалы: `values.csv` (`00123,19700,1300`) + `anchor.txt`
(`00123 = 21000`), инструкция «сложить Q1 и Q2, использовать только исходники».
План из трёх зависимых шагов: `read → sum → report`.

Пройдена цепочка:

1. **Входные материалы → план.** Документы сохранены в project materials;
   план создан с `client_request_id`, шаги `sum`/`report` с зависимостями.
2. **Подтверждение.** Без `acknowledge_cost` запуск отвергнут
   (`EXPLICIT_RETRY_REQUIRED`), модель не вызвана; после одобрения — один
   events записи, повтор управления на старой версии → `STALE_DAG` (потеря
   ответа при старте не создаёт второе разрешение).
3. **Шаги.** Очередь с `maxConcurrentWork=1`: завершён `read`, `sum` в
   pending, `report` blocked. Все модельные вызовы видели исходные строки
   `ID,Q1,Q2` (материалы закреплены снимком плана).
4. **Пауза.** `pause` меняет режим проекта, новых вызовов модели нет;
   `resume` возвращает активный режим.
5. **Перезапуск API + потеря ответа.** Свежий `ManagerWorkCoordinator` дважды
   вызывает `recoverAutomation()`/`advance()` с тем же чекпоинтом: план
   `paused / RESTART_REQUIRES_RESUME`, завершённый `read` сохраняет SHA,
   ровно один незавершённый child для `sum`, одно событие разрешения.
   Вызов `execute` без явного разрешения не тратит модель.
6. **Явное продолжение.** `resume_step` + одобрение оставшейся волны: тот же
   attempt (`attempts.length === 1`), `read` не регенерируется, `report`
   видит исходные материалы, не видит правок mid-flight.
7. **Проверка и скачивание.** Содержимое отчёта проверено по точным
   значениям `19700`, `1300`, `21000 [S1]`; SHA-256 conformity; полный ZIP
   содержит ожидаемый текст и `"complete": true`. `GET /results.zip`
   возвращает **побайтно тот же Buffer**, что и сохранённый
   `resultsArchive()` — скачанный файл совпадает с артефактом.

## Что исправлено

Производственный код не менялся: подтверждённых разрывов в очереди,
восстановлении и выдаче результатов в этой версии не найдено — все проверки
прошли на существующем механизме. Исправление — **сам воспроизводимый
сквозной сценарий** с жёсткими проверками «не дублируются разрешение/запуск»
и «скачанный ZIP == сохранённый артефакт», которых не было в связке.

Фактическое поведение, зафиксированное как требование: после рестарта
автозапуск остаётся запрещённым (`RESTART_REQUIRES_RESUME`); для оставшейся
волны нужно **одно явное продолжение** — это повторное согласие на новой
границе рестарта, а не дубль исходного разрешения.
