## Цикл 2 — падение Koscode-сценария

Локальное воспроизведение с instrumentation запросов дало ровно 3 запроса с `/code-agent` в URL:

| Тип              | URL                                                                                | Инициатор                                            |
| ---------------- | ---------------------------------------------------------------------------------- | ---------------------------------------------------- |
| `document` GET   | `/code-agent?project=unavailable-project&run=00000000-0000-4000-8000-000000000001` | `about:blank`                                        |
| `stylesheet` GET | `/_next/static/css/app/code-agent/page.css?v=…`                                    | страница `/code-agent?project=unavailable-project&…` |
| `script` GET     | `/_next/static/chunks/app/code-agent/page.js`                                      | страница `/code-agent?project=unavailable-project&…` |

Ни одного запроса к `/api/v1/projects/<id>/code-agent`; `state.publications()` remained 0; combobox «Проект» пуст, панели состояния задачи нет. Значит:

- **дефекта Koscode нет** — приложение не подставляет задачу другого проекта и не запрашивает её данные;
- **тест смешал** загрузку страницы (документ + CSS/JS) с сетевой границей API.

Исправление критерия: считать только `fetch/XHR` по шаблону `/api/v1/projects/[^/]+/code-agent` и требовать `[]`. targeted test — **1 passed**. Минимальное воспроизведение разработчику Koscode не передавалось: дефект не найден, исправлён только критерий теста.
